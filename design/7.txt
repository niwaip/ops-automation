## 1) 全体架构图（权限/控制 + 模板回放 + 人工接管）


### 图中关键点（你关心的“权限/控制”落点）

*   **`johnymoo/chrome-novnc-docker` 被定位为 Browser Worker（运行时平面）**：只负责跑会话（Xvfb + headed Chrome）并提供两条通道：
    *   **noVNC Web（8080）**：人类接管通道
    *   **CDP（9222）**：回放引擎/自动化通道  
        这三个端口（8080/5900/9222）以及 noVNC/CDP 的用途在该仓库 README 的使用说明中就明确列出。 [\[CodeInterpreter \| InteractiveChart\]](https://jp-prod.asyncgw.teams.microsoft.com/v1/objects/0-wjp-d3-e4168d7714c657369db4a8f509c81972/views/original/arch_overall_permissions_control_replay_takeover.png)
*   **模板解析/回放引擎（Replay Engine）放在“执行平面”**：它通过 **CDP 9222** 控制同一个浏览器会话，而不是塞进浏览器容器里（避免权限边界混乱、便于统一策略与锁）。 [\[CodeInterpreter \| InteractiveChart\]](https://jp-prod.asyncgw.teams.microsoft.com/v1/objects/0-wjp-d3-e4168d7714c657369db4a8f509c81972/views/original/arch_overall_permissions_control_replay_takeover.png), [\[blog.csdn.net\]](https://blog.csdn.net/gitblog_00884/article/details/154063557)
*   **控制平面（网关/PEP/Session Broker）统一裁决**：是否允许接管、是否冻结 Agent、是否签发 noVNC/CDP 的短期令牌（lease/token），并把审计落在统一的证据链里（Trace/日志/录像）。Playwright 的 Trace/Trace Viewer 正是你做“可观测+可追责”的强证据链工具。 [\[blog.csdn.net\]](https://blog.csdn.net/wellshake/article/details/142338065), [\[gitee.com\]](https://gitee.com/yunfengZH/docker-novnc)

## 4) 你现在“画清楚权限/控制”的关键落点（把图落成评审结论）

你可以把下面 4 条作为架构评审结论写进去（非常关键）：

1.  **浏览器容器（johnymoo/chrome-novnc-docker）是运行时节点**：暴露 noVNC(8080)/CDP(9222) 能力，但**不承载业务策略与回放逻辑**。 [\[CodeInterpreter \| InteractiveChart\]](https://jp-prod.asyncgw.teams.microsoft.com/v1/objects/0-wjp-d3-e4168d7714c657369db4a8f509c81972/views/original/arch_overall_permissions_control_replay_takeover.png)
2.  **Replay Engine 外置**：统一由控制平面签发的 token/lease 来决定它是否能连接 CDP 发送输入（CDP Input 域就是“可注入鼠标/键盘事件”的能力）。 [\[blog.csdn.net\]](https://blog.csdn.net/gitblog_00884/article/details/154063557), [\[CodeInterpreter \| InteractiveChart\]](https://jp-prod.asyncgw.teams.microsoft.com/v1/objects/0-wjp-d3-e4168d7714c657369db4a8f509c81972/views/original/arch_overall_permissions_control_replay_takeover.png)
3.  **接管是状态机驱动**：进入 HUMAN\_CONTROL 时冻结 Engine 的输入通道，只开放 noVNC 输入；离开接管后再恢复 Engine 并做 state sync。
4.  **审计默认开启**：回放用 Playwright trace（可用 Trace Viewer 分析每一步的定位器、DOM 快照、网络等）。 [\[blog.csdn.net\]](https://blog.csdn.net/wellshake/article/details/142338065), [\[gitee.com\]](https://gitee.com/yunfengZH/docker-novnc)

## 5) 你下一步如果要“把图变成可执行接口”，我建议先定这 6 个 API

这 6 个接口一旦定好，你的“权限/控制”就从 PPT 进入工程：

*   `POST /sessions`：创建会话（分配某个 browser-worker）
*   `POST /sessions/{id}/attach-cdp`：签发 CDP token/代理地址（给 replay-engine）
*   `POST /sessions/{id}/attach-novnc`：签发 noVNC token/代理地址（给人接管）
*   `POST /sessions/{id}/takeover`：切到 HUMAN\_CONTROL（冻结 engine）
*   `POST /sessions/{id}/resume`：从接管回到 AGENT\_RUNNING
*   `POST /sessions/{id}/revoke`：撤销令牌/销毁会话/导出审计包
