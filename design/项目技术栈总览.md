# Ops Automation 项目技术栈总览

本文档用于汇总当前仓库（`ops-automation`）的核心技术栈、服务分层与运行基础设施，方便新人上手与架构沟通。

## 1. 总体架构

- 架构形态：`Monorepo + 多服务（微服务风格）`
- 代码组织：`pnpm workspace`（`services/*`）
- 主要分层：
  - 前端体验层：`portal`（管理后台/发布中心）、`office-addin`
  - 业务服务层：`auth`、`control-plane`、`session-broker`、`ai-orchestrator`、`template`、`report`、`replay-engine`
  - 执行层：`browser-worker`、`temporal-worker`、`temporal-sandbox-agent`
  - 基础设施层：`PostgreSQL`、`Redis`、`Temporal Server + Temporal UI`、`Chrome/noVNC`

## 2. 语言与运行时

- Node.js：`>=20`（主力后端/前端）
- TypeScript：后端与前端统一主语言
- Python：用于 Temporal sandbox 验证代理（`temporal-sandbox-agent`）
- SQL：PostgreSQL 持久化存储

## 3. 前端技术栈

### 3.1 Portal（`services/portal`）

- 框架：`React`
- 构建：`Vite`
- 语言：`TypeScript`
- UI：`Ant Design`
- 网络请求：`axios`

### 3.2 Office Add-in（`services/office-addin`）

- 框架：`React + Vite + TypeScript`
- 形态：Office 加载项（Word/Excel/PPT）
- 通信：`axios`

## 4. 后端技术栈

### 4.1 统一后端框架

- 主框架：`NestJS`（绝大多数 Node 服务）
- API 风格：REST + 部分 SSE（流式日志/事件）
- 常见中间件能力：鉴权、RBAC、DTO 校验、服务间调用

### 4.2 数据访问层

- `Prisma`：`auth`、`control-plane`、`session-broker`、`ai-orchestrator`
- `TypeORM`：`template`、`report`
- 数据库：`PostgreSQL 15`
- 缓存/会话：`Redis 7`（部分服务使用 `ioredis`）

### 4.3 AI 与编排

- AI 编排服务：`ai-orchestrator`
- 关键模式：Planner + ReAct 工具链（技能匹配、参数提取、执行决策）
- 外部模型接入：`OpenAI / DeepSeek / 阿里云相关模型`（由环境变量配置）

### 4.4 Temporal 相关

- 工作流运行：`Temporal Server`（Docker）
- Node Worker：`services/temporal-worker`（`@temporalio/workflow` / `@temporalio/worker`）
- Python 验证代理：`services/temporal-sandbox-agent`
  - 依赖：`temporalio`、`aiohttp`、`orjson`、`python-json-logger`
- 验证模式：真实验证（测试队列）与运行时执行链路并存

### 4.5 浏览器自动化

- 执行服务：`browser-worker`（NestJS）
- 自动化库：`Playwright`
- 浏览器容器：`browser-chrome`（CDP + noVNC + codegen API）

## 5. 基础设施与运维

### 5.1 容器与编排

- 容器编排：`Docker Compose`
- 核心文件：`docker/docker-compose.full.yml`（全栈开发）
- 推荐启动方式：`docker/start-smart.sh`（适配 worktree，统一 `PROJECT_ROOT` 挂载）

### 5.2 主要基础组件

- 数据库：`PostgreSQL`
- 缓存：`Redis`
- 工作流引擎：`Temporal`
- 可观测入口：
  - Temporal UI：`8088`
  - Portal：`5173`
  - 其他服务端口见 `docker/README.md`

## 6. Monorepo 与工程化

- 包管理：`pnpm`
- Workspace：`services/*`
- 代码规范：`ESLint + Prettier`
- 类型检查：`TypeScript`
- 测试：`Jest`（单测/集成）
- 常用根脚本（`package.json`）：
  - `lint` / `format`
  - `typecheck`
  - `build`
  - `test:unit` / `test:integration`

## 7. 服务清单与关键技术（按目录）

- `auth`：NestJS + Prisma + 鉴权/RBAC + 能力发布管理
- `control-plane`：NestJS + Prisma + 执行单编排与状态机
- `session-broker`：NestJS + Prisma + ioredis（会话相关）
- `ai-orchestrator`：NestJS + Prisma + ioredis + LLM 编排
- `browser-worker`：NestJS + Playwright
- `template`：NestJS + TypeORM
- `report`：NestJS + TypeORM + ioredis
- `replay-engine`：NestJS
- `temporal-worker`：NestJS + Temporal TS SDK
- `temporal-sandbox-agent`：Python + Temporal Python SDK
- `portal`：React + Vite + Ant Design
- `office-addin`：React + Vite（Office Add-in）

## 8. 当前技术栈特点

- 优点：
  - 技术栈统一（TypeScript/NestJS 主导），团队协作成本低
  - AI 编排、执行控制、Temporal 工作流能力分层清晰
  - 支持容器化全栈开发，环境一致性较好
- 注意点：
  - 同时存在 Prisma 与 TypeORM，数据层范式需统一规范
  - 多服务链路较长（Portal -> Auth -> Control-plane -> Runtime），需重视链路日志与鉴权透传
  - Temporal 与执行引擎并行演进，接口契约需持续治理
