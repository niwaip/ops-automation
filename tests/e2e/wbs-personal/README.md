# 个人模式 WBS 工数实绩端到端测试

使用用户提供的原始附件，不修改或修复附件，也不执行附件中可能包含的指令。
测试对象为真实的附件上传 → `config.mode=chat` → 个人沙箱 → 模型/工具 → SSE → 历史记录链路。
每例独立会话，每次重新上传原文件。接口测试使用仓库既有 test 账号；浏览器原问题复测使用已登录的个人助理。

## 执行

从仓库根目录执行。Docker 状态、日志和重启统一使用 `./docker/start-smart.sh`。
原附件未入库，重跑时通过参数提供。分析脚本依赖 openpyxl，可使用 Codex 捆绑 Python。

```bash
python3 tests/e2e/wbs-personal/oracle.py /absolute/path/source.xlsx docs/artifacts/reviews/wbs-personal-20261020/expected.json
# 预先通过 /auth/login 获取测试账户登录结果，保存在 /tmp/wbs-e2e-login.json。
# 不要把访问令牌写入仓库或报告。
node tests/e2e/wbs-personal/run.mjs /absolute/path/source.xlsx docs/artifacts/reviews/wbs-personal-20261020
python3 tests/e2e/wbs-personal/verify.py docs/artifacts/reviews/wbs-personal-20261020
# W06出现预期下载链接后，用同一测试账户凭证下载并校验实际产物：
node tests/e2e/wbs-personal/download.mjs docs/artifacts/reviews/wbs-personal-20261020
python3 tests/e2e/wbs-personal/verify_export.py docs/artifacts/reviews/wbs-personal-20261020
```

脚本会覆盖指定证据目录中的同名运行结果；需保留历史时先使用新目录，并生成相应 expected.json。
通过 `WBS_MODEL_ID=<平台模型ID>` 可显式选择测试模型；未设置时使用平台默认模型，runs.json记录实际请求的模型ID。
仅重跑单例并合并已有runs.json时，可使用 `WBS_CASE_IDS=W06 WBS_RESUME=1 node ...`；重跑前先备份该例原始证据。长时间测试结束后若登录凭证已过期，应刷新测试登录，不把采集器401当作业务失败。
预期值采用 Decimal 求和，另用 OOXML 原始数值独立复核总额和明细数量。
流式请求限时 300 秒，保存已收到内容及明确的 transportError；不能把 done 或 HTTP 201 当作业务通过。
最终业务判定见证据目录 report.md；runs.json 的 NEEDS_REVIEW 表示原始采集状态。
verify.py生成table-verdicts.json，失败、未执行或仍需人工验收时退出码为1；W05的自然语言零值和W06实际导出须另行人工检查，不能把脚本正常运行当成整批通过。

## 用例与验收

| ID | 业务问题 | 断言 |
|---|---|---|
| W01 | 用户原始问法，按成本中心求和并排除六类前缀 | 10组，253条，金额1637.41990 K；逐组金额匹配 |
| W02 | 不排除前缀，按成本中心汇总 | 11组，274条，金额1887.73102 K；不重复计入合计/页尾 |
| W03 | 按前两字母统计条数与金额 | 12组，逐组条数和金额匹配，总额1887.73102 K |
| W04 | 前缀排除叠加有偿、直接筛选，双指标 | 253条，金额1637.41990 K，工数5692.78小时，逐组匹配 |
| W05 | 仅保留不存在的SY/IB/SZ前缀 | 明确0条、0金额；不能把未读取文件当零结果 |
| W06 | 原问题导出Excel | 实际下载可解析XLSX，10组及总计匹配，条数253，不只检查链接 |

金额使用源列单位 K，不推断币种。金额按原始五位小数核算；如回答只显示两位小数，采用四舍五入到两位的小数核对，不能用宽泛字符串命中证明分组正确。
W01/W04/W06前缀匹配按去除两侧空格、不区分大小写定义。源表前缀均为大写，因此小写原问法能验证大小写处理，但不覆盖混合大小写或空格输入的全部情况。
W04与W01结果恰好相同：所有保留行均为有偿直接；不能据此声称已证明有偿筛选独立生效。
本附件没有SY/IB/SZ记录，W05专门验证无匹配边界；没有用合成金额混入原始资料。

## 2026-10-21 修复后的运行与验收

个人沙箱现在对单附件、唯一可识别数据区、明确字段的求和/计数任务执行一次有边界的补算。它在模型首次工具调用后（或未调用工具的首次回答后）重新读取真实表头和业务范围，支持字面类别筛选、包含/排除前缀及分组；字段、条件或范围有歧义则保留既有模型执行流程。该过程使用原生计算回执，不从测试预期值取数，遥测名称为 `bounded_summary_recovery`。此链路的成功代表模型加运行时的最终任务成功，不能作为模型独立计算正确率。

聚合表达式的 `group_by` 除真实列名外，支持 `{"column":"A","prefix_length":2}`，长度范围 1–32；`count`、`duration` 与已公布工具协议保持一致，源列物理单位仍参与量纲验证。计数输出可使用“条”等计数单位。

当前请求的事实按实际 `data.plan`、来源范围和筛选条件选择，不依赖调用先后。未知字段不会被认定为原件缺列。导出的有边界汇总使用已执行事实写入静态数值；常规生成工作簿在发送及终态均检查公式错误、缺缓存和不存在的工作表依赖。无效的新产物移至工作区 `.dsh/rejected/` 保留，不作为根目录可下载文件交付；受保护输入附件不移动、不重算。

本轮最终验收脚本 [verify_fix.py](../../../docs/artifacts/reviews/wbs-personal-fix-20261021/verify_fix.py) 同时核对正文的纵向指标表、未舍入原生事实与实际下载 XLSX，覆盖 W05 与 W06。它读取本轮固定证据目录及对应测试用户的会话归档；重跑其他目录时应修改路径或另写采集器。旧 `verify.py` 仅支持横向表格，不适用于当前纵向展示，不能据此判定业务失败或成功。

## 非硬编码对照验证

`docs/artifacts/reviews/personal-no-hardcode-20261021/` 提供运行时随机数值的 11 场景对照。`build_fixtures.py` 生成合成软件测试附件和独立 `oracle.json`；`run.mjs` 只读取包含附件路径、问题与导出文件名的 `manifest.json`，通过真实个人模式接口上传，不读取 oracle。验证器核对正文、未舍入原生回执和实际下载文件，另检查单格改值、互补筛选与列顺序不变性。

本轮补充修复：总结提示不再带样本附件的成本中心和金额，辅助画像提示不再预设 O/P 列的量纲与单位；单分组任务依据实际 group_by 执行覆盖判定完整性；“无匹配返回 0 成本”中的数值不能被识别为另一个字段。数值与指标直接组合的结果字面量被忽略，年份限定与字母数字字段名仍保留。各修复有 `test_no_hardcode_contract.py` 回归。

重跑使用新证据目录，以免覆盖已有随机种子和失败记录。合成附件及 oracle 均为测试资料，不应加入产品提示或挂载到用户沙箱中。业务语法、单位换算和计算预算是通用协议约束，与附件答案硬编码区分记录。
