# Ops Automation 项目技术栈总览

本文档以当前仓库现态为准，汇总 `ops-automation` 的主要技术栈、目录分层和运行基础设施。

## 1. 总体形态

- 架构形态：`Monorepo + 多前端 + 多后端服务`
- 包管理与工作区：`pnpm workspace`
- 主代码目录：
  - `apps/frontend/`：前端体验层
  - `apps/backend/`：后端服务与运行时
  - `apps/office-addin/`：Office 加载项
  - `apps/desktop/`：桌面端实验入口
  - `packages/`：共享包与契约

## 2. 语言与运行时

- Node.js：`>=20`
- TypeScript：前后端主语言
- Python：用于沙箱与部分运行时辅助能力
- SQL：`PostgreSQL`

## 3. 前端技术栈

### 3.1 Portal

路径：`apps/frontend/portal`

- 框架：`React 18`
- 构建：`Vite 5`
- UI 组件：`Ant Design`
- 路由：`react-router-dom`
- 状态与数据请求：`zustand`、`react-query`
- 国际化：`i18next`

### 3.2 User Web

路径：`apps/frontend/user-web`

- 框架：`React 18`
- 构建：`Vite 5`
- 形态：面向普通用户的独立前端入口
- 关注功能：聊天、通知、执行、报告、技能浏览

### 3.3 Office Add-in

路径：`apps/office-addin`

- 框架：`React 18 + Vite 5`
- 运行环境：`Office.js`
- 数据请求：`axios`
- 状态管理：`zustand`
- 数据请求缓存：`@tanstack/react-query`

### 3.4 Desktop

路径：`apps/desktop`

- 框架：`React`
- 形态：桌面端渲染层实验入口

## 4. 后端分层

当前后端按职责边界组织，而不是按旧服务名堆放：

- `core/`
  当前主要保留 `platform`，承载平台聚合能力。
- `platform/`
  平台级能力预留层。
- `sessions/`
  会话分配、冻结和锁管理。
- `domain/`
  业务领域服务，如 `browser-template`、`document-engine`、`report`。
- `orchestration/`
  编排与控制层，如 `control-plane`、`ai-orchestrator`。
- `runtime/`
  运行时执行器，如 `browser-worker`、`replay-worker`、`temporal-worker`、`sandbox-agent`。
- `shared/`
  受控共享契约与基础能力。
- `var/`
  运行时数据和缓存。

## 5. 后端核心技术

### 5.1 应用框架

- 主框架：`NestJS`
- 接口风格：`REST` + `SSE`
- 常见能力：DTO 校验、Swagger、鉴权、RBAC、服务间 HTTP 调用

### 5.2 数据访问

- 当前主流 ORM：`Prisma`
- 已使用 Prisma 的代表服务：
  - `core/platform`
  - `sessions/session-broker`
  - `orchestration/control-plane`
  - `orchestration/ai-orchestrator`
  - `domain/browser-template`
  - `domain/report`
  - `runtime/replay-worker`
- 数据库：`PostgreSQL 15`
- 缓存：`Redis 7`

### 5.3 编排与执行

- Planner / AI 编排：`orchestration/ai-orchestrator`
- 控制面：`orchestration/control-plane`
- Temporal Worker：`runtime/temporal-worker`
- 浏览器执行：`runtime/browser-worker`
- 浏览器回放与接管：`runtime/replay-worker`
- 文档渲染与模板处理：`domain/document-engine`

### 5.4 浏览器自动化

- 自动化库：`Playwright`
- 浏览器容器：`docker/browser-chrome`
- 辅助能力：CDP、noVNC、codegen API、回放/接管链路

### 5.5 Temporal 与 Python 运行时

- 工作流引擎：`Temporal`
- Node 侧 Worker：`@temporalio/worker`
- Python 侧辅助运行时：`runtime/sandbox-agent`

## 6. 基础设施与 Docker

### 6.1 推荐启动方式

- 统一入口：`./docker/start-smart.sh`
- 要求：从仓库根目录执行，并确保 `PROJECT_ROOT` 指向当前 worktree

### 6.2 Compose 组织

Compose 文件位于 `docker/compose/`，当前包含：

- `docker-compose.base.yml`
- `docker-compose.core.yml`
- `docker-compose.planner.yml`
- `docker-compose.runtime.yml`
- `docker-compose.experience.yml`
- `docker-compose.full.yml`
- `docker-compose.test.yml`

### 6.3 主要基础组件

- `PostgreSQL`
- `Redis`
- `Temporal Server + Temporal UI`
- `browser-chrome`
- Office Add-in 相关本地证书与 nginx 资源

- 若服务名、目录层级、ORM 方案或 Docker 入口发生变化，应同步更新本文档。
- 历史服务名或迁移中间态应放入归档文档，不应继续留在本总览里。

## 8. 当前技术栈特点

- 优点：
  - 技术栈统一（TypeScript/NestJS 主导），团队协作成本低
  - AI 编排、执行控制、Temporal 工作流能力分层清晰
  - 支持容器化全栈开发，环境一致性较好
- 注意点：
  - 同时存在 Prisma 与 TypeORM，数据层范式需统一规范
  - 多服务链路较长（Portal -> Auth -> Control-plane -> Runtime），需重视链路日志与鉴权透传
  - Temporal 与执行引擎并行演进，接口契约需持续治理
