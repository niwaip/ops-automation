# 企业级技能平台 浏览器语义规则版本化与模块重组实施 Backlog

**Browser Semantic Rule Versioning and Module Reorg Implementation Backlog v4.0**  
日期：2026-06-21

> 本文将 `浏览器语义规则版本化与模块重组方案 v4.0` 下沉为可执行任务清单。  
> 目标是在不破坏当前浏览器录制、调试、循环、导出与恢复能力的前提下，先补评测与观测能力，再落地语义规则版本化，最后完成浏览器目录重组。

---

## 1. Backlog 目标

本 backlog 聚焦以下目标：

- 让 `mock-erp` 从演示站升级为可评测浏览器测试网站
- 让业务语义规则脱离硬编码，支持版本化、灰度、回退与回放
- 让 `browser-command.service.ts` 收敛为通用规则解析器，而不是继续叠加业务词
- 让浏览器相关模块按处理流程重组为 `api / session / observe / intent / execute / loop / export / recovery`
- 在整个迁移过程中保持现有链路可运行、可回退、可诊断

## 2. 实施原则

### 2.1 先补评测，再改规则

- 没有测试站页面矩阵、任务集和回放样本时，不进入规则大规模外置
- 没有命中日志时，不进行规则灰度发布

### 2.2 先收边界，再搬目录

- 先明确哪些规则属于通用解析器，哪些属于业务规则系统
- 目录迁移只做职责收敛，不作为继续堆业务逻辑的借口

### 2.3 先兼容旧链路，再切主路径

- 首期规则版本化必须支持“关闭开关后回退到旧逻辑”
- 首期目录重组必须以“迁移目录但不改行为”为优先

### 2.4 优先依赖结构化候选

- 能由 `candidateId / row / region / stableName / field / preferredLocator` 解决的问题，不再继续新增业务正则
- 规则系统负责语义归一化，不直接跳过候选定位层生成任意执行命令

### 2.5 AI 生成优先，人工审核发布

- 规则集生成主路径改为“错误日志沉淀 -> AI 生成候选规则集 -> 人工审核 -> canary/active 发布”
- 后台不再把“人工从零编写规则”作为主能力，人工侧重点转为审核、回放验证、发布、回退
- AI 生成输入必须优先来自真实失败样本，包括执行失败、录制失败、语义误判、fallback 失败和页面定位失败
- 所有错误日志必须保留原始记录，不因规则修复、重新生成或版本回退而覆盖、合并或删除

### 2.6 规则按能力类别管理

- 规则除了 `type` 外，还必须有面向运维与审核的 `category`
- `category` 用于表达业务能力边界，例如 `LOGIN / NAVIGATION / FIELD_FILL / MENU_SELECTION / DETAIL_OPEN / READ_VALUE / ROW_ACTION`
- `type` 负责表达语义规则形态，例如 `intent_alias / field_alias / region_alias`；`category` 负责表达“这条规则解决哪类浏览器意图”
- 后台管理与 AI 审查优先按 `category` 展示、筛选和替换，避免把“登录、导航、填写菜单”继续混在同一条默认规则里
- 规则发布与回退首期仍按 `rule_set` 版本进行，但必须支持在同一规则集中按 `category` 分组查看与审核

## 12. 风险与缓解

### 12.1 规则版本化后误伤增加

风险：

- 新规则可能提高命中率，但也可能把通用命令误归一化到错误业务语义

缓解：

- 必须先过离线回放
- 必须支持 canary
- 必须支持一键回退

### 12.4 AI 自动生成规则引入幻觉或过拟合

风险：

- AI 可能基于少量错误样本生成过窄、过宽或错误的匹配规则，导致线上误伤扩大

缓解：

- AI 生成结果必须附带来源错误日志、推理说明和建议 targeting
- AI 生成结果必须经过离线回放和人工审核，不能直接自动发布为 `ACTIVE`
- 优先从同类错误聚类生成规则，避免使用单条偶发样本直接产出线上规则

### 12.5 错误日志保留不完整导致无法复盘

风险：

- 如果只保留摘要或只保留命中日志，不保留失败上下文，后续将无法判断规则为什么失败、AI 为什么误判

缓解：

- 必须区分命中日志与错误日志，两者都保留
- 必须保留错误现场关键信息，包括截图、页面上下文、原始报错、traceId 和规则版本
- 错误日志只能追加归档，不能被后续修复覆盖

### 12.2 目录迁移期间 import 破坏链路

风险：

- 目录搬迁很容易引入大面积相对路径错误

缓解：

- 按子目录小步迁移
- 每步都跑编译、诊断与关键回放任务
- 必要时保留短期兼容导出层

### 12.3 测试网站过度依赖特殊标注

风险：

- 如果评测完全依赖 `data-*` 标注，可能高估真实线上站点能力

缓解：

- 维持“有标注 / 半标注 / 弱标注”三类变体
- 同时验证文本、role、区域与行信息定位能力

---

## 13. 一句话总结

> 这次实施的正确顺序不是“先人工堆规则、再线上试错”，而是“先保留真实错误日志，再用 AI 生成候选规则，经过回放与人工审核后发布”，同时在这个过程中完成规则版本化与目录重组，才能把浏览器语义能力升级为可持续演进的平台资产。
