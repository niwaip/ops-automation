# 检索答案交付验收方案 v1.0

## 问题与范围

2026-10-22 的“今天的体育赛事”请求成功检索后，仅交付了标题，进程退出码和模型结束原因却均正常。进程完成、检索成功与答案有效交付是三个不同的状态，不能相互替代。

本方案对通用检索回答增加结构验收，不绑定体育领域、特定日期、模型名称或用户。结构通过不等于事实全部核实，不替代来源质量、时效和语义一致性核验。

## 职责划分

| 模块 | 职责 |
| --- | --- |
| `planning_phase.py` | 将只读检索结果转换为 ToolResult 回执，记录阶段和工具来源 |
| `runner.py` | 汇集前置检索和规划回执，传递到执行循环；预算内保留原始资料；显式传递原始用户指令 |
| `agent_loop.py` | 执行工具及循环编排，合并本轮已有回执 |
| `final_answer.py` | 独立处理最终呈现与已有交付物恢复，在终态执行答案验收 |
| `retrieval_answer_validation.py` | 根据本轮证据、问题及输出结构进行确定性检查，公平分配多来源上下文预算 |
| `retrieval_answer_recovery.py` | 一次有预算限制的同模型综合，管理成功、澄清与未完成状态 |
| `response_observability.py` / `telemetry.py` | 记录脱敏响应指纹、流结束来源及验收状态 |

最终回复处理从原 1441 行循环文件下沉，保留 `_finalize_agent_text` 兼容入口，通过注入模型适配器与工作区配置保持依赖单向。

## 验收契约

触发依据是当前请求的成功且非空检索回执，来源包括前置搜索、规划阶段和执行循环。不能从历史 `tool` 消息推断本轮已检索，也不把失败/空回执当成可用事实。

任务契约以 `runner` 显式传递的原始用户指令为准，不能让后续插入的呈现指令或检索资料取代用户问题；兼容调用未提供该参数时，沿用已有消息提取逻辑。

| 输出 | 处理 |
| --- | --- |
| 只有标题、标题加来源行、只有标题层级 | 拒绝，尝试一次补全 |
| 空正文 | 拒绝，沿最终回复恢复及验收处理 |
| 正常简短事实、负面结果、明确不确定性说明 | 结构通过 |
| 明确的具体澄清问题 | `needs_input`，不强迫调用工具 |
| 用户明确只要求标题 | 保留标题；“不要只给标题”等否定不构成豁免 |
| 模型 `length` | 保留已有截断提示，标记未完成，不将其误判为标题故障 |
| 未收到有效结束状态的流提前关闭 | 不以部分正文自动判完成，进入一次补全并记录原始原因 |

检测针对可确认的结构缺失，不以统一字数门槛迫使简短答案扩写。带事实的 Markdown 标题也可通过。

## 有界补全与失败闭环

1. 拒绝候选输出后记录 `reject`，清空前端未决增量，展示补全进度。
2. 复制对话与策略，加入预算内的本轮原始回执；各来源分摊总字符预算。
3. 调用同一选定模型一次，不提供工具，关闭 thinking 和 runner 的网络重试，缓冲候选答案。允许代理既有的瞬时网络重试，客户端仍受本次截止时间约束。
4. 调用预算为 `min(30 秒, 单次调用预算, 任务剩余时间)`；不足 5 秒不启动。总任务已到期时保留原有 TimeoutError/退出码 124 路径。
5. 对候选再次验收；工具协议、未执行脚本、内部计划、空输出、再次仅标题、`length`、提前 EOF 均不能作为成功补全。
6. 补全仍不合格或异常时，输出明确“本次回答未完成”，记录原因，不再追加轮次或切换模型。错误原因只记录类型和分类，不携带上游密钥或错误正文。

## 状态与可观测性

既有 DSH/SSE 协议和进程成功语义保持兼容，新增字段随 `executionTrace.metrics` 持久化：

```json
{
  "answerValidation": {
    "status": "completed | needs_input | incomplete",
    "reason": "substantive_answer | title_only | recovery_timeout | ...",
    "attempts": 0
  },
  "modelResponses": [{
    "rawChars": 24,
    "cleanChars": 24,
    "rawSha256": "sha256",
    "cleanSha256": "sha256",
    "finishReason": "stop",
    "finishReasonSource": "upstream | done_fallback | stream_closed",
    "receivedDone": true
  }]
}
```

`attempts` 只能是 0 或 1，`answerValidation={}` 表示不适用；`guardDecisions` 保存拒绝、补全和接受的链路。指纹不保存响应原文或思考原文，用于区分模型生成不足和清洗损失。`upstream` 指模型代理明确透传的状态，不证明底层推理服务内部行为。

## 验证与生效

回归覆盖原始标题、合法短答案、澄清、标题请求及否定、补全成功与失败、低预算、父级超时、length、EOF、非法工具协议、来源公平裁剪以及规划/前置检索回执贯通。循环和规划集成测试验证不会重复执行搜索。

本地开发沙箱使用 `${PROJECT_ROOT}` 模块目录挂载，每次请求启动新的 dsh 进程，核对实际挂载及新进程源码摘要即可确认生效；本次未修改常驻 Node 服务代码或配置。无源码挂载的部署须更新镜像并按统一 Docker 入口重建沙箱。

本次验证结果见 [修复验收报告](../audits/sports-call-fix-2026-10-22.md)。
