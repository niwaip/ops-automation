# 外部 MCP 连接：使用与运维

本项目作为 MCP 客户端，复用官方 SDK 和外部服务提供的数据库连接器。平台自身不开放 MCP Server。当前支持 Streamable HTTP、无需认证的公开服务、手工 Bearer Token/API Key；OAuth 登录、stdio 本地进程和特定数据库供应商适配不在本次交付范围。

## 入口与权限

- 个人设置 → 外部工具连接：配置个人连接、绑定本人凭证、选择工具。
- 管理后台 `/admin/mcp`：管理员配置当前组织连接，发现并发布工具，设置读写属性及允许角色。
- 需要认证的连接，每位使用者在个人设置中为工作连接绑定本人外部凭证；管理员发布连接不会共享管理员凭证。
- 写入或未明确标记为只读的工具必须在连接页面核对参数并确认。确认有效期为 10 分钟。工作流程会阻塞，确认后需续接原执行。
- 修改连接配置会创建新版本，旧工具及授权失效，需要重新授权和发布。
- 远程写入超时可能已经提交，状态标为 `outcome_unknown`。平台不自动重复调用；先向外部系统核对。

外部 MCP 服务负责适配数据库及数据库侧权限。把工具标为只读并不能证明它没有副作用；应使用数据库只读账号、最小授权及经过审查的服务。不要直接向模型开放任意 SQL 写入工具。

## 启动

所有命令在仓库根目录执行，挂载通过 `${PROJECT_ROOT}`。

1. 在 `docker/.env` 设置 `MCP_RUNNER_SECRET`，使用密码管理器产生至少 32 字符随机值；Platform 与 Runner 必须一致。复用现有 `USER_CREDENTIAL_ENCRYPTION_KEY`，按原凭证库备份及轮换规则管理。
2. 按现有迁移流程应用 `20261104000000_add_outbound_mcp` 并生成 Prisma Client；控制面 schema 由 canonical schema 同步。
3. 执行 `PROJECT_ROOT="$PWD" ./docker/start-smart.sh dev up -d`。新增服务为 `mcp-client-runner`，无宿主机发布端口。
4. 构建或依赖变更后显式重启相关服务，不能假定热更新生效。

支持公开 HTTP（含自定义端口）和 HTTPS（默认 443）。保存的服务地址禁止 URL 内嵌认证、查询参数及片段，调用禁止跳转及跨路径请求。API Key 可配置为请求头或单个查询参数；查询参数只由 Runner 在校验目标后注入，不进入保存的地址或 SDK 地址配置。企业内网 MCP 可继续使用 Platform 和 Runner 中的 `MCP_PRIVATE_HOST_ALLOWLIST` 与管理员连接的精确主机名单。个人连接不能自行扩大内网访问范围；需要访问本机服务时使用下方的运维精确端点配置。云元数据、链路本地、广播等地址仍被拒绝。

### HTTP 与平台宿主机服务

传输方式仍选择 `Streamable HTTP`，服务地址可以填写 `http://主机:端口/mcp`，不需要新增一种传输类型。路径必须与 MCP Server 实际提供的路径一致；支持根路径的服务也可填写 `http://主机:端口`。

`localhost` 指平台侧服务所在环境，不是浏览器用户的电脑。Docker 中配置 `MCP_LOCAL_HOST=host.docker.internal` 后，保存 `http://localhost:9000/mcp`、`127.0.0.1` 或 `::1` 会转换为宿主机域名；页面及授权提示展示转换后地址。Runner 配置 `host.docker.internal:host-gateway`，兼容 Linux 宿主机访问。

本机或其他专用服务必须由运维在 Platform 和 Runner 同时设置 `MCP_TRUSTED_ENDPOINTS`，逗号分隔**完整 URL**。例如本地开发环境：

```dotenv
MCP_LOCAL_HOST=host.docker.internal
MCP_TRUSTED_ENDPOINTS=http://host.docker.internal:9000/,http://host.docker.internal:9000/mcp
```

该策略只放行精确的协议、主机、端口和路径，不放行相邻端口及其他路径；个人连接和工作连接均可使用运维已批准的端点，仍保留原有所有权、组织角色、本人凭证及写入确认检查。允许某个本机端点不等于共享管理员账号或取消网络检查；云元数据与链路本地地址即使写进名单仍被拒绝。

变更环境变量后须从仓库根目录通过 `PROJECT_ROOT="$PWD" ./docker/start-smart.sh dev up -d --no-deps platform mcp-client-runner` 重新创建相关服务，单纯重启不会载入新的 Compose 环境。代码变更需要构建并核对运行结果。未启动 MCP 服务时，配置可以保存，但发现工具仍会提示连接失败。

## API Key 查询参数认证（高德地图等）

高德官方 Streamable HTTP 地址示例为 `https://mcp.amap.com/mcp?key=个人密钥`。平台配置时拆开填写：

- MCP 服务地址：`https://mcp.amap.com/mcp`。
- 认证方式：`API Key`；API Key 位置：`查询参数`；API Key 参数名：`key`。
- 保存后在「连接我的账号」中只填写本人 Key 的值，然后发现并选择工具。

配置 API 字段为 `authType=api_key`、`authLocation=query`、`queryParameter=key`；省略 `authLocation` 的旧配置继续使用请求头。参数名只允许字母开头、最多 64 位字母/数字/下划线/连字符。Bearer 和无需认证仅允许请求头位置配置，不接受查询参数认证。

工作连接仍只允许组织管理员配置，凭证仍由每位用户单独加密保存。改变配置版本后需要重新授权及发布工具。Runner 对初始化、工具发现、调用和会话清理统一注入查询凭证；不会把它改发成 `X-API-Key`。返回的目录和工具结果在进入持久化或展示前，对凭证原文及 URL 编码进行脱敏；远端错误保持固定安全分类。第三方服务本身仍可看到鉴权 URL，需按其凭证管理规则使用。

生产部署需要接入对应环境的私密变量管理，并部署 Runner、限制网络出口；本次验证的是本地开发 Compose，不代表生产环境已经部署。

## 工程边界

连接、版本、用户授权、工具绑定及调用记录持久化在 PostgreSQL。凭证使用原有加密库，但标记 `purpose=mcp_transport`，不会注入沙箱或供通用 Skill/凭证测试入口解密。Runner 通过带时间窗及防重放的 HMAC 内部请求接收单次调用凭证，每次创建独立 SDK 客户端。

工作工具通过现有 builtin registry 发布为 `platform.mcp.<bindingId>`，权限额外校验当前组织及不可变绑定。`McpInvocation` 是个人及工作网关共用的确认与防重复记录；它没有替换现有工作流/outbox，也不能保证任意外部系统的 exactly-once。不同调用标识的重新发起仍可能造成业务重复，需要外部业务键及对账支持。

## 传输方式

MCP 消息采用 JSON-RPC；当前主要标准传输方式是 stdio 和 Streamable HTTP，旧版 HTTP+SSE 仍有存量服务。Streamable HTTP 本身也可以返回 SSE 流，与旧版独立 SSE 端点不同。本项目的传输字段仅接受 `streamable_http`，页面显示其他方式尚未支持。匿名连接不创建虚假凭证、不发送 Authorization 请求头，仍执行原有所有权、组织、角色及写入确认检查。

## MCP Skills 与分层披露（2026-11-04）

已启用、已选择当前版本工具的连接自动投影成用户权限范围内的虚拟 Skill。复用个人沙箱的 `get_available_skills`、`SkillRouter`、`read_skill`，无需生成磁盘 SKILL.md，也不将个人连接注册为全局能力。用户 Skills 页面新增“外部 MCP Skills”列表；组织工具继续按现有 builtin 能力目录发布。

1. **目录层**：每个连接一条 Skill 摘要，包含名称、简短用途、别名和模式；不包含工具 Schema。
2. **Skill 层**：读取该 Skill 才返回该连接的工具索引（名称、短描述、操作类型），不包含完整参数。
3. **契约层**：`list_external_tools(skill_id, tool_name)` 只返回选定工具的输入/输出 Schema 和 binding ID；随后经原受控调用入口执行。

无参数的 `list_external_tools` 仅列 Skill 元数据，不再一次返回所有远端工具 Schema。连接停用、切换版本或角色权限变化会从服务端目录撤回相应能力；沙箱目录缓存最长 10 秒，实际调用始终重新校验权限，不依赖缓存授权。

普通查阅请求命中外部 Skill 后仅提供 Skill 读取和 MCP 发现/调用工具，不额外授予 shell，也不静默使用普通网页搜索。组合文件任务仍按原有文件工具规则提供能力；统一的末尾汇合保证早返回的文档分支也能发现 MCP。披露步骤元数据为多轮发现、取契约、调用和回答预留执行轮次。

API：`/mcp-integrations/skills`、`/skills/:id`、`/disclosure` 均按当前用户、个人/工作模式及组织角色过滤。个人沙箱经 `/ai/proxy/v1/mcp` 的认证代理访问，仅提供个人模式。

### 能力与执行说明预览

个人设置、管理员连接页及外部 MCP Skills 列表统一提供「能力与执行说明」。先显示由当前可见已发布工具描述裁剪拼接的能力摘要，支持展开目录提示词预览、平台执行说明，再按需展开单个工具的完整描述和输入/输出契约。目录预览与沙箱生成规则通过跨语言对照测试保持一致。此入口只读，不调用外部 MCP，不签发模型调用凭据；`GET /mcp-integrations/skills/:id/tools/:toolName?mode=personal|work` 继续校验本人范围、组织角色、启用状态及当前工具版本。

未保存能力摘要时采用确定性拼接：最多前 8 个工具、每个 72 字符、总计 512 字符，模型目录再截至 160 字符。工具索引仍包含全部本人可见工具；不要把目录预览理解为完整能力清单。

发现工具仅使用 SDK `tools/list`；远端初始化说明、MCP `prompts` 和 `resources` 不会自动转为系统提示词。执行说明由平台统一模板生成，工具描述和结果作为外部数据处理。生产运行时无高德连接 ID、域名或 `maps_*` 工具名分支；通用中文能力短语评分、坐标字段识别及「从 A 到 B」依赖策略仍是显式编写的启发式规则，适用范围有限。

### AI 生成与编辑能力摘要

连接页及能力详情中的「AI 生成能力摘要」调用现有模型网关 `/ai/model/call` 的默认模型，将当前本人可见的全部已发布工具名称、描述、经审核的操作类型及有限参数用途摘录归纳为最多 160 字符的能力总述。支持 1–100 个工具，不再只取前 8 项。不会发送连接地址、凭证、参数默认值、示例值或真实业务查询结果，也不调用外部 MCP 工具。

生成结果是草稿，展示能力到工具的覆盖映射；覆盖检查要求每个工具恰好出现一次。模型提出的业务原词，仅在对应工具说明/参数说明和最终摘要中都能核对时才展示，忽略空白及括号举例；未通过的词不作为原词依据，不阻止合理的中文归纳。生成使用共享 30 秒预算，JSON、长度或覆盖校验不通过时最多一次修复；模型或网络失败不写入现有摘要，也不把拼接结果标成 AI 生成。拒绝日志仅记录固定原因分类、轮次和工具数量，不输出草稿及凭证。

本人可以编辑草稿、保存或恢复自动摘要。个人连接仅本人可操作，工作连接仅本组织管理员可操作；生成前后和保存时都重新验证权限与当前工具集合。保存仅更新 `mcp_connections.capability_summary`，不创建传输配置修订，不使本人授权失效。该元数据不直接公开在连接列表；目录只复用与当前修订及当前角色可见工具集合完全一致的摘要，权限或工具变更后自动回退。管理员与员工可见工具不同的情况下，不将管理员摘要直接用于员工目录。

保存的摘要同时用于路由和一级目录。路由另使用 `routing_description` 中经过权限过滤的原始工具短描述作补充，最多 1024 字符；它不加入模型提示词，因此摘要中的缩写、近义词或中英文转换不会挤掉已有能力词。完整 Schema 仍保留三级按需披露。沙箱元数据缓存最长 10 秒；后续请求在缓存过期后使用新摘要。该功能不提供平台执行说明的任意编辑。

API：`POST /mcp-integrations/connections/:id/summary/generate` 生成草稿；`PUT /mcp-integrations/connections/:id/summary` 接收 `description`、`revisionId`、`toolsetDigest`，空字符串恢复自动摘要。`DELETE /mcp-integrations/connections/:id/summary` 可直接恢复自动摘要，不依赖 AI 可用性。过期草稿返回 409，非法/超长摘要返回 400。部署前应用 `20261105000000_add_mcp_capability_summary`，更新 Prisma Client、构建 Workbench 并重启 platform。

## 执行与来源优化（2026-11-05）

- 只读连接公开 read_only 元数据，复用既有只读准入快路径，避免模型对明确只读查询反复要求选择场景；含写入或未知副作用的连接仍按原准入及确认规则执行。
- 个人沙箱必须先读取单工具契约。披露接口签发绑定用户、工具、版本、Schema 摘要和模式的短时凭据；代理调用走受验证的专用入口。凭据不进入模型可见文本。现有工作能力使用其已冻结契约，管理页面直接测试保持原接口。
- Runner 在同一 SDK 会话内重新核验远端 Schema 并执行工具，避免每次调用建立两套 SDK 会话。仍按用户单次调用隔离，不共享认证或远端会话。
- 只读调用单次上限 15 秒，仅连接/网络超时类故障最多重试一次；写入和未知副作用从不自动重试。失败持久化安全的 phase/category，不输出远端错误原文或凭证。
- MCP 文档结果去重、按需限量展示；原始返回仍保存在调用记录。模型收到的结果不重复包含 JSON 文本与 structuredContent 两份完整文档。
- MCP 专属请求不再自动混入个人成果库匹配。来源页脚从本轮成功 MCP ToolResult 的结构化证据生成，优先列出答案实际引用的返回来源，区分片段与全文，不使用环境扫描条目冒充引用。
- 文档类回答增加一次有时间预算的原文依据审核：配置要点要有有效 source_id 和可在该来源片段找到的原文引句。无法审核或证据不足时收窄回答，不返回未经核实的草稿。原文匹配并不等同于形式化证明语义正确，仍需关注产品/版本和关键操作适用性。
- 未在本轮证据或用户输入中出现的 UUID 类配置标识会被隐藏，避免把记忆中的旧应用 ID 当作已核验配置值。
- 模型 fallback 默认最多选 2 个兼容候选，过滤明确缺密钥和输入/输出能力不匹配项，失败候选进入短时冷却；缓冲流也遵守配置重试次数，且传递 fallback 的工具调用元数据。未改动管理员模型配置。

admin 的 Microsoft Learn 测试连接另启用了只读 microsoft_docs_fetch，允许按需取教程正文。新增测试在 `test_mcp_optimization.py`、`test_mcp_answer_review.py` 和 `sandbox-fallback.policy.spec.ts`；本日集成证据见 `docs/artifacts/reviews/mcp-outbound-verification-2026-11-05.json`。

## 模型中断与查询步骤约束（10:27 调用回归修复）

- 明确命中只读 MCP Skill 时，按执行证据逐步提供 Skill 读取、单工具契约披露、已披露 binding 调用的工具选择。每步缩小通用工具参数中的 Skill/binding 范围；仅把本步已披露的一个 inputSchema 用于 arguments 校验描述，不注入所有远端 Schema。已完成、已失败或待确认后不强制继续调用；写入及未知副作用任务不使用该强制步骤。
- 模型代理在内部缓冲之前检测正文/思考内容的连续重复，立即取消上游请求，返回 `MODEL_REPETITION`。仅保存模式长度、次数、目标和 SHA-256，不保存重复原文。工具参数不参与正文重复检测。
- 内部缓冲上限为 2 MiB / 32768 帧；MCP 工具阶段单次生成预算 45 秒，其他内部缓冲请求 180 秒。超限分别返回 `MODEL_STREAM_LIMIT` / `MODEL_GENERATION_BUDGET`。这类主动终止不会自动重试或切换候选模型；普通临时网络故障仍遵守既有有界重试规则。
- MCP 来源门禁保留结构化模型终止原因，不再把“没有成功结果”统一描述成连接故障。没有核验结果仍不得输出已核实答案。
- 中断的模型请求也写入调用账本和 `model_failed` 事件，计入调用次数及耗时。`usageKnown=false` 标明缺失用量，`tokenUsageComplete=false` 表明汇总 Token 不是整轮完整消耗；不会把未知用量补成 0。进程正常退出仍不代表业务任务成功。
- MCP 代理保留安全的 HTTP 错误状态，屏蔽 Axios 请求配置、凭证及上游错误正文；沙箱在发出请求前拒绝非对象业务参数。通信、参数、鉴权、权限等失败统一返回类型化 ToolResult，不再被普通字符串适配为成功，最终答复使用固定的错误类别说明。
- 回归：`test_mcp_failure_regression.py`、`test_model_repetition_breaker.py`、`test_llm_accounting.py`、`sandbox-stream-guard.spec.ts`。真实模型验证脚本 `tests/e2e/mcp/verify-personal-skill.cjs` 可通过第一个参数指定独立证据文件，保留历史验证记录。

## 后续步骤、审核来源与有界恢复（10:57 调用回归修复）

- 每次披露只读工具都建立待执行步骤，下一次受控调用只接受该 binding。该约束在首次搜索成功后仍生效；同一强制步骤中的并行调用不能切换 binding 或重复执行。请求发出前消费步骤，网络失败后不强制重复；参数/步骤错误在本地返回失败回执。模型请求和工具派发使用同一阶段的工具集合。
- 审核前按文档 URL（忽略锚点）跨调用去重，合并不同片段，优先已读取正文及文档类来源，将已识别社区问答单独分类。最多 8 个文档，每个最多 5000 字符，总原文字符预算 20000；额度在入选文档间分配。每个片段保留自己的 invocationId，不能用同文档的另一轮调用冒充该引文来源。
- 资料生成稳定的 source_id 和原文 span_id。模型选择段落编号并概述其内容，程序回填该段的原始文本、链接及调用记录，避免模型复制时插入省略号或改动 Markdown 而导致引用全部失配。跨来源段落、未知编号、无效字段及社区问答配置依据均有明确拒绝分类；兼容回执中的手写引用仍须通过严格原文匹配。
- `mcp_review_sources` 记录实际入选来源、片段、调用、字符数和裁剪状态；`mcp_answer_review` 记录轮次、候选数、有效要点数、逐项拒绝原因及有界候选字段。凭证样式脱敏，候选 statement/quote 分别限 700/1000 字符。模型账本用 `mcp_answer_review`、`mcp_answer_review_repair` 区分阶段；失败请求不会重复记账。
- 首轮零条通过后，最多补读一个同 Skill 的新文档，再进行一次审核修复；资料 URL 来自本轮回执，补读工具先通过单契约披露并核验 effect=read。自动恢复要求已准入只读 Skill；写入、未知副作用及未确认权限不会自动执行。补读走现有本人授权、版本契约和 MCP 网关，并记录 `execution_origin=mcp_review_recovery`。
- 整个审核恢复流程时间预算 40 秒，并受原任务剩余时间限制；单次审核最多 15 秒，补读阶段最多 12 秒，最多两次审核、一次文档读取。模型重复熔断直接保留原因并结束，不进入自动恢复。仍无有效要点时返回明确的未核验提示，不交付无依据草稿。
- 本次只改沙箱 Python 模块；其通过既有只读目录挂载供每次新 dsh 进程导入，不依赖常驻热更新。真实回归核对新增诊断及模型 purpose，确认加载了新代码。

## 业务能力召回与坐标依赖（公共交通请求修复）

- 虚拟 Skill 从权限过滤后的当前版本工具生成用途摘要：最多读取前 8 个描述、每个 72 字符、总计最多 512 字符；不包括参数 Schema。模型目录对每个 MCP Skill 最多显示 160 字符，工具索引和单工具契约仍按需读取。
- 路由对用途摘要中的明确中文能力短语增加匹配分数，不要求用户输入技术服务名，不硬编码高德服务或某个连接 ID。匹配分数、选中 Skill、授权状态及只读状态记入 `mcp_skill_route`。
- 只读 MCP 的默认预算为 10 轮，工具阶段最多 12 轮，并继续受任务时间预算约束。避免地址解析等依赖链被普通查阅的短轮次提前结束。
- 通用 `results` 数组不能单独作为文档判据。地理编码和 SQL 行保留原始结构；只有包含文档字段的结果进入文档摘要与引用处理，防止经纬度被当作无链接文档丢弃。
- 对已披露契约中明确声明的坐标字段，在调用前核对本轮用户输入及成功只读返回值；拒绝猜测坐标、近似改写和受控步骤中的参数串用。校验失败不会发送远端请求，并释放步骤以允许补查依赖。
- 对明确的「从 A 到 B」请求，结合已披露坐标契约与已发布只读地址解析能力，分别绑定原始起终点进行查询，再将对应坐标绑定到目标字段。仅适用于契约和工具索引可明确识别依赖的场景；不把未知/写入工具自动分类为只读。
- 完成辅助查询并不代表完成目标。目标可从工具索引明确区分时，必须有本轮对应目标工具成功回执，才能交付完整方案；诊断为 `mcp_objective` / `mcp_dependency_step`。该机制验证调用及输入依赖，不是对生成回答所有自然语言断言的形式化证明。
- admin 已有高德只读路线配置旁补充了 `maps_geo` 和 `maps_text_search`，保留当前修订、本人凭证及已有骑行/驾车工具。真实验证使用独立 `mcp-transit-test-*` 会话，不污染用户聊天历史；按该会话 evidence 的 invocationId 核对数据库回执，避免混入并发调用。
