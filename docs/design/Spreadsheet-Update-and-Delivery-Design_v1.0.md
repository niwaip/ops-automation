# Excel 理解、跨文件更新与验证交付实施方案

日期：2026-10-23，Asia/Shanghai。状态：部门聚合回填首期已实现；当日修复与实测记录见下方。

本方案基于当前工作区代码、现有 Excel 查询能力、技能准入约定，以及用户提供的工数预实工作簿。工作区已有未提交修改；实施应保留这些修改，逐个集成点核对当前源码。本文不表示服务、接口或端到端流程已经通过验证。


## 2026-10-23 去除模板假设后的接口

2026-10-24 补充：已删除 `work-hours-update` 专用技能及运行时副本。标准工作簿更新由独立任务契约直接选择通用更新引擎，不加载领域技能正文。对单位问题的简短答复沿用已核对的原任务、来源与目标，使用相同的平铺聚合接口。目标单位接受工作簿声明或经意图提取、独立复核、原话匹配后的用户确认；模型在规划工具里自行填写单位不构成确认。单位确认随当前执行上下文绑定，独立新任务不继承；与工作簿唯一声明冲突时需要说明冲突。

完整的简短单位答复由标准单位表直接识别，避免语义复核将其丢失；只在延续任务时绑定，问句、否定和来源字段不按这种完整答复处理。若语义要求清单只保留了新增单位，使用紧邻的原始用户更新任务恢复能力路由，跳过前面的单位答复，不使用助手内容或附件文字增加执行权限。默认输出名已存在时自动分配带序号的新文件名；显式指定的冲突名称仍拒绝覆盖。

当前模型接口按实际读取结果绑定业务。`SpreadsheetUpdatePlan/v1`、原子操作和哈希属于服务端内部数据。

标准更新流程的 `aggregate_spreadsheet` 仅暴露实际文件、Sheet、表头行、平铺过滤条件、分组字段、值字段和聚合方式，由服务端编译为既有 Query IR。此流程跳过独立的自由文本规划阶段，避免模型在读取正式工具定义前生成另一套查询协议；实际推理、读取、聚合、更新规划及执行仍经过正常工具链。

规划器的必填字段为 `target_file`、`base_sheet`、`new_sheet`、`period`、`period_field`、`section`、`target_label`、`target_kind`。它们来自本轮请求、当前工作簿与已执行来源查询，不再从日期格式、字段别名、编码格式或默认位置推断。`result_id`、`key_field`、`metric_id` 用于多结果、多分组、多指标的消歧；`target_range` 和 `protected_labels` 引用实际区块及受保护标签。

`target_unit` 可省略，由规划器读取工作簿的实际单位声明。多单位时使用真实 `unit_cell` 消歧。来源单位不能作为目标单位依据；缺少依据返回 `needs_input`，保留输入，不制造示例说明或猜单位写表。

结构工具返回带坐标的 `label_bands`、原文 `unit_declarations` 和显式 `metadata_scan_complete`，不再因为表头移出顶部窗口而让模型分页读取整张表。资源预算只控制扫描成本，不产生字段或布局默认值。

`plan_spreadsheet_update` 仅生成逐格预览；随后 `execute_spreadsheet_update` 与状态查询均只接收 `plan_id`。规划器使用本轮聚合查询的真实分组字段、期间等值约束和指标单位，生成唯一事实/坐标映射。编码可为数字、文字或含分隔符的字符串；未匹配项保留原值。

旧发现器不再生成默认 B 列、默认工时单位或指标/性质/单位别名。底层来源适配器必须显式声明字段与范围；不再自动挑第一张表、猜列或调用隐藏业务技能。对账检查只使用明确的明细/控制单元格与声明容差，不搜索某一种语言的小计标签。

测试覆盖与真实 35B 复测证据见 [本轮报告](../artifacts/reviews/spreadsheet-generic-binding-20261023/report.md)。历史章节是原设计背景，不能代替当前接口约定。

## 1. 交付目标与首期边界

用户通过自然语言指定目标工作簿和数据来源，系统理解其业务区块、指标、期间与输入位置，在副本中更新，完成重算与门禁后交付新 Excel。每个写入值能够追溯到本轮来源和计算过程。

首期落在个人沙箱 DSH，不新增微服务、不新增工作流平台、不先改造 Office 插件。复用现有附件同步、独立任务契约、技能准入、Query IR、ToolResult、证据归档和文件下载。后续 Office 插件与工作模式通过适配器复用同一协议。

| 首期支持 | 首期遇到后的行为 |
| --- | --- |
| 本次上传的一个目标 XLSX、多个来源 XLSX | 来源限当前用户授权的附件；文件目录检索后续增加 |
| 合并表头、多个业务区块、稳定编码、月度列 | 无法唯一定位时返回候选及缺口，不按第一张表或第一处命中执行 |
| 同工作簿复制 Sheet、更新快照日期、按键填入数值 | 原始附件只读；新文件中保存旧 Sheet 和新 Sheet |
| 已有普通公式、月度/季度合计、差异和比率 | 支持范围内保留并重算；禁止把汇总公式替换成固定结果 |
| 编码映射、分组求和、显式单位换算 | 多个匹配按已声明规则处理，缺失不自动填零 |
| 已声明的上次快照比较 | 比较期间和指标有明确绑定，不能把上次快照称为前日 |
| 无图表、宏、透视表、外部链接等复杂对象的模板 | 发现尚未验证可保真的特性时返回 unsupported_feature；保留输入 |

首期不支持任意 Python/SQL/Excel 宏、跨工作簿复制 Sheet、自动修改预算口径、凭相似名称强制映射、自动创建个人技能。XLS/XLSM、动态数组、UDF、INDIRECT/OFFSET 等无法可靠解析的依赖由能力探测明确拒绝；需要时单独建设经过验证的适配器。

## 2. 当前实现与实际集成点

下列路径相对于仓库根目录。图索引可能落后于工作区，实施前必须读取文件确认。

| 模块 | 当前能力 | 本次集成方式 |
| --- | --- | --- |
| `src/dsh_modules/workbook_reader.py` | 工作簿清单、来源哈希、真实范围读取 | 复用，增加区域级发现层，不把顶部三行样本当完整结构 |
| `src/dsh_modules/spreadsheet_analysis.py`、`query_*.py` | 单来源工作簿的受限查询、聚合和计算证据 | 分别执行每个来源，形成多来源事实表；不声称现有工具已支持跨文件 JOIN |
| `src/dsh_modules/workbook_calculation.py` | LibreOffice 重算、缓存验证、来源凭据 | 保留旧入口严格语义，抽出返回候选文件和原始诊断的底层重算入口 |
| `src/dsh_modules/workbook_delivery.py` | 全局公式错误/缓存/内部依赖检查；无效新产物隔离 | 扩展为可接收可信更新上下文的验收入口；普通生成路径保留默认严格检查 |
| `src/dsh_modules/skill_admission.py`、`task_intent.py` | 用户任务契约、候选技能准入 | 引用既有任务契约；不新增基于技能名或“Excel”关键词的权限绕过 |
| `src/dsh_modules/runner.py` | 附件上下文、能力选择、历史状态恢复 | 注册更新能力并注入当前任务绑定；只读任务不暴露更新执行能力 |
| `src/dsh_modules/tools.py`、`tool_dispatch.py` | 工具目录、分发与本轮可用工具约束 | 仅注册/转发；更新实现下沉到独立包 |
| `src/dsh_modules/file_tools.py::send_workspace_file` | 显式发送前检查 XLSX | 接入统一更新交付凭据校验 |
| `src/dsh_modules/artifact_exporter.py::export_deliverables` | 发现本轮文件，返回候选下载项 | 返回交付项之前调用同一校验，不能只看扩展名、修改时间或文件大小 |
| `src/dsh_modules/agent_loop.py` | 终态重算、无效 Excel 隔离、文件存在性断言 | 调用更新终态编排器，避免再次重算已验收文件使最终哈希失效 |

以上 `src/` 均位于 `apps/backend/runtimes/personal-sandbox-runner/`。

当前不是“没有 Excel 文件校验”：显式发送和终态隔离已经存在。缺口是校验还没有绑定自然语言要求、多来源事实、允许变更集合与最终更新事务。现有零错误策略也不能直接处理“历史 Sheet 保留旧错误、当前 Sheet 已修复”的场景。

依赖方向：任务契约 → 更新计划 → 来源查询/事实绑定 → 修改执行 → 重算候选 → 独立验收 → 交付。展示层只读已通过回执。通用查询模块不反向依赖更新编排器。

## 3. 用户流程与自动执行规则

1. 接收“按今天复制最新 Sheet，再用部门统计更新预实数据”的请求。
2. 复用独立任务契约，区分咨询、只读分析、生成新副本、修改预算、保存个人方法等意图。
3. 从当前附件中识别目标和来源；业务日期、期间、版本、覆盖范围用于选择，文件修改时间只作辅助。
4. 形成业务语义绑定与更新计划，程序完成执行前检查和变更预览。
5. 信息充分则自动在副本执行，不要求用户逐格确认；仅对单位、数据性质、来源冲突等会改变结果的歧义提出一个集中问题。
6. 在实际重算后的候选文件上完成确定性检查和语义验收。
7. 返回新 Excel 与简短变更摘要。来源明细、全部门禁和错误基线默认折叠展示。

预览是程序产物，不是默认审批流程。仅当用户要求先预览时停在预览阶段。原始附件、来源文件不被覆盖，外部表格中的文字、批注和隐藏内容不产生新权限。

正常回复示例的结构为：“已创建 <快照名>，更新 <核验数量> 项；计划基线保持原口径；检查通过。<文件卡片>”。数字均来自回执。未通过时说明具体缺项，候选文件留在内部，不作为完成品下载。

## 4. 业务语义与跨文件绑定

### 4.1 WorkbookIR

在清单之上新增区域级 IR，分两阶段生成：程序提取真实结构，模型提出语义解释，程序检查解释所引用的单元格是否存在。语义解释本身不等于业务定义已经得到证明。

每个区块保存：`region_id`、真实范围、标题/表头路径、合并关系、行角色、业务键、期间轴、指标、数据性质、单位、可写输入、已有公式及依赖。保留原始值/类型/格式与有效合并表头两个视图；只在逻辑视图中继承合并标签，不填改原件。

逻辑键采用有类型元组：`(region_id, department_code, metric_id, period, value_kind, unit)`。禁止用未经转义的字符串拼接，也不能只用 FC 编码或物理行号。一个编码可能同时出现在有偿和其他工数区块。

对季度/财年、含税/未税、金额/工时/人日、预测/实绩、月累计/全月等概念建立显式字段。单位由原件、可信配置或用户定义绑定，不由文件名强制推断。工时与人日转换必须有明确换算参数及其来源；金额必须另有币种，不能从 K 推定币种。

### 4.2 SourceCatalog 与 FactTable

来源目录由运行时分配 `attachment_id`、角色和 SHA-256；模型仅引用 ID，不能注入任意文件系统路径。每个来源记录业务截止日期、期间、版本、统计范围、是否完整/已结账、单位、候选业务表和选择理由。

每个来源的受限查询沿用 Query IR，输出规范事实表：业务键、Decimal 数值、单位、数据性质、期间、截止日期、来源行/单元格、查询计划哈希与证据 ID。多文件聚合由受限组合器执行，不能依赖模型抄写聚合值。

匹配策略需要显式区分：唯一查找、先分组聚合后匹配、经授权映射表转换。先检查连接基数，禁止多对多连接造成金额/工数放大。相同编码的冲突、不完整月份、遗漏部门、额外部门分别报告。

来源中存在控制总计时独立提取并核对；没有控制总计时，可以独立重算明细并标注核对层级，不能声称“已与权威源总额对账”。

## 5. 更新契约与受限操作

新增 `SpreadsheetUpdatePlan/v1`。下面是字段设计而非已经发布的工具 Schema；省略项不代表可以静默采用默认业务规则。

| 字段 | 内容/约束 |
| --- | --- |
| `task_contract_ref` | 当前用户原话、明确限制、要求 ID；运行时绑定，模型不能改写 |
| `target_ref`、`sources` | 运行时附件 ID、期望哈希、角色与来源选择规则 |
| `as_of` | Asia/Shanghai、完整日期、来源于本轮时间上下文或用户指定；进入计划后固定 |
| `snapshot` | 候选日期证据、选中 Sheet ID、命名方式、同日冲突策略 |
| `semantic_bindings` | 区块、业务键、指标、期间、单位、数据性质及定位依据 |
| `source_queries` | 每个来源的 Query IR 与当前证据引用；不接收任意 SQL/代码 |
| `mappings` | 来源事实到目标逻辑键的连接、聚合和换算规则 |
| `operations` | 下表中的受限操作及用户要求关联 |
| `preserve` | 历史 Sheet、计划基线、已有公式、样式/合并/打印属性等保护集合 |
| `checks` | 结构、覆盖、总计、差异、单位、依赖、保真、目标要求检查 |
| `requirements` | 要求 ID → 操作/检查节点的覆盖关系，不能只写解释文字 |
| `output` | 展示名、XLSX、输出字段/范围；落盘路径由运行时分配 |

首期仅提供以下操作：

| 操作 | 行为与前置条件 |
| --- | --- |
| `copy_sheet` | 复制已确认的最新业务 Sheet 到同一候选工作簿，验证支持的对象与属性 |
| `set_snapshot_date` | 写入已绑定的快照日期位置，保留模板日期显示惯例 |
| `fill_from_result` | 从本轮 FactTable 引用取值，按逻辑键写入已经解析的输入格；禁止模型提供业务数值常量 |
| `bind_snapshot_comparison` | 按显式指标/期间生成受限差额公式；通过 Sheet/单元格引用构造器生成并正确转义 |

V1 不公开任意 `set_formula`、整表清空、删除 Sheet 或覆盖来源。复制保留的旧公式可包含原模板公式；新生成比较公式只允许已验证的引用和运算。

编译器生成不可变 `CompiledUpdate`：实际单元格写集合、旧值与类型指纹、新值来源、受影响公式集合、保护集合和预期检查。目标原来是公式、合并单元格从属格或保护格时拒绝写入。业务规则要覆盖公式时应作为独立能力建设，不自动降级覆盖。

编译后的所有数值变化必须有来源回执，所有公式变化必须有明确规则。`plan_hash` 使用规范化 JSON；`request_hash` 由可信任务契约生成，分别保存，防止模型计划自洽但偏离请求。

## 6. 工具接口与能力路由

复用已有结构读取/查询工具，新增三个模型可调用入口，内部阶段不全部暴露为独立工具：

| 拟新增工具 | 输入 | 输出 |
| --- | --- | --- |
| `plan_spreadsheet_update` | 目标/来源 ID、业务绑定、受限查询、更新操作 | `plan_id`、计划哈希、预览、未解决问题与结构证据；不输出可编辑任意脚本 |
| `execute_spreadsheet_update` | `plan_id`、期望计划哈希 | 运行时复核原件 → 副本写入 → 重算 → 确定性门禁 → 独立语义验收，返回 `run_id` 与回执 |
| `get_spreadsheet_update_status` | 当前用户有权访问的 `run_id` | 阶段、缺项、摘要、已验证成品引用；支持中断后的状态查询 |

发布由执行器在全部条件满足时内部触发；模型不能通过 `publish=true` 豁免验收。需要分阶段停留时，预览和执行由同一计划引用衔接。

权限来自用户请求、任务契约、输入和运行时配置。标准更新任务提供受限读取/查询/更新工具，不提供通用 bash、patch_file 或任意写文件入口来实现同一任务。即使另一受权任务可执行通用脚本，其 Excel 产物也不能伪造标准更新完成状态。

不匹配技能仍可使用通用更新能力。技能默认口径只有通过既有准入的明确调用才生效。沿用 `Personal-Skill-Execution-Gates.md` 的独立要求覆盖和语义验收，拒绝用技能名、附件名或历史助手答案替代当前授权。

## 7. 执行、恢复与凭据

状态主线：`discovered → planned → prechecked → applied → recalculated → validated → published`。异常状态：`needs_input / unsupported / failed`。工具执行成功、文件存在、重算进程结束分别只证明对应阶段；只有 published 可宣称标准更新完成。

内部工作目录采用 `/workspace/.dsh/spreadsheet-runs/<run_id>/`，保存输入快照、计划、候选、差异、诊断和检查。原附件始终只读；输入快照在事务开始时校验全部哈希。运行中和发布前再次核对来源，变化则拒绝旧计划。

候选先完整落盘，失败不覆盖最后成功产物。发布时在同一文件系统原子切换到不可变输出版本，并再次读取确认哈希；不覆盖已有用户文件。下载应服务固定成品字节或不可变对象，防止验收后替换文件。

幂等键由用户/目标逻辑资源、任务契约哈希、输入哈希集合、配置版本、规范化计划与固定快照日期生成。同一运行重试复用有效结果；任一业务输入变化产生新运行。目标逻辑资源使用短期互斥锁，并发不允许同时提交。

当天同名 Sheet 已存在时，仅在来源、计划与运行凭据一致时复用；否则返回具体冲突。新版本后缀策略必须来自用户或已接受的模板约定，不能默默覆盖或不断追加“(2)”。

每阶段输出统一 ToolResult，并保存 `kind=spreadsheet_update`、run/plan/request ID、输入哈希、编译写集合、来源证据、候选/成品哈希、引擎版本、检查版本和要求覆盖。完整细节写入现有当轮证据归档，模型仅接收预算内摘要。

运行时凭据不能由模型提交的 JSON 或工作区任意 sidecar 自我证明。当前执行使用运行时维护的证据对象；跨请求恢复须通过服务端持有的可信记录校验或重新验证成品，不能直接相信可编辑状态文件里的 passed。计划和文件哈希不等于权限凭据。

超时/进程崩溃后保留阶段状态。恢复时验证全部指纹，仅从完整阶段继续；无法确认的候选重新执行验证。模型纠偏最多两份有效计划，确定性检查不能被语义审核豁免，仍受总截止时间和预算约束。

## 8. 重算与历史错误：必须单独解决的兼容问题

当前原件有断引用和除零错误。复制 Sheet 会把错误带入新 Sheet；既有全局零错误检查会拒绝文件。不能只在提示词中承诺“忽略旧错误”。

拆开三个状态：

1. `engine_execution`：计算引擎是否确实完成本次计算，输入/输出文件是否对应本轮候选。
2. `global_formula_health`：整个文件的错误、未计算值、缺失依赖等原始诊断，可为 partial。
3. `delivery_validation`：目标 Sheet、可见交付结果及其完整依赖闭包是否满足当前契约。

旧的 `get_or_create_recalculated_workbook` 继续保持默认严格返回条件。抽出公共底层 `recalculate_candidate`，无论诊断为 clean 或 partial，都返回实际候选路径、引擎执行结果和诊断；不把 partial 改名为 verified，也不返回原件冒充已计算候选。更新模块负责作用域验证，旧分析路径不自动放宽。

历史错误指纹包含原始 Sheet 身份、单元格、规范化公式、错误类型与来源哈希。新复制 Sheet 是新的交付对象，不能因为公式相同就继承历史豁免。

只有以下条件全部成立，旧错误才可标为不阻断告警：

- 仅位于保留的历史 Sheet，错误与基线一致；
- 当前交付结果及其依赖闭包均不读取该错误格；
- 依赖闭包完整可解析，没有未知动态引用、外部引用或其他不确定边；
- 历史内容保护及当前作用域所有检查通过。

无法证明隔离则阻断。目标 Sheet 内的断引用、除零、缺失缓存均阻断；没有业务依据时不使用 IFERROR(...,0) 或直接置零。零分母如何显示，由用户或可信业务配置定义后才可修复。

带历史告警的状态为 `published` 且 `validation=passed_with_warnings`，用户正文明确“当前更新范围通过，历史页仍有已列明问题”，不能写成“整本无错误”。旧生成路径无可信更新回执时继续采用全局零错误检查。

重算可能改写公式表示或样式。通过允许的公式等价规范化做内容比较，不比较 ZIP 二进制一致；常量、业务日期、合并、格式等仍逐项核对。不能用“引擎会这样保存”解释掉未知保真差异，无法保真则不发布。

## 9. 门禁矩阵与统一出口

| 检查 | 判据 | 失败行为 |
| --- | --- | --- |
| 输入/权限 | 当前用户、附件/配置 ID 可用，哈希与任务绑定一致 | 拒绝或重新规划 |
| 结构/特性 | 最新快照、表头、区块及可写输入唯一，特性在验证范围内 | needs_input 或 unsupported |
| 业务类型 | 期间、单位、数据性质和口径兼容 | 提出具体缺口，禁止猜单位 |
| 覆盖/连接 | 必需键匹配完整，基数符合声明，无未处理冲突 | 不用零、第一条记录或部分结果替代 |
| 写集合 | 实际更改与编译写集合一致，保护内容未变化 | failed，隔离候选 |
| 独立对账 | 规范事实与来源控制/独立明细核算一致，合计无重复累计 | 返回差异与来源 |
| 公式/依赖 | 实际重算；目标与依赖闭包无错误或未计算；历史告警满足隔离条件 | 不发布 |
| 保真 | 受保护常量/公式/样式、合并、行列尺寸、冻结和打印设置符合约定 | 不发布 |
| 语义验收 | 从原始请求独立审核要求覆盖、额外条件、选择来源、指标和交付 | revise 或 clarify，不能豁免以上失败 |
| 发布一致性 | 最终字节哈希、回执、用户/运行/计划/来源一致 | 撤销完成标记及下载项 |

数值按声明单位选择 Decimal/缩放整数及容差；标识、期间、计数和类别精确比较。容差不能由展示小数位倒推，更不能统一设成 0.01。对账的独立路径不能拿目标总计与其自身引用比较。

统一调用 `validate_update_delivery(context, artifact)` 的位置：显式 send_file、自动 ArtifactExporter、终态隔离/完成判断，以及服务端接收该类型产物的注册/下载边界。普通产物与更新产物按可信任务类型选择检查，不依赖文件名或模型标志。

标准更新的候选和中间文件不参与根目录自动发现。原始 OUTBOUND 标记只表示候选引用；标准更新任务不得在 validated/published 前流出下载卡片或“已完成”文本。服务端必须拒绝缺少对应可信回执的标准更新候选。

`agent_loop` 已有的末尾自动重算对已发布更新产物应跳过：新链路已在语义验收前完成重算。任何后续改写都必须撤销旧回执并重新校验，不能让末尾重算改变已验收文件后继续使用旧哈希。

## 10. 模块拆分与改动边界

新增包位于 `apps/backend/runtimes/personal-sandbox-runner/src/dsh_modules/spreadsheet_update/`。按职责逐步创建，避免为凑目录预建空文件。

| 文件 | 职责 |
| --- | --- |
| `contract.py`、`schema.py` | 版本化计划/回执、操作定义及严格 Schema；未知字段/操作拒绝 |
| `discovery.py`、`bindings.py` | 区域结构、表头轴、输入/公式识别、逻辑键到实际坐标 |
| `sources.py` | 多来源目录、Query IR 调用、事实表、连接基数与单位 |
| `compiler.py` | 请求约束校验、受限操作编译、写集合与依赖集合 |
| `executor.py` | 副本写入与底层重算调用；不承担语义审核或展示 |
| `diff.py`、`validation.py` | 独立语义差异、保护检查、对账、历史错误与依赖验收 |
| `turn.py`、`state.py` | 当轮编排、语义审核衔接、阶段持久化、锁和恢复 |
| `delivery.py`、`tools.py` | 成品发布/凭据校验与工具适配；复用 ToolResult |

领域定义独立维护，如工数、稼动率、有偿率；模板配置保存命名、区域选择和字段绑定规则。通用引擎不包含某个 Sheet 名、FC 编码、固定金额或部门过滤条件。

个人模板与配置默认保留在当前用户知识目录，私有业务附件不进入共享代码库或 CI。只有用户明确提出保存/更新方法时才进入现有个人技能捕获流程，保存已通过计划的参数化配方及门禁约定，不保存本轮数值和临时路径。

既有 `agent_loop.py` 已超过 1200 行，新需求只增加小型协调调用；必要的 Excel 终态逻辑提取到交付模块。`tools.py` 保持注册/分发。新业务模块优先控制在 300–500 行以内；禁止把新增编译、写入和检查逻辑继续塞入大文件。

## 11. 以用户附件完成第一条闭环

本次工作簿包含一个名为 1019 的 Sheet；本轮观察到 343 个公式、30 个断引用、2 个除零错误。这些是附件基线，不是通用代码常量；统计结果也不代表已经在 Excel 引擎重新计算验证。

第一条真实验收流程为：

1. 接收目标工作簿和真实部门统计来源；先确认值的单位、预测/实绩口径及统计截止时间。
2. 识别两个业务区块及其 FC 编码、202610–202612 期间；按原财年保留“3Q”。
3. 结合 1019 标签和内部日期证据识别快照；内部数字日期必须经工作簿日期系统和上下文交叉判断，不能把任意普通数字视为日期。
4. 按运行日期复制为新快照，例如本轮 1023，保存完整日期及 Asia/Shanghai。只更新已绑定的日期位置。
5. 由来源查询产生各区块/部门/期间的事实；保留计划基线，更新已授权的当前输入。未结账月份不能仅因“今天属于该月”就改标实绩。
6. 保留合计和差异公式。P 列现有断引用只在有明确比较定义时修复；它当前关联 12 月 E 列，不能直接改成当月差额。
7. 当前新 Sheet 中零分母和断引用必须解决；缺比较定义/零分母口径时进入 needs_input。历史 Sheet 的原有错误按第 8 节隔离核验。
8. 完成重算、独立合计核对、写集合检查和原始请求验收；发布新 XLSX 及变更摘要。

用户尚未提供本轮配套部门来源，因此第一条真实跨文件验收当前具备设计与目标基线，不具备完整输入。缺少的业务信息集中为：来源及截止日期、单位/指标含义、预算是否修订、前日/上次快照比较与零分母规则。实施核心引擎和合成测试无需等待这些输入。

## 12. 分阶段开发与合并验收

建议采用六个依赖顺序明确的 PR；每个 PR 保留兼容入口，独立可验证，不要求先完成全量前端或新服务。

| PR | 实施范围 | 合并验收 |
| --- | --- | --- |
| 1：契约与保真基线 | 计划/回执 Schema、能力探测、输入基线、事务状态；整理重算底层候选接口 | 未知操作/字段拒绝；只读原件；旧重算入口行为不变；partial 候选不假报 verified |
| 2：结构与来源 | 多区块 IR、业务键、期间/单位绑定、多来源 Query IR 与事实表 | 区块/编码重复可区分；列/行重排仍定位；连接基数及来源覆盖有证据 |
| 3：受控更新 | 计划编译、Sheet 复制、来源填值、快照比较、差异与保护检查 | 写集合越界拒绝；不覆盖公式/预算；幂等重试及并发冲突可控 |
| 4：门禁与交付 | 作用域依赖、历史错误、独立对账、语义验收、统一出口 | 目标错误不放行；历史隔离可证明；send/自动发现/最终声明均校验同一成品 |
| 5：聊天接入 | 任务准入、工具路由、集中澄清、阶段进度、文件卡片与摘要 | 自然语言完整执行；只读不开放写工具；只要文件仍有门禁；无提前成功卡片 |
| 6：真实验收与发布 | 私有目标/来源回放、性能记录、故障恢复、运行文档 | 真实来源对账通过；实际容器加载新代码；最终下载文件哈希一致；回滚验证 |

可发布首期版本需完成 PR 1–6；只有局部工具测试通过时不能称为端到端能力完成。PR 6 依赖真实来源和必要业务定义，之前可以用标明为合成的脱敏输入开发。

## 13. 测试与上线门槛

测试分三层：纯契约/执行器、含实际 LibreOffice 的文件集成、通过真实聊天/API 的端到端。接口调用成功不替代成品核验；mock 引擎测试不能证明真实重算或保真。

| 场景组 | 必须区分的变体 |
| --- | --- |
| 理解与定位 | Sheet 乱序/跨年/未来日期、同日候选、多层合并表头、多区块相同编码、列重排/插列 |
| 来源与数值 | 多部门来源、乱序键、一对多聚合、重复冲突、缺失与真实零、额外部门、小时/人日/金额不相容、截止时间不一致 |
| 业务边界 | 预测与实绩、月累计与全月、财年季度、负数合法、预算保留、前日与上次快照区别 |
| 写入与保真 | 仅允许集合更改、历史保留、不能覆盖公式、合并从属格拒绝、格式/冻结/打印设置、复杂对象拒绝 |
| 公式与门禁 | 新 Sheet 继承错误不能豁免、历史独立错误告警、被当前结果引用的旧错误阻断、零分母、未知依赖、引擎不可用/超时/partial |
| 交付与恢复 | 验收后改文件、来源中途变化、伪造回执、显式发送/自动发现/标记注入、崩溃重试、并发、最终重算不得覆盖已验收凭据 |
| 意图与技能 | 咨询不写入、只读不写入、用户要求先预览、普通请求不继承技能默认口径、明确调用保留规则、禁止提前输出成功 |

独立 Oracle 使用脱敏合成数据和预先定义的业务结果，来源聚合可采用 Decimal/缩放整数 SQL；另读最终 OOXML 验证坐标、类型、公式和样式。不能复用被测编译器生成所有预期值。变体须真实改变结果，例如移动列、改变部门顺序、加入边界记录，而不只是改文件名。

发布硬门槛：上述确定性正反测试全通过；未验证产物在所有标准出口都无法作为成功品交付；输入哈希未变化；保护集合通过；同一输入重试稳定；至少一条真实模型到实际下载文件的完整回放通过。自然语言成功率、澄清率、耗时、模型轮次、错误归因和保真率单独记录，不用一次成功外推稳定性。

性能先记录来源扫描、结构识别、查询、编译、写入、重算、验证和模型调用各阶段；按哈希缓存结构，但每次执行验证来源，重算缓存绑定候选和引擎版本。只向模型提供必要结构和摘要，禁止把数十万格全量文本当默认上下文。预算上限通过测试确定并进入配置，不因大文件静默截断验收范围。

Docker 操作必须在仓库根目录通过 `./docker/start-smart.sh`，校验 PROJECT_ROOT 与挂载。DSH 新 Python 进程可能加载源码挂载，但需要在实际沙箱核对模块来源/哈希；缺少挂载的部署必须更新镜像并重建。涉及 Broker/Orchestrator 路由或环境变量的变更重启相应服务，不能假定热更新生效。

先通过可信运行时开关 `DSH_SPREADSHEET_UPDATE_ENABLED` 对测试用户启用，真实回放通过后扩大。关闭开关停止新标准更新运行；已发布不可变文件继续按凭据提供。失败请求返回具体限制，不能回退到无门禁脚本并宣称相同保证。

- [SheetCopilot](https://github.com/BraveGroup/SheetCopilot)：借鉴动作与反馈闭环；采用受限可组合操作，不替换现有执行控制架构。
- [SpreadsheetBench](https://spreadsheetbench.github.io/)、[SpreadsheetBench 2](https://arxiv.org/abs/2606.29955)：借鉴多变体和端到端成品验收；公开分数不作为本项目服务承诺。
- [openpyxl 复制限制](https://openpyxl.readthedocs.io/en/stable/tutorial.html)、[公式说明](https://openpyxl.readthedocs.io/en/stable/simple_formulae.html)：明确复制保真范围及“写公式不等于计算”。
- 本仓库：[技能执行门禁](Personal-Skill-Execution-Gates.md)、[查询能力设计](Spreadsheet-Query-Capabilities-and-E2E-Design_v1.0.md)、[个人技能捕获与复用](Personal-Skill-Capture-and-Reuse-Design_v1.0.md)。
