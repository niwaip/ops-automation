下面我按你要的目标来做两件事：

1.  给你一套\*\*“最小可用”Dockerfile 项目样例\*\*：容器内 **Xvfb + (headed) Chromium + x11vnc + noVNC/websockify**，浏览器端访问 `http://host:6080/vnc.html` 就能看到并操作容器里的 Chrome。
2.  说明**类似的开源方案有哪些**（你可以直接拿来用或借鉴其目录结构/脚本）。

> 说明：noVNC 是 HTML5 VNC 客户端，典型组合就是 Xvfb → VNC → noVNC（websockify 转 WebSocket）。这一模式在很多开源镜像/项目里被广泛使用。 [\[github.com\]](https://github.com/ConSol/docker-headless-vnc-container), [\[github.com\]](https://github.com/novnc/noVNC), [\[gitee.com\]](https://gitee.com/yunfengZH/docker-novnc)

## 1) 最小项目结构（建议这样整理）

    novnc-browser/
    ├─ Dockerfile
    ├─ entrypoint.sh
    ├─ supervisord.conf
    └─ README.md

这种结构的好处是：

*   Dockerfile 只负责装依赖 + 复制配置。
*   启动逻辑集中在 `entrypoint.sh`（可读、可维护）。
*   多进程用 `supervisord` 管（Xvfb、x11vnc、noVNC、Chrome），避免 PID1/后台进程问题。  
    这种“supervisor 管多服务”的方式在不少 noVNC 容器项目里也很常见。 [\[gitee.com\]](https://gitee.com/yunfengZH/docker-novnc), [\[github.com\]](https://github.com/ConSol/docker-headless-vnc-container)

***

## 2) Dockerfile（最小可用样例）

> 说明：这里用 Ubuntu + Chromium（非 headless）+ Xvfb；noVNC/websockify 用 git 拉取（与 noVNC 官方 repo 组合一致）。 [\[github.com\]](https://github.com/novnc/noVNC), [\[github.com\]](https://github.com/ConSol/docker-headless-vnc-container), [\[github.com\]](https://github.com/johnymoo/chrome-novnc-docker)

```dockerfile
FROM ubuntu:22.04

ENV DEBIAN_FRONTEND=noninteractive \
    DISPLAY=:99 \
    SCREEN_WIDTH=1280 \
    SCREEN_HEIGHT=720 \
    SCREEN_DEPTH=24 \
    VNC_PORT=5900 \
    NOVNC_PORT=6080 \
    VNC_PASSWORD=vncpassword \
    CHROME_USER_DATA_DIR=/data/chrome

# 基础依赖 + 图形栈 + VNC + 进程管理 + Chromium
RUN apt-get update && apt-get install -y --no-install-recommends \
    ca-certificates curl wget git \
    xvfb x11vnc \
    supervisor \
    chromium-browser \
    fonts-noto-cjk fonts-wqy-microhei \
    xauth x11-utils \
 && rm -rf /var/lib/apt/lists/*

# noVNC + websockify
WORKDIR /opt
RUN git clone https://github.com/novnc/noVNC.git /opt/novnc \
 && git clone https://github.com/novnc/websockify.git /opt/websockify \
 && ln -sf /opt/novnc/vnc.html /opt/novnc/index.html \
 && chmod +x /opt/novnc/utils/novnc_proxy

# 持久化目录（浏览器 profile / 下载等）
RUN mkdir -p /data/chrome /data/downloads /var/log/supervisor

COPY supervisord.conf /etc/supervisor/conf.d/supervisord.conf
COPY entrypoint.sh /entrypoint.sh
RUN chmod +x /entrypoint.sh

EXPOSE 6080 5900

ENTRYPOINT ["/entrypoint.sh"]
```

> 备注：如果你希望直接用一个“已集成好的基础镜像”来减少工作量，也可以考虑用 `jlesage/docker-baseimage-gui` 这类 base image（里面已经集成了 noVNC/NGINX/VNC/Openbox 等），你的镜像只要装浏览器/应用并写 `/startapp.sh` 即可。 [\[github.com\]](https://github.com/jlesage/docker-baseimage-gui), [\[1ms.run\]](https://1ms.run/r/jlesage/baseimage-gui), [\[deepwiki.com\]](https://deepwiki.com/jlesage/docker-baseimage-gui/2.4-novnc-web-client)

## 3) supervisord.conf（最小可用样例）

```ini
[supervisord]
nodaemon=true
logfile=/var/log/supervisor/supervisord.log

[program:xvfb]
command=/usr/bin/Xvfb %(ENV_DISPLAY)s -screen 0 %(ENV_SCREEN_WIDTH)sx%(ENV_SCREEN_HEIGHT)sx%(ENV_SCREEN_DEPTH)s -ac +extension RANDR
autorestart=true
priority=10

[program:x11vnc]
command=/usr/bin/x11vnc -display %(ENV_DISPLAY)s -rfbport %(ENV_VNC_PORT)s -forever -shared -passwd %(ENV_VNC_PASSWORD)s
autorestart=true
priority=20

[program:novnc]
command=/opt/novnc/utils/novnc_proxy --listen %(ENV_NOVNC_PORT)s --vnc localhost:%(ENV_VNC_PORT)s --web /opt/novnc
autorestart=true
priority=30

[program:chromium]
command=/usr/bin/chromium-browser --no-sandbox --disable-dev-shm-usage --user-data-dir=%(ENV_CHROME_USER_DATA_DIR)s --start-maximized --disable-features=TranslateUI
environment=DISPLAY="%(ENV_DISPLAY)s",HOME="/data"
autorestart=true
priority=40
```

*   `Xvfb` 提供虚拟显示；
*   `x11vnc` 把 X 显示导出成 VNC；
*   `novnc_proxy`（内部用 websockify）把 VNC 转成 WebSocket+网页；这正是 noVNC 常用启动方式。 [\[github.com\]](https://github.com/novnc/noVNC), [\[gitee.com\]](https://gitee.com/yunfengZH/docker-novnc), [\[blog.csdn.net\]](https://blog.csdn.net/weixin_56291477/article/details/131856950)

## 4) entrypoint.sh（启动前的准备：密码/权限/目录）

```bash
#!/usr/bin/env bash
set -euo pipefail

# 允许外部通过环境变量覆盖
: "${DISPLAY:=:99}"
: "${SCREEN_WIDTH:=1280}"
: "${SCREEN_HEIGHT:=720}"
: "${SCREEN_DEPTH:=24}"
: "${VNC_PORT:=5900}"
: "${NOVNC_PORT:=6080}"
: "${VNC_PASSWORD:=vncpassword}"
: "${CHROME_USER_DATA_DIR:=/data/chrome}"

mkdir -p "${CHROME_USER_DATA_DIR}" /data/downloads

exec /usr/bin/supervisord -c /etc/supervisor/conf.d/supervisord.conf
```

## 5) 构建与运行

```bash
docker build -t novnc-chrome:mini .
docker run -d --name novnc-chrome \
  -p 6080:6080 -p 5900:5900 \
  -e VNC_PASSWORD=ChangeMe \
  -e SCREEN_WIDTH=1366 -e SCREEN_HEIGHT=768 \
  -v $(pwd)/data:/data \
  --shm-size=1g \
  novnc-chrome:mini
```

访问：

*   **浏览器接管**：`http://localhost:6080/vnc.html`（输入 VNC\_PASSWORD）
*   **VNC 客户端**：`localhost:5900`（同密码）

> 注：高分辨率/多标签页时 Chromium 可能对 `/dev/shm` 敏感，`--shm-size` 提升稳定性是常见实践（很多相关镜像/项目都会建议）。 [\[github.com\]](https://github.com/ConSol/docker-headless-vnc-container), [\[github.hjkl01.cn\]](https://github.hjkl01.cn/remote-desktop/docker-headless-vnc-container_consol/), [\[blog.laoda.de\]](https://blog.laoda.de/archives/install-ubuntu-desktop)

# 6) 这种实现方式，有类似的开源方案吗？（有，而且不少）

下面按“与你需求贴合度”给你列几类：

***

## A) 直接就是 “Chrome + Xvfb + noVNC”的开源仓库（最像你要的）

*   **johnymoo/chrome-novnc-docker**：明确是 “Chrome + Xvfb + noVNC Docker”，并提到支持 CDP 端口、Playwright/Selenium。你可以直接参考它的 Dockerfile/compose/脚本拆分方式来整理项目。 [\[github.com\]](https://github.com/johnymoo/chrome-novnc-docker)

***

## B) “通用 headless VNC + noVNC + 浏览器”的成熟项目（适合做基座）

*   **ConSol/docker-headless-vnc-container**：提供一系列镜像（Xfce/IceWM + VNC + noVNC + Chromium/Firefox），并且提供 K8s/OpenShift 的落地方式；非常适合你做企业内部“浏览器执行节点”的通用底座。 [\[github.com\]](https://github.com/ConSol/docker-headless-vnc-container), [\[github.hjkl01.cn\]](https://github.hjkl01.cn/remote-desktop/docker-headless-vnc-container_consol/)

> 它虽然叫 “headless-vnc”，这里的 headless 指“无物理显示器”，但容器里仍然是 **有图形会话**（VNC/noVNC 正常）。 [\[github.com\]](https://github.com/ConSol/docker-headless-vnc-container)

***

## C) “Ubuntu 桌面 + noVNC”的经典镜像（更重，但开箱即用）

*   **dorowu/ubuntu-desktop-lxde-vnc**（以及其衍生 repo）：提供 Ubuntu + LXDE/LXQt + noVNC 的完整桌面环境，适合你在 PoC 阶段快速验证“接管体验”和“浏览器持久化 profile”。 [\[github.com\]](https://github.com/testingkaro/dorowu-desktop), [\[1ms.run\]](https://1ms.run/r/dorowu/ubuntu-desktop-lxde-vnc)

## D) “把 noVNC 做成基础镜像”的方案（你只装应用/浏览器）

*   **jlesage/docker-baseimage-gui**：这是一个专门为了“在 headless server 上跑 GUI 应用，并通过浏览器访问 GUI”设计的 base image，内置 noVNC/NGINX/VNC/Openbox 等，适合你快速构建“可接管的浏览器容器”。 [\[github.com\]](https://github.com/jlesage/docker-baseimage-gui), [\[1ms.run\]](https://1ms.run/r/jlesage/baseimage-gui), [\[deepwiki.com\]](https://deepwiki.com/jlesage/docker-baseimage-gui/2.4-novnc-web-client)

***

## E) noVNC 组件本体（你想自己拼装时必用）

*   **novnc/noVNC**：noVNC 的官方仓库，你在 Dockerfile 里 git clone 的就是它；websockify 也是同组织常用搭配。 [\[github.com\]](https://github.com/novnc/noVNC), [\[github.com\]](https://github.com/novnc/noVNC)

# 7) 额外建议：你更关注“权限控制（只控制浏览器）”，这个方案要怎么做？

noVNC 只是“画面 + 输入通道”，真正的权限控制需要你外面再加一层 **Control Plane**（这正好符合你前面“模板回放 + 人工接手”的架构）：

### 推荐的最小权限策略（落地可做）

1.  **接管令牌**：noVNC URL 必须携带一次性 token（网关验证后再放行）。
2.  **只读模式**：网关可按策略把会话置为 view-only（可观看不可点击）；ConSol 那类镜像常见提供 view-only 开关思路，你也可在网关侧实现“丢弃输入事件”。 [\[github.hjkl01.cn\]](https://github.hjkl01.cn/remote-desktop/docker-headless-vnc-container_consol/), [\[github.com\]](https://github.com/ConSol/docker-headless-vnc-container)
3.  **域名白名单/网络隔离**：容器网络层做 egress 控制（只允许访问指定域名/网段）。
4.  **浏览器级策略**：Chrome policy / 扩展强制安装（例如禁下载、禁密码保存等）。
5.  **审计**：录制 VNC 会话（或结合 Playwright trace/rrweb），用于事后追踪。 [\[playwright.dev\]](https://playwright.dev/docs/trace-viewer), [\[github.com\]](https://github.com/rrweb-io/rrweb)

***

# 8) 你下一步我建议怎么走（不需要你再反复试错）

你现在有两条清晰路线：

### 路线 1：完全自研最小镜像（就是我上面这个）

*   优点：最小、最可控、最容易与“模板回放引擎”耦合
*   缺点：你要自己维护浏览器/依赖/安全补丁

### 路线 2：基于成熟基座二次封装（更推荐给企业）

*   用 **ConSol/docker-headless-vnc-container** 或 **jlesage/baseimage-gui** 做底座
*   你只需要加：
    *   Chrome profile 持久化策略
    *   你自己的接管网关/鉴权
    *   你的回放引擎（Playwright/CDP）

这类“基座镜像”路线在企业里维护成本更低。 [\[github.com\]](https://github.com/ConSol/docker-headless-vnc-container), [\[github.com\]](https://github.com/jlesage/docker-baseimage-gui)
