# 个人核算技能的匹配、执行与语义验收

2026-10-22。当前接入对象为个人沙箱中的 `execution_mode: verified_workflow` 表格核算技能。普通说明型技能和其他执行引擎没有因此自动获得同等验收保证。

## 执行约定

技能检索和亲和度匹配只产生候选。候选的默认业务规则不能自动成为当前请求的业务口径。用户明确调用或延续技能时，以已保存规则生成查询模板；普通相似问题只取得其能力参考，不把未选中技能的命令性正文加载为执行规则。

标准流程：候选发现 → LLM 适用性与请求解析 → 程序校验执行计划 → 确定性执行 → LLM 独立验收 → 绑定证据呈现。验收不通过时，反馈缺项重新规划、执行和验收，最多两个计划；仍不通过则返回具体缺口或说明未完成，不能用旧结果作为成功兜底。

“只要表格”“无需解读”和关闭 insights 只关闭额外解读，不能关闭执行前与执行后的语义门禁。聊天中的模型沿用本轮指定模型；直接调用独立计算脚本仍可无模型运行，但它只验证已保存流程的计算，不证明满足新的自然语言请求。

## LLM 与程序的边界

| 阶段 | LLM 负责 | 程序负责 |
|---|---|---|
| 候选准入 | 理解本轮要求、判断适用性、识别歧义 | 包摘要、当前输入范围和权限；不把相似度当成适用性结论 |
| 制定计划 | 提交 query / clarify / fallback，并逐项引用用户原话 | 校验类型、引用、JSON Pointer 绑定、真实字段与数据范围 |
| 执行 | 不执行任意生成代码、不口算金额 | 复用受限查询 IR，按 WHERE → GROUP BY → HAVING → ORDER BY → LIMIT 执行 |
| 完成验收 | 从原始请求重新检查遗漏、额外限制、单位与交付 | 验收引用本轮证据且覆盖全部要求；来源和回执完整性不可由模型豁免 |
| 呈现 | 选择已验证事实的解读重点 | 表格、数字、条件和来源绑定程序回执；不流出未经验收的结果 |

门禁使用无副作用的结构化决策函数，不把自由文本当作执行权限。无效响应、截断、模型不可用、未覆盖要求和未知证据 ID 均不能产生完成标记。查询条件必须出现在实际计划与回执中，不能仅在说明里提及。

固定技能规则生成当前附件的 `saved_query_template`。模型完整复用该模板时，运行时可直接复用已验证的固定引擎；追加条件或调整口径时采用临时查询，保持技能包与历史版本不变。临时条件需要永久保存时仍须走显式技能更新与保存时重放验收。

## 审核输入与结果

规划输入包含原始请求、有限的用户历史、候选能力及附件结构。历史助手答案不构成业务规则确认。未明确调用的候选只提供能力描述，默认筛选不进入规划或独立验收的命令性上下文。

每项要求保存 `id`、用户原话 `quote` 与查询节点 `target`。验收输入为原始请求、有效计划、实际回执和来源，输出 `accept / revise / clarify`、当前 `evidence_id`、已覆盖要求 ID 和简短缺项。验收不能把额外的排版偏好或附件里的无关列变成必做事项。

成功不仅要求算术校验通过，也要求本轮语义验收 accept。失败尝试保留在本地执行档案中，状态为 partial 或 error；本轮成功引用只包含最终通过的回执。最终呈现前检查附件摘要与回执摘要，变更时撤销完成状态。不能在语义验收之前流式展示“已完成”。

当前适配器只处理预检定位的当前单一 XLSX/XLSM 业务表。其他表结构、交付类型或不支持的查询可以返回通用分析执行路径；需用户补充信息时直接提出确切问题。通用分析继续使用其既有证据门禁，本适配器不为该路径额外背书。

## 回归验收

使用合成数据验证：隐式匹配不继承排除规则、明确技能调用保留规则并追加阈值、按分组总额筛选而非单行金额、严格大于的相等边界、单位换算、没有命中部门、语义拒绝后的重新规划、重复失败、引用伪造、要求漏项、模型超时、来源变化，以及仅表格模式仍执行语义门禁。真实服务回放另核对查询、回执、模型调用数与最后结果；用户业务数据不放入公开代码或 CI fixture。

本设计参考本地 `skill-creator` 的意图与范围保持、精确发现、渐进披露、脚本复用和行为验证原则。模型审核仍有误判可能；该流程通过受限计划、独立审核、完整性校验、有限修复和失败不报成功来控制影响，不能将其描述为数学证明。
