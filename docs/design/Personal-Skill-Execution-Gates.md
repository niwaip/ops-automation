# 技能通用准入与领域执行验收

2026-10-23。公共准入已覆盖个人沙箱 `dsh run` 的所有候选技能，包括内置技能、个人技能和后续安装的新技能。业务计算、文件交付等结果校验由各领域执行器负责；共享准入不等于所有业务场景都已获得相同的结果验收保证，也不覆盖其他服务绕过该入口的执行路径。

## 公共准入契约

先从用户原话独立提取任务契约，再让候选技能接受这份契约的约束：

`候选检索 → 独立任务契约 → LLM技能准入 → 执行器绑定 → 领域证据验收 → 呈现`

任务解析经过独立LLM复核后才锁定契约，复核重新核对原话、否定限制、交付与调用意图，修正初稿遗漏或扩张。两次响应均接受结构和来源校验。任务解析只接收可调用名称目录以识别调用对象，不加载技能正文、默认业务规则或默认交付格式，记录任务模式、对话/文件交付、明确要求及其用户原话。候选审核不能修改这些字段。读取附件与交付同格式文件分别处理；仅解释技能的 consult 模式不会启动其专用执行器。

调用意图也由此阶段做语义分类，区分完整执行、方法参考、没有指定技能及是否明确替换原口径。它理解否定和讨论，不用“名称出现在文本中”作为执行依据。用户要求完整执行且未改写口径时，不能在后续准入悄悄降级成“只借方法”；追加结果筛选不自动取消原有口径。对应检查对所有目录元信息使用同一协议，不包含具体技能名称。

所有技能使用相同的 `use / general / clarify` 准入协议。可以采用候选、换用目录中的其他候选、放弃技能通用规划，或对目标歧义提出澄清。换用技能时必须先读取新候选正文并再次审核，不能直接执行未审候选。提到技能名、Slash、检索分数与输入格式均不绕过该协议。

默认业务规则仅能由明确的整项技能调用授权；未指定技能时，即使规则部分相同，也根据本轮原话制定计划。是否沿用规则由结构化准入结论及用户依据决定，领域模块不得通过查找技能名来重新判断。未接受默认规则时不注入命令性正文。新技能只需提供目录元信息和实际内容，不需要在公共门禁中添加名字、部门、阈值或文件格式分支。

结构错误最多复核一次。已可靠取得任务契约、但技能准入失败时，可清除候选身份、技能内容与专用标志，保留原目标转入通用规划；不能保留被拒技能的生成标志或额外规则。如果任务意图本身无法确认，停止执行。非空澄清问题不能被静默删掉后继续。

工具可用性来自输入资源、用户授权和运行时能力，不取决于必须匹配某个技能。例如拒绝业务统计技能后，实际表格输入仍可绑定只读分析能力；拒绝技能不会扩大修改、发送或审批权限。准入失败也不会自动重放已有外部副作用。

## 执行约定

技能检索和亲和度匹配只产生候选。候选的默认业务规则不能自动成为当前请求的业务口径。表格适配器读取共享准入中的 `use_default_rules`，不再用是否出现技能名推断口径；接受规则时生成当前附件查询模板，否则只取得能力参考。

标准流程：候选发现 → LLM 适用性与请求解析 → 程序校验执行计划 → 确定性执行 → LLM 独立验收 → 绑定证据呈现。验收不通过时，反馈缺项重新规划、执行和验收，最多两个计划；仍不通过则返回具体缺口或说明未完成，不能用旧结果作为成功兜底。

“只要表格”“无需解读”和关闭 insights 只关闭额外解读，不能关闭执行前与执行后的语义门禁。聊天中的模型沿用本轮指定模型；直接调用独立计算脚本仍可无模型运行，但它只验证已保存流程的计算，不证明满足新的自然语言请求。

## LLM 与程序的边界

| 阶段 | LLM 负责 | 程序负责 |
|---|---|---|
| 候选准入 | 理解本轮要求、判断适用性、识别歧义 | 包摘要、当前输入范围和权限；不把相似度当成适用性结论 |
| 制定计划 | 提交 query / clarify / fallback，并逐项引用用户原话 | 校验类型、引用、JSON Pointer 绑定、真实字段与数据范围 |
| 执行 | 不执行任意生成代码、不口算金额 | 复用受限查询 IR，按 WHERE → GROUP BY → HAVING → ORDER BY → LIMIT 执行 |
| 完成验收 | 从原始请求重新检查遗漏、额外限制、单位与交付 | 验收引用本轮证据且覆盖全部要求；来源和回执完整性不可由模型豁免 |
| 呈现 | 选择已验证事实的解读重点 | 表格、数字、条件和来源绑定程序回执；不流出未经验收的结果 |

门禁使用无副作用的结构化决策函数，不把自由文本当作执行权限。无效响应、截断、模型不可用、未覆盖要求和未知证据 ID 均不能产生完成标记。查询条件必须出现在实际计划与回执中，不能仅在说明里提及。

固定技能规则生成当前附件的 `saved_query_template`。模型完整复用该模板时，运行时可直接复用已验证的固定引擎；追加条件或调整口径时采用临时查询，保持技能包与历史版本不变。临时条件需要永久保存时仍须走显式技能更新与保存时重放验收。

## 审核输入与结果

规划输入包含原始请求、有限的用户历史、共享准入契约及附件结构。历史助手答案不构成业务规则确认。未接受默认规则的候选只提供能力描述，默认筛选不进入规划或独立验收的命令性上下文。

每项要求保存 `id`、用户原话 `quote` 与查询节点 `target`。验收输入为原始请求、有效计划、实际回执和来源，输出 `accept / revise / clarify`、当前 `evidence_id`、已覆盖要求 ID 和简短缺项。验收不能把额外的排版偏好或附件里的无关列变成必做事项。

成功不仅要求算术校验通过，也要求本轮语义验收 accept。失败尝试保留在本地执行档案中，状态为 partial 或 error；本轮成功引用只包含最终通过的回执。最终呈现前检查附件摘要与回执摘要，变更时撤销完成状态。不能在语义验收之前流式展示“已完成”。

当前适配器只处理预检定位的当前单一 XLSX/XLSM 业务表。其他表结构、交付类型或不支持的查询可以返回通用分析执行路径；需用户补充信息时直接提出确切问题。通用分析继续使用其既有证据门禁，本适配器不为该路径额外背书。

## 回归验收

公共层额外验证：独立意图提取不含技能默认交付信息、候选不能改写任务契约、未知新技能无新增代码即可准入、替换候选必须再读正文、默认规则不相容时通用规划、讨论技能不触发执行、真实问题不能被删掉、失败降级不遗留技能身份或丢失只读工具。

使用合成数据验证：隐式匹配不继承排除规则、明确技能调用保留规则并追加阈值、按分组总额筛选而非单行金额、严格大于的相等边界、单位换算、没有命中部门、语义拒绝后的重新规划、重复失败、引用伪造、要求漏项、模型超时、来源变化，以及仅表格模式仍执行语义门禁。真实服务回放另核对查询、回执、模型调用数与最后结果；用户业务数据不放入公开代码或 CI fixture。

本设计参考本地 `skill-creator` 的意图与范围保持、精确发现、渐进披露、脚本复用和行为验证原则。模型审核仍有误判可能；该流程通过受限计划、独立审核、完整性校验、有限修复和失败不报成功来控制影响，不能将其描述为数学证明。
