# 原生 XLSX 整本翻译

明确目标语言的单文件 XLSX 整本翻译，在技能准入后由 `xlsx_translation_turn.py` 执行。它跳过自由规划及工具选择循环；部分工作表、计算、多文件、外部发送等请求沿用普通路由。

简短的“重新生成”“重试生成”“继续”由 `xlsx_translation_routing.py` 恢复上下文：要求本轮经过意图复核，属于执行文件交付的 followup，最近一项实际用户任务是明确目标语言的整本翻译。只跳过连续的简短重试消息，不越过更新的其他任务；保留此前的范围限制和明确技能选择。意图复核可能只引用“重新生成”，也可能同时引用原任务，两种结构都须支持。通用路由本身不应使已经确认的翻译任务落回自由工具循环。

## 执行与缓存

- 默认每批最多 50 项、约 4,500 JSON 字符，并发 4。单条超长文本会独占一个批次。
- 模型流不完整、输出截断、缺键、空值或改动网址时不能视为成功。传输故障有限重试；已完成批次保留检查点。
- 运行目录：用户工作区的 `.dsh/xlsx-jobs/<run-id>/`，保存 manifest、译文字典、原生包及 QA。
- 复用缓存：`.dsh/xlsx-cache/<binding-hash>.json`，`xlsx-cache/5` 绑定会话 ID、原件 SHA256、目标语言与逻辑模型名。当前不绑定代理解析后的实际模型版本。只在同一会话内复用；不同会话即使原件相同也重新翻译。无会话 ID 时使用单次运行作用域，不回退到全局缓存。旧版本缓存不自动迁移，避免复用旧前缀策略或未经模型复核的译文。缓存复用耗时不能作为冷启动性能。
- CLI 备用流程继承运行时的 `DSH_SESSION_ID`，文本检查点 `xlsx-text-cache/6` 同时校验会话、输入文本哈希、语言、逻辑模型名与保护前缀指纹；运行时恢复缓存和批次层使用同一套前缀绑定。无标识时不读取已有检查点。
- “重新生成”会重建候选文件并重新验收，可复用已完成译文；这与让模型重新翻译全文不同。当前没有单独的强制清空译文缓存产品入口，不能把重新打包宣传成全文重译。
- 翻译子请求直接进入父级遥测；没有 usage 的失败请求会使 token 统计保持不完整。
- 上游 SSE 中断属于流传输错误，仅有限重试，不按译文 JSON 错误递归拆批。完整但缺键/截断的译文仍按内容错误处理。
- 网址逐字保留校验排除包裹引号和句尾多余括号，保留 URL 路径内配对括号；不能用 `https?://\S+` 将外层句子标点算作链接。
- `session_context` 记录本会话加载的历史条数，`xlsx_cache_scope` 及 manifest 记录缓存作用域、命中状态和读入条数；翻译 `model_started` 记录输入条数、角色和请求内容指纹，不记录 API 密钥。
- manifest 的 `active_stage`、完整异常链和 `progress` 区分翻译请求失败与结构验收失败。失败回复必须说明原因、有效完成/总数、剩余量和下一步；传输故障提示在原会话回复“继续”，权限或结构问题先提示修复对应问题，不承诺自动恢复。
- 缓存条目数不是已完成数量。中文翻译中仍含未翻译日文的缓存会重新进入待处理项，不计入有效完成/复用数量；新的进度统计从实际输入与检查点计算。
- 批次与进度共用前缀拆分后的正文口径。固定工作流对每批候选译文执行基于当前原文、候选译文和目标语言的模型复核；按语境区分普通外文残留与合法名称、品牌、代码和术语，不根据词长或大小写直接拒绝，也不维护具体词的黑白名单。模型复核只输出同键完整译文，仍受键覆盖、非空值和 URL 保留检查约束。复核失败有限重试后停止，候选译文不能写入检查点。
- 复核请求记录为 `xlsx_translation_review` 并纳入耗时、tokens 和失败账本。各工作线程内部执行“翻译→复核”，保留批次间并发。冷启动每批会增加一次模型复核请求；质量收益与实际延迟需分别衡量，不能沿用旧流程耗时。

## 内容与保真

覆盖共享和内联文本、富文本段、工作表名称、下拉选项、可编辑图形/批注、公式文本常量和文本型公式缓存。图片内文字保持原样。

默认不通过 LibreOffice 重写工作簿；保留原有数值缓存及原生部件，设置 Excel 打开时重算。不能把原生包校验、成功退出码或旧缓存当作 Excel 原生计算验证。

候选文件经过翻译覆盖和结构校验后才原子发布。校验包括样式、图片、部件、坐标、行列尺寸、合并、冻结、下拉、条件格式、富文本以及公式引用。失败不能覆盖原件或旧交付。

`xlsx-quality/3` 增加输出实体回读，按映射检查共享字符串、富文本段、内联文字、表名、下拉选项、图形与批注文本是否匹配已验收译文，并记录 `text_readback_verified=true`。评分代码仅在标签边界受保护，保留 C＊/N＊ 中的星号；C-D 列范围及自然语言整句提交模型，不拆除句首字母。

发布 manifest 写入异常时撤回本次替换并恢复旧成品；辅助缓存写入失败仅记录警告，不把已发布任务改报失败。此回滚处理可捕获的异常，不承诺进程被强制终止时具备跨文件事务恢复能力。成功后记录 `workbook_delivery=accept`，通用 evidence 与发布状态一致。完成答复仅说明实际验收范围，不再无条件声称处理图形或完成语义、视觉复核。

固定工作流在模型复核与结构回读均通过后记录 `semantic_reviewed=true, semantic_review_method=model_batch`，这表示执行过模型复核，不保证全文准确，也不代表人工校对或视觉验收。单独调用结构校验函数仍不宣称做过语义复核。现有固定路由只识别中/英/日等已声明语言表达；通用复核没有文档专用特判，不等于入口已支持任意语言。既有假名残留和频率识别属于覆盖有限的语言启发检查，不能据此声称完整语义正确。

图形和批注按原始 XML 文字节点替换，避免重新序列化图形对象引起渲染兼容性问题。结构检查之外仍需对关键图形和长文本做视觉抽查。

翻译提示词使用当前文档的术语语境，不固定假设 IT、安全、财务或其他行业。固定批大小、字符预算和并发是运行参数；不能把文件名、原件专有术语、用户 ID 或某次文本总数写进通用执行逻辑。

## 验证

在仓库根目录使用本地 Python 运行 `test_xlsx_translation_*.py`，另运行既有 `TestOfficeSandbox.test_ooxml_xlsx_translate_unpack_and_pack`。实际执行后核对本轮 manifest 的 `state=published`、QA 的输入/输出哈希与真实文件。

源码为每次新 Python 进程加载；共享技能脚本需要同步到 `data/shared/dsh-skills/xlsx/scripts/` 并核对哈希。若更改容器配置、镜像或后端服务入口，仍按根级 AGENTS.md 通过 `./docker/start-smart.sh` 重启验证。
