# 文档读取与视觉能力

个人沙箱的普通附件问答默认使用原生文本读取。联网许可不代表已联网；只有明确的外部搜索任务才执行检索。“查看/归纳附件”不启用搜索；“归纳附件，并联网搜索最新动态”可同时保持只读和搜索意图。工具隔离使用结构化附件列表，兼容旧请求中的附件包装标记。

## 视觉启用

- 图片附件保留视觉能力。
- PDF 在本地探测页面文字和图片实际占据的区域，默认不开启 `vision_inspect`。
- 最多均匀抽样16页；超过4页的文档排除首尾封面，避免单张封面和Logo触发整份文档视觉读取。
- 抽样页中至少一半的图片覆盖率达到50%，判为图片占比高的PDF。
- 抽样页中至少一半的图片覆盖率达到65%、可提取文字少于120字符，判为扫描PDF。
- 带OCR文字层的整页图片PDF仍可因图片覆盖率启用视觉，不仅按“能否提取文字”判断。
- 用户明确要求OCR、图表识别或版式分析时，可开放视觉；明确禁止OCR/视觉时关闭。
- 解析失败记录为unknown，不因失败自动发送到视觉模型。文字型PDF不因截断、文件名或技能名称自动开启视觉。

这是抽样启用策略，不是逐页图表质量或语义完整性验收。全文原生提取还会记录每一页的状态；发现预检未覆盖的纯图/扫描页后，会保留未读取页码并更新视觉资格。不会因为文字未截断而宣称这些页已读完。普通文字与少量插图仍不自动触发视觉调用；明确禁止视觉/OCR时不发送图片。

`visual_reading_policy.py`负责探测和工具过滤；`file_tools.inspect_image`在发送PDF图片前再次检查。模型自己在工具参数里写“OCR”不能覆盖原始用户请求。已有PDF生成流程的`inspect_pdf_page`验收工具保持独立。

视觉PDF单次最多4页。显式范围超限时拒绝，不静默截去后续页面；`all`仅代表开头最多4页，回执给出实际页码及后续范围。实际提供页码同时注入视觉请求，避免大范围提示与四页图片不一致。

## 长文档读取

初始附件按附件预算构造正文、章节索引、真实行号和续读提示。工具调用期间通过`document_reading_budget.py`将工具回包预算传入提取器，避免尾部索引/续读提示被第二次截断。长文档按抽样文字量估计分段轮次，范围3–12轮；短任务保持3轮。预算不是全文覆盖证明，回答仍需依据已读内容披露范围。

普通文档只读循环使用最多12轮的文档上限，并受配置的通用执行上限约束；不再套用默认8轮的表格计算上限。表格分析保留其独立预算。

## PDF 原生读取接口与覆盖契约

`read_file` 的 PDF 路径为 `tools.execute_tool → file_tools.read_workspace_file → office_tools.extract_pdf_text → pdf_reading.read_pdf`。初始附件预读取复用同一入口，读取本身不调用模型或网络。

- 全文读取：`read_file(file_path="report.pdf")`。长文档根据回执里的全文件行号，用 `start_line/end_line` 续读。
- 按页读取：`read_file(file_path="report.pdf", start_page=4, end_page=5)`。页码从1开始且含结束页；仅传 `start_page=4` 表示第4页，返回保留物理页码。冷缓存下只提取请求页的文字。
- 单页区域：`read_file(file_path="report.pdf", start_page=4, bbox=[x0, top, x1, bottom])`。坐标为PDF点、左上为原点，正文的页面/区域标注提供坐标；必须指定单页，坐标越界或非有限值会报参数错误。
- 页码/区域与行号不得混用。无效页码、行号或区域不静默回退成第一页或全文。页码参数仅适用于PDF。

`pdf_page_layout.py` 根据文字坐标识别重复栏间空隙，能够分离的双栏按区域输出，保留边界；表格状、三栏及其他不确定结构保留空间排布并标记复核，不将其强行改成两栏。几何划分是阅读辅助，不是表格/图表的语义解析证明。

`pdf_text_cache.py` 管理逐页提取与缓存。物理页码始终保留，包括空白页、未读取的图像页和解析失败页；单页失败只对该页尝试后备提取，不能丢弃其他页已成功提取的文字与布局。缓存版本为 `pdfplumber-layout-v2`，旧平铺缓存不复用；写盘使用原子替换，不把带解析失败页的结果存为可长期复用的成功缓存。不读取来源不明的同名TXT文件冒充PDF提取结果。

读取返回兼容字符串的结构化 `TextToolOutput`，其中：

- `coverage_scope=native_text`：覆盖仅指原生文字层，不代表图像或事实已经验证。
- `text_complete`：本次完整展示整份文档的可读取原生内容，没有截断或未读取页。局部页、区域、行号切片不能冒充全文完整。
- `page_coverage_complete` / `selection_coverage_complete`：分别表示提取阶段对整份文档或选择范围的原生读取覆盖；即使提取完整，本次显示仍可能截断，需同时查看`text_truncated/text_complete`。
- `unread_pages` / `visual_pages`：失败或图像未读取页、可定点视觉复核页；`layout_status/layout_pages` 表示复杂版面及页码。
- `fact_verified=false`：提取成功不能被当成事实校验通过。

**PDF的`read_file`始终保留**，完整文字注入不再删除按页/区域复核能力。无需为了保留能力强制重复读全文。上下文组装通过独立的`attachment_text_complete`字段接受覆盖证据，不再根据工具数量推断正文是否完整。

初始预读取的`pdf_reading`门禁记录包含源SHA-256、页数、覆盖范围、截断、未读取页、版面状态及实际注入字符数，即使模型没有调用工具也能审计。它不代替摘要质量或语义正确性验收。

## 只读与 PDF 交付边界

`is_inspect_intent=true` 且 `is_generate_intent=false` 时，最终导出器与外部PDF验收器均不得创建交付文件或替换归纳正文。技能选择为`pdf`只表示处理PDF资料，不等于请求生成PDF。

旧导出路径必须通过`pdf_output_contract.requests_pdf_output`确认PDF输出契约或明确的输出动作；提示中出现`pdf`、上传附件名称包含`.pdf`均不构成生成授权。直接调用Markdown转PDF的兼容入口也使用相同规则。

PDF页数约束在移除附件包装和文件名后解析，避免把`85页_资料.pdf`或`共85页_资料.pdf`中的数字当成输出要求。用户指令中单独写明的`共3页`、`2至4页`等仍生效。实际生成请求继续通过原有PDF验收，普通归纳不会收到“扩写内容并重新生成”的交付失败提示。

## 异常与验证

超时提示描述已知失败阶段，不根据“查看”推断联网，更不在没有回执时声明检索完成、文件不存在或检查点可续跑。附件视觉阶段超时使用`SANDBOX_DOCUMENT_ANALYSIS_TIMEOUT`及`stage=visual_reading`；已有Harness/工具执行证据保留在executionTrace中。

编排服务运行编译后的dist，修改TypeScript后从仓库根目录使用`./docker/start-smart.sh dev restart ai-orchestrator`重建并重启，检查`/health`与编译后分类器。个人沙箱Python源码为只读挂载，每次新DSH进程加载新代码；不要据此推断已运行进程会热更新。
