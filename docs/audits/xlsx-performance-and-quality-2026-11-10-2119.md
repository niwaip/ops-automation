## 4. 已实施的优化

### 固定执行与可恢复翻译

`xlsx_translation_turn.py` 只接管经过准入、目标语言明确、单一 XLSX 输入的整本翻译。局部范围、多文件、发送邮件、计算与其他复合请求保留原路由。它在自由规划之前执行，通过分阶段计时、来源哈希校验和原子发布完成交付。

`xlsx_translation_client.py` 独立承担模型请求：每批最多 50 条、约 4,500 JSON 字符，并发度 4；检查流终止、截断、键完整性、非空字符串和网址完整性。协议问题可以拆批，传输故障有限重试，持续鉴权或网络故障不会扩展成大量递归请求。

`xlsx_translation_batches.py` 负责文本去重、逐批检查点和目标语言验收。失败保留已完成批次，取消尚未开始的排队请求，不能把原文回填后仍标为“成功”。运行时缓存绑定原件 SHA256、语言、模型标识及缓存版本；同一原件已有译文可以复用。

### 覆盖、保真与门禁

- 富文本按原 run 分段翻译，保留颜色、粗体及边界空白；移除过期的日文注音元数据。
- 覆盖共享/内联字符串、工作表名、下拉选项、可编辑图形与批注文本、公式常量，以及公式的文本型显示缓存。最终覆盖 **4,736 个文本单元**；数量包含重复引用和文本缓存，并不等于独立模型翻译次数。
- 同步跨表引用、名称定义、文本判定常量和内部超链接。数值缓存与原有数字不改写；**1,062 个文本型公式缓存**通过译文映射本地化。
- 默认保留原生包和缓存，设置 Excel 打开时重算；停止使用 LibreOffice 重写交付工作簿。
- 发布前检查包部件、图片、样式、坐标、合并、行列尺寸、冻结、下拉、条件格式、富文本样式及公式依赖。候选验收失败不会覆盖旧交付文件。

视觉抽查还发现：中间优化版重新序列化图形 XML 后，有一幅原图在打印预览中消失，尽管包部件及 XML 节点校验通过。改为仅替换原始文字节点、保留图形的其他标记后，同一页配图恢复；新增了原始图形标记保留的回归断言。该证据支持重序列化的渲染兼容性问题，没有进一步假定具体 Office 内部分支。
