# 财务与表格链路中的程序自动业务计算排查

## 排查原则与范围

按本轮明确的边界检查：程序可以发现缺失指标、提供反馈、管理重试、执行AI显式声明的计划与验证来源；新增业务计算应由AI明确调用内置工具，程序不自行生成并启动计算，也不在展示阶段增加没有工具事实的新业务数值。

检查范围为personal-sandbox-runner的财务/表格分析、主循环恢复、展示、总结核验、个人核算技能和产物生成入口。先用知识图谱发现符号和调用，再用当前源码及AST交叉核对直接调用点。未做整个单仓库的全量业务逻辑审计。

结论：除已确认的RegisteredMetricCompletion外，找到**3处同类自动业务计算**，另有**1处派生数值放行漏洞**和**1处正文脚本执行旁路**。个人技能执行有AI明确计划，单独列为执行入口统一问题，不能混称为程序自己决定业务。

本次只排查，新增报告和离线证据，未修改业务源码、重启服务或发起真实模型调用。

## 1. 已知：注册关系补算直接执行

- 调用链：`agent_loop.py:589` → `AnalysisTurn.complete()` → `RegisteredMetricCompletion.complete()` → `calculate_spreadsheet_analysis()`。
- 位置：`registered_metric_completion.py:143–188`、`analysis_turn.py:112–113`。
- 程序根据领域配方与已取事实生成新的calculations，直接执行，再追加工具遥测。该遥测并不证明存在对应的AI工具调用。
- 14:15原调用的D列毛利差额/收入差额就是此处生成。已有审计中的真实回执与离线重放证明该路径实际发生。
- 调整方向：发现缺项后给AI返回缺项及来源信息，继续模型工具轮次；AI显式调用`analyze_spreadsheet`/`aggregate_spreadsheet`提交派生表达式，再经正常工具分发执行。

## 2. 同类：SummaryRecovery自行选范围、构建汇总计划、执行和导出

- 位置：`bounded_summary_recovery.py:20–75,83–100`、`spreadsheet_request.py:93–154`。
- 主循环入口：`agent_loop.py:354`（AI无工具调用时）；`agent_loop.py:584`（工具执行后尚无有效分析事实时）。
- 程序读取附件结构、枚举候选区域、解析自然语言中的字段/筛选/分组，构建sum/count计划并直接调用计算引擎。成功后可调用`export_recovered_summary()`直接生成Excel，然后结束当前循环。
- 这不是只检查或给模型建议，而是接管了规划、计算和交付。其范围虽受“唯一附件、唯一候选区域、generic领域、简单汇总”等约束，仍属于本轮要求排除的行为。
- 最小复现：在临时工作簿中放入甲中心7K、乙中心9K，提示“按中心汇总金额(K)，生成可下载Excel，文件名结果.xlsx”。禁止所有模型请求后，程序仍生成汇总事实和`结果.xlsx`，原件哈希不变。
- 当前规则拒绝财务领域及带明确年份等复杂请求，因此**不能将其认定为14:15那次财务请求的触发原因**。
- 调整方向：恢复器只向AI提供结构候选、未满足要求和可用工具；保留主循环，由AI重新调用工具。导出也使用显式工具调用。

## 3. 同类：展示层直接补“各组总计”，且只按单位相加

- 位置：`report_presentation.py:157–178`。
- 触发：用户文本含“总计/合计”等，visible facts中没有现成总计且存在多个分组事实。
- 程序按unit把各组事实相加，直接插入正文，不生成新的计算计划或结构化事实。没有按指标、期间、实际/预算场景或可加性分别分组。
- 展示层单元复现：40%与60%被写成“各组总计100%”；两组收入1000/2000和净利润100/200，因单位均为千元，被写成一个“各组总计3300千元”，而不是收入3000、净利润300。
- 复现中仅stub了事实选择，让指定visible facts进入真实展示分支；这证明该分支的算法问题，**不冒充全链路会在所有这类请求上必然进入该分支**。纯Query IR可能走另一展示路径。
- 调整方向：总计成为任务所需但尚无回执时，要求AI在工具计划中补充相应聚合；展示层只呈现工具已返回的总计。

## 4. 同类：趋势展示自行选比较期间并计算百分点差

- 位置：`spreadsheet_trends.py:30–45`；入口`spreadsheet_analysis_evidence.py:318–322`。
- 程序在已有期间比率事实中按月份排序，选择后续不重叠期间，直接计算`delta=b-a`，生成“提高/下降N个百分点”。没有对应的派生工具回执。
- 最小复现：两个输入事实为上半年40%、下半年45%；调用展示函数后输出“提高5个百分点”，事实池仍只有原来的两条，没有5个百分点的计算事实。
- 这次数学可以正确；与本轮边界冲突的是程序主动决定比较对象、执行派生并作为核验数据变化输出。
- 调整方向：AI在工具调用中显式声明比较基准与subtract表达式，展示时读取返回事实。

## 5. 相关漏洞：总结数值白名单预计算大量无业务绑定的组合

- 位置：`analysis_synthesis.py:444–625`，特别是`578–613`。
- `_collect_allowed_numbers()`预先计算事实总和、占比、累计占比、事实除以记录数，以及事实两两之间的加减除、增长率等，加入允许数值集合。组合没有同时绑定业务名称、期间、主体、场景和表达式。
- 因此模型可以不调用财务工具，直接在正文增加一个碰巧落在组合白名单里的数值，数值核验依然通过。
- 最小复现使用14:15原始第一份回执：只有12项金额事实，没有任何百分比事实。候选正文列出原金额并附“全年毛利率85.65%”，`_is_synthesis_grounded()`仍返回true，因为D6/D4属于自动枚举的数值组合。
- 这是**总结核验入口的实测结果**；整轮任务另有完整性门禁，不能据此声称没有毛利率回执时整轮也一定成功。
- 调整方向：新增业务数值必须引用实际工具事实或AI显式提交、已经执行的表达式；核验其指标/数值/单位/期间/场景绑定。格式化与展示舍入可以继续确定性执行。

## 6. 执行旁路：正文Python脚本被自动执行

- 位置：`agent_loop_helpers.py:700–720` → `deliverable_contract.py:243–308`。
- 任务期望docx/xlsx/pdf产物时，程序会从模型回复正文提取Python代码块，通过`subprocess.run()`直接运行，并在历史中追加“bash”，无需AI实际发出bash工具调用。
- 业务脚本内容来自模型，因此与“程序自己发明财务计算”有区别；但按本轮“AI重新调用内置工具”的要求，它仍是需要收口的执行路径。若脚本内部包含财务计算，还会绕开财务工具的显式调用记录。
- 本次只检查源码，没有执行正文脚本。调整方向：将未执行脚本反馈给AI，要求通过相应工具显式调用；若保留受控脚本工具，也应统一分发、参数、回执和调用关联。

## 7. 有AI计划的路径与正常工具内部计算

个人核算技能：`personal_skill_workflow.py:85–104`先调用`plan_candidate()`取得AI生成的结构化query，再由`execute_proposal()`执行，随后AI独立验收。它没有像注册补算那样自行新增业务表达式，但绕过了主循环的普通财务工具分发入口，并由外层程序记录工具名称。若统一要求财务计算走一个分发入口，可将其执行适配到同一工具层，保持AI已经明确的计划。

普通工具分发`tools.py:522–524`、更新聚合`spreadsheet_update/aggregation_api.py:77–84`执行的是AI传入的参数。查询编译、表达式求值、来源哈希、工作簿已有公式重算和数值格式化属于执行已有计划或校验，不属于本次发现的程序主动新增业务任务。

检索答案恢复`retrieval_answer_recovery.py`会再次调用模型，仅综合已有回执且`tools=None`，未发现它自行发起财务工具计算。

## 8. 建议统一执行链路

```text
发现缺项/计划失败
  → 返回缺项、失败位置、来源证据及工具Schema给AI
  → AI明确生成新的财务工具调用
  → 统一dispatcher执行
  → 返回带调用ID、来源、表达式、数值及口径的回执
  → 核对任务覆盖与事实
  → AI组织回答，展示层只格式化已有事实
```

程序可以扩展有限修复轮次、选择错误反馈并在预算不足时如实终止；不通过自动汇总、展示层补算或宽泛数值组合来替代缺失的AI工具调用。
