## 4. 工程与模型归因

| 发现 | 归因与证据 |
| --- | --- |
| Bold 字体文件不存在 | 当前资产只提供 Regular；初版模型直接使用 Bold，未实施技能所写的“若不存在则回退常规体”。主要为模型执行遗漏，技能的可选路径提示也容易诱导无条件使用 |
| 三次整段生成脚本 | 模型选用手写 FPDF、出错后重写，随后又因页数返工；技能已有首选标准生成器，本任务无必须精确坐标排版的证据 |
| 简单文档规划 34.539 秒 | 工程编排要求“深入思考”“清晰详尽的规划”，与“不要太复杂”的任务规模不匹配；模型输出量也偏大 |
| 4 次 aborted 重试 | 上游/代理传输或执行中断，归为工程链路可靠性问题；日志不足以进一步区分网络、提供商或超时触发源 |
| 个人信息、荣誉与页面概览问题 | 模型内容与最终校验遗漏；工程侧未验证来源标注与最终摘要一致性 |

## 5. 改进优先级

1. **先补交付质量**：最终 PDF 生成后读取最终页数、逐页标题与正文摘要，再生成聊天概览；禁止在之后重写文件却沿用旧摘要。新增独立 PDF 检查模块，检查可解析、页数范围、空白页、文本异常，并对最终版渲染验收。不要继续往现有大 agent_loop 文件堆逻辑。
2. **个人材料默认占位**：姓名、班级、岗位使用占位符；荣誉限制为两到三条待填写项，或在 PDF 内醒目标注示例。三页即可覆盖本次需求，第四页仅在确有展示需要时保留。
3. **减少模型生成量**：将简单文档分流至短规划/直接模板生成；用已验证的固定分页模板渲染结构化内容，字体路径由代码解析并回退；出错优先局部修复。先消除本轮的完整重写，再测端到端改善。
4. **定位文本兼容性**：固定相同内容，分别对字体格式、FPDF 版本和标准生成器做小规模对照；至少用目标消费端解析器验证。当前不宜直接归咎于某一个库版本。
5. **补可靠性和取消遥测**：为上游每次尝试记录模型、重试原因、失败耗时与取消信号；取消应终止当前上游请求。重试策略既要恢复能力，也要有整体 deadline，避免重复生成大量脚本。

以上为建议，未实施修复或重跑任务，因此没有优化后耗时承诺。
