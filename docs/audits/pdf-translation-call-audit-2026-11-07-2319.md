## 10. 第 7 页专项归因（用户确认 balanced 正确后的补充）

**复合问题，修复失败的主因在工程闭环。模型在布局输出与最终复核两处出错；工程将模型的局部错误放大，并让本轮修复缺乏解决实际问题的能力。**

### 10.1 缺陷如何产生：模型冲突输出 + 工程错误消歧

保留的 `layout-p7-1.json` 不是完全没识别脚注：模型把 `p7_g43/p7_g44` 组成第一条 footnote、`p7_g45/p7_g46` 组成第二条 footnote，同时又把 `p7_g43`、`p7_g45` 单独列为 furniture。**同一标号分配两次，违反输入 ID 只能归属一次的要求，属于模型布局错误。**

以审计快照代码和保存的本轮输入离线重放，路径确定如下：

1. `expand_candidates` 对重复候选按几何距离和包围框面积消歧。标号的极小 furniture 包围框胜过包含整条说明的 footnote 框，标号从脚注中剥离。
2. `isolate_margin_lines` 本来有标号合并逻辑，但明确排除 furniture，故没有把两枚标号合回邻近说明。
3. `materialize_page` 后续发现这两枚 furniture 不在极端页边区域，将其转成 paragraph。处理顺序使它们错过前面的脚注合并机会。
4. renderer 按普通段落输出，于是形成两个孤立数字。

这不是 balanced 必然带来的问题。工程应对模型冲突输出重试或按脚注语义/邻接证据恢复归属，不应仅凭更小包围框静默决定。

### 10.2 为什么修复没有解决：三处确定的工程缺陷

**A. 修复动作分错类。** 初审把关系缺陷标为 `kind=translation`，也是模型分类不精确。`triage_review_issues` 对此只产生 `nodes_to_retranslate`，本轮 `pages_to_relayout=[]`。跨节点 quote 无法命中单一文本，兜底把 8 个正文/标题/说明/数字节点一起重译；没有合并标号、绑定脚注或改节点类型的动作。

**B. 问题说明在接口处丢失。** `pdf_repair_loop` 用 `anchor`（“页脚注脚/表格下方文本”）作为 `feedback_map` 的键；`repair_nodes` 却用节点 ID（如 `p7_b10`）读取。两端键不一致，所以本轮初审缺陷说明没有进入修复提示词。离线用 stub gateway 重放得到六个重译请求，全部没有 `Fix these errors:` 内容。这是对代码控制路径的复现，不是取得了历史完整模型 messages。

**C. 真正受影响的数字被跳过，且修复 API 没有结构修改权限。** 虽然 `p7_b11/p7_b12` 在修复目标集合里，但 `needs_translation('1'/'2')` 为 false，代码在判断目标前就原样回填并 continue。实际请求只针对其余六个节点；模型仅能返回 ID → 译文字符串，无法改变标号节点归属和阅读顺序。

因此，即使换更强翻译模型，沿当前修复路径也不能可靠修复这两个孤立标号。v1/v2 HTML diff 已证明实际只改了四处附近措辞，标号节点和结构未变。

### 10.3 为什么最后还能成功：旧 issue 丢失 + 新一轮漏检

v1 同页独立确认曾返回 PASS，但缺少逐项反驳证据，被 `validate_confirmation` 正确挡住。这一层并未强行把 REPAIR 改为 PASS。

漏洞发生在重新渲染后：注册新候选会重建审阅状态；`inspect_pdf_page` 的新提示只做一般页面检查，没有把上一版未关闭的脚注 issue、原位置、修复动作和应满足的条件传给它。新一轮 PASS 不需要逐项证明旧问题已解决。循环只要看不到新的 error 就宣布 success，原有非收敛检查也只在下一轮仍报错时才起作用。

最终第 7 页 receipt 实际返回 PASS，并建议修复“OCR 列 ✓7”的上标；该 OCR 行属于第 5 页表 1，而不是第 7 页表 2，显示模型的定位与证据使用也不可靠。当前 `table_review_evidence` 对最终产物的离线重建，会因共同产品名 Google、DeepL 等误把第 5 页表格注入第 7 页提示。该重建与错页建议一致，但未留存历史完整请求，不能把它断言为漏检的唯一原因。

另外，源译文证据函数过滤长度小于 4 的片段，两枚数字不会进入结构化源译对；几何证据里仍有整页文字，不能说模型完全看不到它们。主问题仍是缺少针对旧 issue 的复核要求和程序验证。

### 10.4 修复方向

- 保持 balanced，不改为机械保页。
- 对重复 ID、标号/furniture 冲突建立明确恢复或重试策略，标号与说明形成关联节点。
- 使用稳定 issue ID 与目标 node ID 传递反馈，保留跨节点范围；关系修复不能退化为普通重译。
- 修复器支持合并/关联/重分类这类结构动作，并检查指定目标是否真的产生相关变化。
- 每个原 issue 持续保留至结构验证或带位置证据的复核确认消失；普通 PASS 不能自动关闭旧 issue。
- 按真实页面位置提供局部证据，避免短词命中引入其他页面表格。

补充证据：`page7-cause-replay.json` 保存布局消歧各阶段、实际 triage 集合、反馈键、stub 捕获的六个提示和数字原样保留；`page7-table-review-reconstruction.txt` 保存当前代码对最终第 7 页的表格证据重建。均未调用生产模型、改动业务源码或覆盖 PDF。
