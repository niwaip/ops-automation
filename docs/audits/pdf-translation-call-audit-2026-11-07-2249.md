## 5. 实物质量：确定问题与责任

### P1：用户的格式约束未落实

证据：原稿 7 页变为 6 页；源第 2 页下半部双栏在成品第 2 页变为单栏；首屏字体和正文密度变化；源三线表重建为带竖线和底色的表格；原第 1 页底部脚注出现在成品第 1 页右栏开头。

### P1：可复制的 Docker 命令被解析损坏

原第 3 页为 `docker pull byaidu/pdf2zh`；成品第 3 页为 `docker pull byaidu / pdf2zh`。跨行的 `docker run -d -p 7860:7860 byaidu/pdf2zh` 同样变成 `... byaidu / pdf2zh`。镜像名被拆成多个 shell 参数，复制后无法按原意执行。这里只核查命令文本，没有运行原文命令。

证据链：原稿完整页图和文字 → `source.ir.json` 的 `p3_b14` / `p4_b1` 已带空格 → 译文完全照抄损坏后的 IR → 成品保留空格。`native_parser.page_lines` 用较小字距抽词后对所有片段执行 `' '.join(...)`，`source_text.join_lines` 又用普通空格接跨行片段。

### P2：普通表格标签漏译，被工程规则当成字面量

成品第 4 页保留 `Open-source`、`Layout1`、`Formula2`、`Bilingual3`。它们应分别表达开源、布局、公式、双语；脚注数字应独立保留。`OCR` 缩写可保留，但不应把含脚注数字的全部词一概当作代码。

离线复现：`translation_validation.is_literal_or_command` 把只含英文字母/数字/点/横线的非纯字母字符串直接视作字面量；以上词的 `needs_translation=false`，照抄也返回验收成功。`text_translator` 因而直接回填原文，不要求模型翻译。`Open source` 改为空格形式才会要求翻译，证明这是词形规则误伤，不能要求模型对未交给它的单元负责。

## 6. 为什么现有门禁仍通过

1. `verify_candidate` 的来源、结构哈希和原生行校验有价值，但原生解析本身引入的空格同样成为“可信原文”；没有命令 token/链接注释对照。
2. 文本覆盖主要比较规范化字符 Counter，能防缺字，无法证明空格、句序、题注归属、脚注位置和链接功能正确。
3. “含连字符/数字即字面量”等启发式把普通标签豁免，完整性检查无法发现自己认定无需翻译的词。
4. 数字保护 token 默认关闭，`validate_value(..., strict_numbers=False)` 默认不校验数值；重试后非空无乱码即可接纳，pipeline 和发布门禁也只阻断缺失/乱码类错误。本轮未查出数值改动，但这种配置不能提供对未来错误的确定性保护。离线构造“250 美元→999 美元”：默认返回通过，strict 模式才拒绝。
5. 最终审阅虽增加原表 cell 关系证据，却没有原始整页图和逐段源文供完整翻译/布局比对；只看成品不能完整判断译文忠实度。
6. 审阅提示多次“严禁”因跨页、留白和原图英文判 REPAIR；合理豁免没有与明确保格式需求充分区分。表 1 标题与表分离也未被识别。六次 PASS 是模型实质漏检，不是本轮代码把 REPAIR 改为 PASS。

## 7. 建议修复顺序与验证条件

1. **P1：以结构化交付约束落实“保持格式”。** 明确源页、单/双栏、字体层级、图表和脚注锚点的可验证目标；保格式模式不能静默降级成通用阅读版，也不能只靠最终页数一致验收。
2. **P1：保护命令、URL 和不可拆分 token。** 从字形/原始文本和链接注释恢复连续性，跨行接续不盲目加空格；最终对照源命令 token，URL 使用完整目标地址。不得通过执行文中任意命令来验证。
3. **P2：按角色判断是否翻译。** 普通文本标签与脚注数字拆分；真实专名/代码采用明确证据，取消把所有带横线/数字词都豁免的宽规则。用不同拼写、含脚注的普通词做泛化验证。
4. **P2：保留文档关系。** 建立表格、题注、说明的显式组；脚注标记绑定脚注正文；保留链接注释，并验收全部可点击目标和关键内外链。
5. **P2：恢复事实保护，改进审阅输入。** 数字/URL/命令用动态提取的源证据核对；区分可允许中文数字或月份转换与真正数值变更，避免用全面放行代替语义校验。视觉审阅引入源页、关键原段和锚点关系，要求对未保留项目作明确结论。
6. **P2：去除样本提示和过度成功声明。** 通用提示中移除本文特定数字/措辞，改为当前块数据；成功话术来自明确完成的验收项。遥测应分离最终 job 状态和历史调用失败，未知 Token 继续明确标注。

验证至少覆盖本样本的六个确定问题，并增加其他版式、字号、命令/URL、表格和脚注的新文档；不能只让这篇样本变好就证明通用能力合格。
