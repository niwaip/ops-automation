## 失败复现与责任归因

原件中的一个句子把链接包在外层括号内，末尾为 `.../guideline/)`。原先使用 `https?://\S+` 提取链接，将句子的 `)` 也纳入“必须逐字保留的 URL”。

修复前真实模型返回保留了完整 `.../guideline/` 链接，但省略外层句子的括号；校验立即报 `Translation changed a source URL`。这不是实际链接被改写。原始调用中的六次 URL 错误沿递归拆分缩小到单条，最终使整批失败，取消尚未执行的其他批次。

另有 11 次 `Upstream stream error`，代理日志包含已输出部分内容后的 `aborted`，以及一次 30 秒超时重试。原客户端把这种连接中断包成通用 TranslationFailure，误入 JSON 格式错误的二分拆批路径。单靠减小文本不能证明可以修复连接故障，这种分类增加了负载。

定性：工程性原因与上游传输故障共同作用。没有证据证明本轮因混入其他会话而失败，也不能将网址误报算作模型翻译错误。

已修复以下问题：

- URL 校验排除外层引号/多余右括号，保留路径内配对括号；真实改写域名仍会被拒绝。
- 上游流错误独立分类，有限重试后停止，不递归拆分；不完整结束的流也不被当成正常 JSON 内容处理。
- 翻译 JSON 改用代理内部缓冲模式，允许代理丢弃失败的部分输出后安全重试，避免向下游混合多次尝试。

模型缓存键当前使用逻辑模型名 `default`，没有绑定解析后的模型版本。会话内若切换默认实际模型，缓存不会仅因模型实际身份改变而自动失效。这不导致跨会话复用，但后续比较模型效果时需要补齐实际模型身份与翻译策略版本绑定。
