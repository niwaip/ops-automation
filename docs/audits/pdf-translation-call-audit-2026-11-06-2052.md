# PDF翻译调用审计：2026-11-06 20:52

## 1. 结论与归因

**本轮是布局语义错误、恢复机制缺口与模型错误操作叠加的业务失败。新版引擎已启用并运行；没有进入最终PDF渲染与逐页视觉验收。最终不外发是正确行为。**

失败链：

1. 首次auto完成7页布局分析，但把第一页作者姓名和机构片段错排、错归为普通段落 `p1_b2`；该块两次翻译校验均未通过，任务在translate阶段结束。
2. 主模型没有修复该块，而是编造 `auto --unpack` 参数，argparse立即拒绝。
3. 改为正确unpack子命令后，它没有获得auto/pack的预算和父账本桥接，60秒被杀；再次使用timeout包装，从头重做布局。
4. 第二次unpack生成了倒置的图片框，Pillow裁图失败。保存的原始布局与当前代码可离线复现同一坐标错误。
5. 后续模型反复猜IR字段、混淆bbox坐标次序并修改中间件；并未生成译文字典，仍调用pack，必然报 `translated.json` 不存在。
6. 门禁聚合三个已登记失败job，拒绝交付。但最终提示遗漏了unpack超时和倒置裁图框这两个重要工程原因。

**不能归结为“模型翻译能力不足”或“再补一个JSON文件就能交付”。** 源块在翻译之前已经读序错误；恢复路径又缺少统一预算、记账与明确状态。也没有证据说明是原PDF损坏、用户文件权限或网络不可用。

## 5. 恢复阶段的独立问题

### 5.1 模型编造参数，桥接器又把非法参数当成路径

正确接口为 `unpack INPUT WORKDIR`；模型却发出 `auto --unpack ...`，因此命令行参数错误属于模型操作错误。

桥接器仍登记了这个失败job（`52236e0faec94633b70da8aad14c6038`），其manifest输入路径为 `/workspace/\n`，输出路径为 `/workspace/--unpack`。说明位置参数识别没有与CLI有效参数解析对齐，续行和选项被当成了文件名。它没有导致本次真正翻译，但污染了尝试身份和最终错误汇总。

### 5.2 unpack预算和父账本没有覆盖

桥接识别器仅覆盖auto/pack，不覆盖unpack或timeout包装后的命令。于是：

- 第4轮unpack退回普通bash预算，60秒被杀；这不是证明解析器死循环。
- 第5轮模型用timeout 120重新运行，最终107秒后因裁图失败结束；不是120秒超时。
- 两次unpack在同一/tmp目录写入model-events，后一次覆盖manifest/布局文件，但事件文件追加，留下了两次尝试混合记录。
- unpack的parent_run_id为standalone，未与当前run的父TelemetryStats合并。

必须给分步入口相同的deadline、run/job归属和记账规则，不能让模型通过shell timeout补救平台预算缺口。重试应复用合格检查点，而非从第一页重复解析。

### 5.3 倒置裁图框是可复现的工程错误

第二次unpack的第3页图形节点p3_b8原始bbox为：

```text
[344.28, 316.72, 486.27, 315.72]
```

按[left, top, right, bottom]解释，bottom小于top。Pillow因此报 `Coordinate 'lower' is less than 'upper'`。

用保存的layout-p3-1.json、source.ir的原生行与当前materialize_page离线重建，得到完全一致的倒置框。当前实现先规范化bbox，随后为了避开单独分配的正文行不断收缩top/bottom，**收缩之后没有再次验证正面积和最小尺寸**。这属于确定的工程缺陷，不能归因于译文内容。

后续模型交换上下坐标，把它改成仅1pt高的小条；这也不能证明原图区域已正确恢复。应返回布局冲突并重新确定图形边界，保留完整图形，不以交换坐标或强制最小框掩盖问题。

### 5.4 中间件诊断低效且没有进入翻译

IR的节点在顶层nodes，页引用字段为page_id。模型先后猜测blocks、page内nodes、page/ref_page等字段，产生Total blocks:0、Page nodes=0、id=?、NOT FOUND。这些输出不证明IR为空；同一文件实际有87个节点。

多次 `cat FILE | python3 -c '...open(FILE)...'` 不读取stdin，配合pipefail产生退出码141，符合上游cat遭SIGPIPE的命令结构。这是诊断命令问题，不是JSON解析失败。

模型还一度按错误bbox顺序解包，报告49处坐标错误；随后按正确顺序又得0处。不能把这种结果当作修复了49处真实错误。

pack需要按节点/单元格ID写好的translated.json。本轮没有创建该文件，unpack又未成功完成资产阶段，模型便直接pack，缺文件是必然结果。正确恢复顺序应是定位首个失败块→修复结构或译文→验证检查点→继续翻译→渲染；当前执行在诊断和打包之间跳过了翻译。

## 8. 修复优先级

1. **结构正确性**：作者/机构独立识别；在翻译前校验姓名行、上标和机构归属，不能仅靠ID全覆盖。不得简单把所有失败段落标为author绕过检查。
2. **裁图不变量**：所有裁剪/避让处理后验证bbox正面积、尺寸及完整图形归属；冲突时有限修正布局，不静默截成小条。
3. **恢复契约**：明确并验证unpack→译文字典→pack前置条件；保留首个失败块的详情，优先定点恢复，阻止模型反复猜schema和跳过翻译。
4. **统一桥接**：auto/unpack/pack和受支持的包装形式共享deadline、父run身份、账本与失败清理；参数解析与CLI对齐，错误参数不制造伪路径。
5. **状态与审计**：每次尝试独立目录、事件不混写；保存失败译文的验证详情；中断请求补失败/未知用量状态；最终呈现根因而非只拼接下游报错。
6. **回归**：使用本轮95节点auto IR、第二次87节点IR和倒置框原始布局作固定fixture，测试作者分组、收缩后倒置、unpack超时/记账、pack缺前置文件和整轮有限恢复。

本轮只审计、读取日志和离线复现，未修改业务代码、未放宽门禁、未调用模型重跑翻译、未读取或复用模型凭据。
