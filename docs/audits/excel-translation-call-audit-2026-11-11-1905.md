## 4. 模型复核究竟证明了什么

四次 `xlsx_translation_review` 均有 started/completed 事件、usage 和请求指纹。当前代码以每项 `{source,candidate}` 组织复核输入，要求检查遗漏、否定、数量、期限、列引用、术语与流畅度，再返回完整最终译文。翻译与复核使用同一个模型参数，代理日志均解析到 `qwen36-35b-a3b`；没有独立复核模型的证据。

因此，这是实际执行的源文对照复核，不是只检查 JSON 语法。但仍存在以下边界：

1. 模型复核返回的是修订后的字符串，没有逐项问题、修改理由或覆盖清单。原始候选与完整复核响应未在当前证据目录中保存，无法精确量化每条是复核修正、保留，还是复核新引入的问题。
2. 当前请求只有当前批次文本和候选，没有单元格坐标、选项所属的检查项目、相邻列标题或全工作簿术语表。这会限制复核理解“状态选项”与“行动要求”的差别；本轮不能证明它是某个错译的唯一原因。
3. 工程门禁覆盖完整性、非空、假名、部分周期/代码保护和输出回读，不负责判断上述语义。带着本轮语义错误的真实成品重新执行验收，仍返回 `passed=true`。
4. `semantic_reviewed=true` 在工作流完成模型复核后赋值，表示复核流程已执行，不等同于“没有语义问题”。独立重跑结构校验返回 `semantic_reviewed=false` 是该函数自身的能力声明，与本轮四次模型复核并不矛盾。

**字体并未原样保留。** 11 个字体定义统一替换为微软雅黑，字符集由 128 改为 134。验收先对原件字体执行同样的本地化，再比较样式，故“样式校验通过”明确容许这一改变。中文字体适配可以有合理用途，但与用户严格的格式不变要求存在差距，完成回执应披露实际字体变更。

审计查看了已有的三个成品分区预览（A1:H23、A24:H57、A58:H72），并参考同 SHA256 原件的既有预览。主要颜色、区块及表格内容可辨识；文本换行和段落占用空间发生变化，例如 E26 的“C（其他）”出现单独括号换行。它们是第三方导入后的渲染，不能据此保证原生 Excel 的行高表现、无裁切或视觉完全一致。

预览把汇总显示为 **0/0/10**，与成品 XML 缓存和独立统计的 **10/0/0** 不一致。此处记录为第三方预览/重算差异，不判为本轮成品公式损坏，也未把预览导出回用户工作簿。

## 8. 建议与验收目标

1. **优先修复内容保真**：对检查表的已执行/应执行、责任主体、动作类型、对象范围、否定和期限做源文对照。D26、G62、D54/D56、D48 可作为回归样例，业务逻辑应保持通用，不硬编码这些具体日文句子。
2. **给复核必要上下文**：保留文本映射中的 sheet/cell、所属检查项及选项编号，附最小相邻标题和当前文档术语表。返回逐项缺陷与修订结果；对关键项做与初译相对独立的验收。更换模型是否更好需同样本实测，不能只按价格或模型名推断。
3. **明确格式策略**：严格保留字体和尺寸，或将实际发生的字体替换记录进质量回执并向用户说明。若需“视觉一致”，补原生 Excel 的显示、打印范围、下拉和条件格式验收。
4. **分开报告质量状态**：保留模型复核已执行、结构通过、文本回填通过、视觉未验证等独立事实；避免通用 `passed`/`verified` 被消费为全文准确的背书。
5. **保存可复查复核证据**：在既有权限与留存边界内记录每批模型/策略版本、输入绑定、初译与终译差异、缺陷及处理状态。只存指纹足以核验身份，不足以度量复核改进率。
