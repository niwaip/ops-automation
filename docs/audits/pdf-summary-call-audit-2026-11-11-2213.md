## 5. 深度归因与代码证据

### 5.1 P1：错误分类把附件查看误报为联网检索成功

### 5.2 P1：代理重试预算超过视觉客户端等待窗口

- `personal-sandbox-runner/src/dsh_modules/file_tools.py:702`：视觉网络等待默认 120 秒。
- 同文件 `:715`：该 timeout 传给 `request_image_completion`。
- `personal-sandbox-runner/src/dsh_modules/model_image_transport.py:26`：非流式 `urlopen` 使用上述等待时长。
- `ai-orchestrator/src/modules/model/model-proxy.controller.ts:31`、`:898`：视觉单次上游调用默认 90 秒。
- 同文件 `:396`、`:427`：默认一次重试，退避 1 秒；每次尝试重新使用单次 timeout。

两次完整尝试的预算可达 `90 + 1 + 90 = 181` 秒，外层仅等待 120 秒。本轮实际发生首次 90 秒超时，之后重试被客户端剩余窗口截断。不能把最后一行“Sandbox client disconnected”倒置解读为用户离开页面导致原始故障。

`runner.py:831` 又将任意 `TimeoutError` 文案写成“任务执行超时”。本次重放读取到的运行策略 `total_task_timeout=0`，没有全任务期限；这里实际上是视觉工具的单请求等待超时。工具级、上游尝试级、全任务级超时应分别记录。

只读检查确认：原件未加密，85 页均有可提取文本，两个全文缓存均于本轮 22:10:27.567 写入，大小各 237,693 字节，SHA256 均为 `e79feed8174919ba2e94ee90829f4cc1d6aebe40c177d6e5ed4f8273907ec547`。

### 5.4 P2：请求范围与实际覆盖范围不一致

另外，实际页码说明在视觉分析完成后才前缀到返回文本，未进入 `request_image_completion` 的视觉提示。原提示若仍要求概括较大范围，会与实际四页图像不一致。第一批视觉正文也出现与工具页码不一致的声明；本次未逐项复核其业务数字和名称，不将其认定为准确摘要。

## 6. 修复建议与验收目标

1. **先修正错误归类**：用真实检索完成回执决定 `searchCompleted`；对附件查看任务，依据实际失败工具输出“PDF 第几批读取超时”。保留禁止无依据降级的保护。验收必须覆盖“查看和归纳内容 + PDF + 视觉超时”，不得返回搜索或天气文案。
2. **统一跨层 deadline**：将剩余总预算传给代理，下一次尝试只使用剩余预算，预算不足时不要启动注定被截断的完整重试。不要只扩大各层 timeout。验收覆盖“首次 90 秒超时后，客户端仍只剩约 29 秒”的情形。
3. **采用文本优先的长文档读取计划**：先确定章节和页码范围，再分段读取原生文本；视觉请求仅处理图表或文字层不足的页面。记录已覆盖、未覆盖和失败页码，完整性不足时明确标注摘要范围。
4. **修复分页契约**：超出单次上限时自动分批并返回结构化覆盖清单，或明确拒绝过大的范围。将实际发送页码注入视觉提示，避免请求 21 页却仅发送 4 页。
5. **失败也要留收尾证据**：记录 `executed:true`、`stage:vision_inspection`、失败工具、已完成页码、模型尝试与用量未知状态；接入视觉 telemetry，并保存适用于重试的完整工具结果和检查点。

这些是审计建议，本次尚未实施或验证修复效果。

这里称为“语义亲和度”的部分是词项、字符特征、别名与权重匹配，不等于每次都先问一个大模型。该请求 `IntentJudge.should_trigger=false`，只读准入也命中 `skill_admission.py:150` 的放行路径，没有独立的重型意图仲裁请求。原事件的模型日志也只有主模型和两次视觉逻辑请求。

### 8.4 为何没有搜索，却出现搜索报错

Runner 在 `runner.py:306` 起独立计算真实搜索意图，`:323` 对无明确搜索词的文档任务进一步关闭前置搜索。只有“搜索意图 true 且联网许可 true”才会调用前置搜索。

工具路由先在 `tool_routing.py:267` 为只读任务提供 `read_file / scan_knowledge / vision_inspect`，再在 `:384` 对带附件包装标记且无搜索/调研意图的请求剔除 `web_search / fetch_page`。

这次离线复现的原生工具确实只有上述三个。合并 MCP 发现层后另外出现 `read_skill / list_external_tools / call_external_tool`，这是当前可用技能目录带来的外部工具发现入口，不证明实际调用；原事件没有它们的执行。

失败后，TypeScript 的 `isLiveSearchRequest` 重新按另一套关键词分类，匹配“查看”，并无条件断言 `searchCompleted=true`。所以这里是正常执行路由和异常路由不一致，不能据该错误文字反推前面真的联网了。

### 8.5 为何已有文本还会调用视觉模型

该调用由主模型选择工具触发，不是意图路由直接设置了“视觉任务”：

1. 初始 PDF 已原生提取全文，但注入主模型的附件上下文被截到 24,000 字符；重建视图只到第 19 页部分内容。
2. 只读任务通常都暴露 `vision_inspect`，没有根据“文字层可用程度、用户是否要求看图表、当前问题是否需版式判断”决定是否开放。附件保护逻辑还会确保 `read_file` 和 `vision_inspect` 存在。
3. 通用提示只要求“必要时调用只读工具”，没有明确的“文本充分时先继续文本切片、特定图表区域再调用视觉”约束。工具 description 则明确宣传支持多页 PDF 视觉阅读。
4. 主模型一次生成 `vision_inspect(page='20-40')` 和 `vision_inspect(page='41-60')`。从初始片段截止页到第一条工具起始页的衔接，支持它在补读后续内容的解释；但没有保存原始推理和完整工具参数，不能证明它选择视觉而非 `read_file` 的内部理由。
5. `tools.py:670` 将调用分发给 `inspect_image`。后者将 PDF 指定页面渲染成图，拼图、缩放并发送 `image_url`，真实进入多模态推理。
6. 模型代理根据消息是否包含图片决定 `isVisionRequested`。本轮逻辑模型为 `default`，带图请求按 `model-proxy.controller.ts:126` 选择首选视觉客户端。日志中最终仍为 `qwen36-35b-a3b`，因此“使用视觉能力”不等于“换成另一个模型名称”。

本轮 `load_skill_context=false`，且只读准入直接返回，技能正文长度复现为 0；没有 `read_skill` 事件。不能把 PDF 生成技能中的“逐页视觉验收”要求当作本次视觉调用的直接原因。

进一步复现发现**两层截断破坏了文本接力读取指引**：`office_tools.py:114` 先创建约 30,000 字符的提取视图，开头标记“已展示前 1112 行，共 3895 行”，尾部包含章节索引和 `read_file(start_line=1113, end_line=1912)` 建议。随后 `ContextBudget.clip_attachment` 再取前 24,000 字符，把尾部索引和行号建议全部裁掉，但保留未经修正的 1112 行声明。最终上下文实际只覆盖到第 19 页的一部分，而截断提示变成泛用的“工作表覆盖度”警告。

这确定造成覆盖元数据失真与文本续读入口丢失，是当前上下文工程缺陷；它增加了主模型自行规划补读的负担。不能进一步声称已经证明它必然导致视觉工具选择，或原有建议行号仍适用于二次截断后的实际覆盖范围。复现结果保存在 `context-clipping-reproduction.json`。

### 8.6 离线反例揭示的边界问题

`intent-routing-reproduction.json` 保存了以下三组输入的当前代码复现。禁止 IntentJudge 真正调用模型，仅运行规则和工具选择。

| 输入 | 搜索意图 | 原生搜索工具 | 含义 |
| --- | --- | --- | --- |
| 本次完整附件包装 + 指令 + 结构化 files | false | 被剔除 | 本次没有因“查看”启动搜索 |
| 相同指令 + 结构化 files，去掉附件包装文字 | false | 仍暴露 | 工具隔离依赖 prompt 中的标记，不完全依赖 files |
| 附件包装 +“归纳附件，并联网搜索最新行业动态”| false | 被剔除 | 当前本地附件优先规则也会压掉明确的复合搜索需求 |

上述反例均为规则复现，不是声称历史任务实际执行过相应搜索。当前 native 网页工具的裁剪也不能当作沙箱全部网络出口均被禁止的证明。

建议统一维护 `task_action / primary_source / needs_external_search / needs_visual_reading / execution_stage`：附件存在决定默认资料来源，显式联网要求决定是否补外部资料，视觉需求由图表/文字层缺失/版式问题决定；异常提示读取执行状态，不再重新从“查看”等泛词猜测。长文档应同时保留结构化覆盖范围，以免文本截断后让模型自行选择昂贵且可能漏页的补读方式。
