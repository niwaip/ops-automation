# PDF 图标显示与修复预算：工程修复验证

## 行为变化

常见图标使用本地 SVG，不依赖 emoji 字体，共有 53 个图符映射。新增报纸、公告、篮球/足球、地球、财经、汽车、飞机、日历、时钟、人物、消息、文件夹、搜索、阅读、奖杯、下降趋势、对勾和叉号等资源。

未收录图标不再抛出 Unsupported PDF symbol。它们显示为可读 Unicode 名称标签，例如独角兽显示 `[UNICORN FACE]`；未知 Unicode 版本的字符使用码点标识。国旗显示地区标识，例如 `[ES]`；肤色与 ZWJ 组合整体转成保留含义的标签，不拆成无关图标。数字键帽和奖牌保留数字。文字标签经过 HTML 转义，不加载远程素材。

资源在 symbols.py 与 symbol_catalog.py 中按显示逻辑、静态图形分工维护，避免按 Bilibili 单个案例硬编码整份内容。原有字体、字形、分页和视觉发布检查继续执行。

## 同步修复的执行链路

- 联网 PDF 也会调用 configure_pdf_tools，向模型绑定单页 pages 数组要求；schema 明确不接受 `_END_` 伪页面。
- render_pdf 失败按阶段及原因分类累计预算。输入错误修好后出现新的渲染问题，不再被前两个输入错误立即耗尽全部机会。同类错误仍有上限，跨类别也有总预算；已有 bash 错误止损行为保持。
- 只要本轮调用过 render_pdf，即使从未成功注册候选，失败终态也由 PDF 流程接管，返回具体错误，不再由“补充条件/未落盘”通用提示遮蔽。
