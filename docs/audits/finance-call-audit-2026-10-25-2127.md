## 修复

1. **缩小来源裁判的输入职责。** 复用意图 LLM 已识别的期间、业务条件、实体和分组信息；来源裁判不再看到整项任务的指标清单。它只检查来源期间和过滤范围，指标完整性由独立门禁处理。
2. **补齐真实来源证据。** 查询及普通计算回执记录程序从原件读取的同表标题、带坐标的选中行标签及是否抽样。实际年度列仍优先于一般标题，未引用的其他年度列不能证明取数正确。
3. **检查 LLM 结构化结论的一致性。** 同一个来源裁判分别识别规范化的 `request_period`、`source_period`，程序检查它们是否与布尔结论一致。两者明确不同则拒绝；识别不足则保留未核验状态。没有添加特定年份、Sheet、科目坐标或年份提取正则。裁判温度设为 0，缓存版本升级为 v7。
4. **支持精确的多行事实引用。** `query_fact_binding.py` 将 sum/min/max 查询事实还原为真实来源表达式、原聚合操作和精确 `row_ids`，交给现有引擎重算。非连续行、分组、HAVING 和 LIMIT 都不会被扩大成全表。注册关系补算复用该绑定模块。计数、均值等暂不能安全还原的引用明确报错，不猜测其含义。
5. **查询同样经过领域验证。** 复用已有领域定义，拒绝把期间利润率做原始月率聚合；可直接读取原件已存在的单值。没有为本次文件新增业务名称或公式特判。
6. **修正诊断。** 已有执行结果但被来源核验排除时，标记为“已计算，尚未通过来源或口径核验”。部分指标被拒绝也会产生明确的来源问题，不再只显示缺项。无法确认期间的无 WHERE 事实不能通过无过滤兜底绕过检查；门禁复核也不能拿被排除的原始事实撤销缺项。

新能力下沉到 `source_scope_metadata.py`、`query_fact_binding.py`、`query_metric_validation.py` 和已有职责模块，未继续把读取、绑定、校验逻辑堆入执行器。工具参数说明和运行时 README 同步更新。
