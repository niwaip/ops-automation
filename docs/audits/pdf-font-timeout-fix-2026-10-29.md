# PDF 字体、提示词、失败预算与长任务超时修复

## 已落地行为

- `pdf_prompt.py` 独立承担按实际工具选择 PDF 执行方式，移除 prompt builder 原来不区分工具、任务而硬性要求 bash/FPDF 的分支。受控模板任务不再收到必须手写 FPDF 的冲突指令；只读及讲解意图不强迫生成文件。
- 有 render_pdf 时字体与字重交给模板；只有 bash 时普通文档走固定 Markdown/WeasyPrint CLI。仅用户明确要求 FPDF/自定义绘制时给出最小正确字体注册示例，区分路径、族名、Regular/B/I，并说明属性命名与页面尺寸用法。
- 生成任务中不同确定性脚本错误共享三次修复预算。成功的 ls/help/print 等 shell 诊断不清空预算。受控渲染结果清除对应渲染失败，已发布逐页验收凭证才清除完整恢复状态。网络瞬断不混入此脚本错误预算；普通非生成调试任务不套用新增跨异常类型的预算。
- 保留已实施的三层默认无总时限策略：Orchestrator 不注入 300 秒，Broker 按进展续期，Runner 默认总预算为 0（不设截止）。连续 360 秒无有效检查点才停滞终止；显式总时限及用户停止保留。
- 补齐看门狗原因：即使配置了较长总时限，先发生停滞也明确报告 idle，不再混报 total。超时或停止后收到迟到检查点不会重新启动计时器。
- 长任务的 Redis 锁每 60 秒按 token 续租至 420 秒，同时刷新容器活动时间；结束清理续租与看门狗。
