# 个人资料统一原件治理，2026-11-12

## 结论与旧副本用途

旧副本用于隔离沙箱的本地资料检索。历史实现同时保存个人空间原件、deliverables 镜像和派生提取缓存；保存初稿、归集附件、后台精炼有三处镜像写入。副本被当成长期成果库，更新依靠尽力同步与目录重命名，没有共同版本校验，因此 UI 原件精炼后，旧内容仍可能长期参与检索。

本例个人空间原件与沙箱副本 source.session_id/message_id 相同、内容和标签不同。缺少历史写入事件，不能进一步断言 11 月 5 日最后一次旧内容写入是哪个进程执行。当前已移除保留和继续消费独立归档镜像的机制，无须依赖重试同步来维持两份资料。

## 已实施变更

- 个人空间 WorkspaceNode + storagePath 原件成为唯一资料源；新增个人资料服务，从当前已认证用户自己的 personal workspace 检索、读取，排除临时目录与派生缓存。
- 沙箱通过签名用户 token 的网关调用检索/读取接口，不接受请求体指定用户或公司空间。模型继续读取时使用 personal-knowledge URI；来源链接指向同一 WorkspaceNode。
- 文本原件直接读取，frontmatter 标签优先且不混入旧 digest 标签；界面文本预览也不再被 extracted.txt 旧缓存覆盖。二进制文本缓存仍是派生视图，不是可编辑原件。
- 移除笔记保存、精炼、附件归档的 deliverables 镜像写入；移除本地知识目录扫描与异常回退路径，旧扫描插件也统一走个人空间接口。提示词不再指示将文件复制到 /knowledge 来假定完成归档。
- 自动扫描写入 personal_knowledge guard，包含状态、节点 ID、内容哈希、匹配与注入数量；区分零命中与失败，不再仅靠模型工具调用数判断是否检索。
- 新的匹配实现归一化 AI网关 / AI 网关，并保持 PDF/AI 等通用格式词不能独立触发资料召回。
