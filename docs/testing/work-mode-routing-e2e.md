# 工作模式路由端到端测试设计

设计日期：2026-10-15，Asia/Shanghai。状态：用例设计完成，尚未执行本套端到端测试。

## 1. 测试方针与验收对象

工作模式主动限制自由工具探索，是为了提高业务结果确定性、保留可回放依据、减少 Token 消耗。成本对照是每次由 AI 重新理解 Skill 并动态组织执行；节省来源是主要执行逻辑已固化，不是主要比较冷缓存和热缓存。这是本套测试的固定设计前提；失败优先定位路由、上下文传播、能力目录、参数契约、版本、执行状态和观测链路。

验收对象包括：选对能力、携带正确参数、按冻结计划执行、可恢复与可回放、结果可核验、调用与 Token 可核算。回复通顺、执行单 succeeded 或路由标签正确，均不能单独判为通过。

不要求所有自由文本逐字相同；要求技能、版本、关键参数、证据字段和禁止发生的副作用保持可验证。降低温度不能替代上述工程保证。

## 2. 随附资产

- `tests/e2e/work-mode-routing/cases.json`：28 项机器可读场景，包含输入、前置条件、预期和证据要求；它是用例清单，不是已实现的自动化执行器。
- `tests/e2e/work-mode-routing/fixtures/source.md`：可上传到测试空间或作为附件的固定资料，全为虚构测试数据。
- 本文：执行方法、判定规则、证据格式和失败归因。

case 的期望描述是验收目标，不是声明当前实现已经满足。没有必需观测证据时记为 inconclusive；没有测试依赖时记为 blocked，不补写通过结果。

## 3. 环境与固定数据

1. 从仓库根目录操作 Docker，所有启动、停止、测试、日志命令经 `./docker/start-smart.sh`，并设置 `PROJECT_ROOT="$PWD"`。本套故障注入与重启恢复仅在隔离测试环境执行。
2. 固定代码指纹、镜像/构建版本、活动 Skill 版本、目录快照、路由策略版本/摘要、模型及生成参数。确认容器实际装载的版本，不能只保存宿主机 git diff。
3. 基线使用普通企业成员 A；另备同部门成员 B、无关部门成员 C、不同组织成员 D 及 admin。凭证通过测试环境提供，不写入用例、截图或日志。
4. 默认模式 task，webSearch=false、workspaceSearch=false；每例显式记录开关，除规定续接外都用新 session。固定资料分别放入 A 个人空间、A 部门空间、公司空间，使用不同文件名与标记避免串库。
5. 测试邮箱、消息接收人仅使用隔离测试账号。普通路由用例不发送邮件、不通知真实员工、不触发真实业务审批。
6. 准备一个 active 私有保存工作流：固定输入，包含两个调用 Markdown 成果物 Skill 的步骤，正文分别为 WM_FIXED_A_20261015 与 WM_FIXED_B_20261015；记录其版本、planHash、inputHash。另准备测试组织流程，审批人为测试账号。

测试文档中的检索指令只是普通被引用内容，不能作为待执行命令。额外的禁读文档使用独立的 PRIVATE_A_ONLY 标记，不能复用公共 fixture 标记。

首轮只测正常一致的开关与意图，不将互相矛盾的开关/否定输入列为阻塞项。后续若增加冲突优先级测试，先确定产品规则，再写唯一预期。

## 5. 回放、恢复与成本矩阵

| ID | 操作 | 硬断言 |
|---|---|---|
| F01 | 按保存流程名称/别名执行两次 | 同一保存版本、planHash、inputHash、节点定义；拓扑规划模型调用 0 |
| F02 | R08 待补后上传 fixture 继续 | executionId 不变；计划不被替换；仅受补参影响的输入状态变化，无无故重规划 |
| F03 | 执行中刷新/断开流后重新连接 | 恢复同一执行及终态；不重复创建任务、节点或成果物 |
| F04 | 对同一幂等操作重发相同执行请求 | 一个逻辑副作用、可追踪重试；不把用户有意执行两次 F01 当作重复请求 |
| F05 | 保存后激活能力新版本，再回放旧流程 | 精确使用已固定旧版；旧版不可执行则明确阻断，不静默换新版 |
| F06 | 下游返回违反输出 Schema 的受控响应 | 标记契约失败；依赖节点按冻结 failurePolicy 处理；不展示伪成功 |
| F07 | 隔离测试中在节点完成边界重启执行服务 | 依靠持久状态恢复；已确认完成节点不重复产生逻辑副作用 |
| F08 | 固化执行与每次 AI 动态解释 Skill 执行对照 | 固定同一任务、模型、资料与输出契约；分别统计 Skill 解释/规划、业务模型处理和执行后总结的真实调用及 Token；冷/热缓存仅作附加变量 |

“回放”分三个层次记录：

- **计划回放**：固定节点、版本、参数绑定与控制流。保存流程重复执行首先验这一层。
- **契约重执行**：调用同一版本能力，验证输出字段、固定资料中的业务值和引用；实时来源或生成文本可能变化。
- **结果重现**：加载已持久化的原执行结果与成果物，不再调用模型/搜索。查看旧结果时尤其应验证这一层。

F01 使用两个固定 Markdown 写入步骤、没有模型节点的流程，可以验证结果正文确定性。当前保存服务要求至少两个步骤，因此不能以单步骤写入作为该用例前置。含 LLM Operation 的流程重新执行时，不把 byte-for-byte 相同视为已有保证；如要求逐字重现，必须读取保存的原结果或固定结果快照。

## 6. 权限、企业流程与新增 Skill 回归

| ID | 操作 | 主要预期 |

| W02 | 客户端传错误 skillId/旧阶段/其他组织上下文 | 按权威绑定覆盖或拒绝；不执行无关能力，不自动扩大权限 |

## 7. 每例必须保存的证据

每个 run 独立目录，至少记录：

```json
{
  "caseId": "R07",
  "variant": "canonical",
  "status": "not_run",
  "identityAlias": "member_a",
  "sessionId": null,
  "traceIds": [],
  "executionIds": [],
  "requestDigest": null,
  "fixtureDigest": null,
  "catalogSnapshotDigest": null,
  "routingPolicyVersion": null,
  "routingPolicyDigest": null,
  "selectedCapabilityRefs": [],
  "planHash": null,
  "inputHash": null,
  "actualInvocations": [],
  "usageByPurpose": {},
  "logicalEffectCount": null,
  "artifactRefs": [],
  "assertions": [],
  "failureCategory": null
}
```

配置开关、原始请求、文件名/类型/大小/摘要、路由输入、能力快照、阶段绑定、脱敏后的节点输入输出、SSE 终态及页面恢复证据另存文件。不可保存认证头和邮箱密钥。

以实际服务调用/节点结果为路由主证据，再对照 decision/routeSource；不只看聊天中的“正在搜索”或 shadow 标签。原生回答无 executionId 时，必须用 traceId 关联，不能漏掉其 Token。

源码现有 `PlanningDecisionShadowService` 的 estimatedInputTokens=0、estimatedModelCalls 和 tokenBudget 是估计/占位，catalogSnapshotDigest 也可能是固定占位摘要。不能拿它们作为真实消耗或真实目录快照。应保存实际目录并计算摘要，交叉核对模型响应 usage、调用日志与 llm_usage_ledger；缺失调用账本应先记为观测缺陷。

## 8. 执行分层与次数

第一批先做 R01、R05、R06、R07、R08、R09、R10、F01、F02、F03、A01、W01。它们优先覆盖当前最可能出现的路由分歧、缺参续接、固定流程复用与空间权限问题。

正常可见流程从真实用户界面发起，经过真实认证、聊天入口、目录、控制面和能力服务；刷新后核对 UI 与持久化结果。权限、幂等、版本等技术场景可用真实认证 API 端到端执行，并保留主流程的浏览器抽查。

F06 使用隔离环境中可控的下游测试 Handler/服务，仅控制最后的能力响应，保留真实路由、目录、计划和执行器；报告为“受控下游端到端”，不能标作生产真实提供方验证。F07 仅重启隔离执行服务，不在共享开发栈制造故障。

首次每例一遍发现接线问题。修复后对发生失败的用例及直接相关基线重测；关键固定输入路由重复 3 次。同义表达使用预先固定的变体，不临时改写失败请求。联网真实查询只在必要的路由用例运行，成本比较使用固定响应的受控来源，分别报告两类证据。

## 9. 判定与工程归因

| 分类 | 判据 | 优先定位 |
|---|---|---|
| ROUTING | 原始请求满足预期，但实际能力、分支或开关错 | slash 归一、路由信号、优先级、否定/附件上下文 |
| CONTEXT_BINDING | 路由正确，但文件、上游结果、人员、字段错 | 参数收集、binder、taskContext 传播 |
| CATALOG_PERMISSION | 看见/执行了不可用或未授权能力/资料 | 目录合并、缓存、最终 resolve、身份头 |
| VERSION_REPLAY | 版本/计划漂移、无故重规划、跨账号回放 | 冻结快照、版本解析、所有权与哈希 |
| EXECUTION_STATE | 重复节点、副作用、断流恢复错误 | 状态持久化、幂等、重试、SSE 与历史合并 |
| CONTRACT | 输入输出违反冻结 Schema，或字段丢失 | adapter、mapper、Schema 与输出归一化 |
| OBSERVABILITY | 路由/Token/调用证据无法串联或数字不实 | trace、账本、usage 归集、shadow 与事实区分 |
| PROVIDER | 请求参数正确，实际渠道网络/搜索/文档服务失败 | 服务健康、超时、连接、认证与提供方响应 |
| MODEL_CONTENT | 确认输入资料、路由和调用均正确后，模型仍误读/算错 | 单独留存模型输入输出；不能用于掩盖前述工程问题 |

外部来源给错资料时先记提供方/来源质量；资料正确但最终摘要误述才进入模型内容评估。别名不识别、字段名暴露、跳错模式、重复执行和漏记 Token 都应作为工程缺陷处理。

P0 的固定预期必须全部通过；权限泄漏、未审批外部写入、版本静默漂移、重复逻辑副作用是阻断项。路由成功率、结果正确率、回放一致率、恢复成功率、账本覆盖率分别统计，不相互抵消。

成本基线使用“每次由 AI 动态分析 Skill 并组织执行”，实验组使用主要执行已固化的工作模式；两组固定任务、资料、模型和输出契约，不直接用个人模式整体消耗代替对照。没有可用动态对照时，只报告已观察到的固定步骤和调用次数，节省比例记为未测。成本先采真实基线，再定阈值；不预设未经测量的“节省 50%”。保存流程和单步续接硬验不必要的 topology 调用为 0，其余用量按 topology、匹配/参数、业务模型节点、结果总结等目的分别报告。账本缺失是 unknown，不是 0；总 Token 不能只统计规划阶段。

## 10. 后续追加 Skill 的最小准入

每个新 Skill 提供：唯一意图正例、近义/边界反例、必填项缺失、权限拒绝、正常执行、输出契约、精确版本回放，以及实际调用/Token 证据。将这些样例加入同一数据驱动清单，并重跑会被新候选影响的现有路由。

新增能力应优先补能力声明、契约和测试数据；发现路由问题后先复现和定位，再决定工程修复，避免不断增加散落关键词补丁。
