# 个人沙箱的稳定正文提交

正文、进度和附件使用三个独立通道。模型的中间delta不具备业务校验完成的含义；个人沙箱将其作为草稿，
仅通过独立进度区域显示整理状态和已处理字符数，不向客户端发送模型草稿。每跨越100字符更新一次整理进度，检索与工具进度照常发送。最终清洗、业务验收、图片链接和产物识别完成后，以一个RESULT提交正式正文。
常规直连模型问答仍使用原有流式输出，任务模式的既有结果协议保持不变。

## 事件约定

- `data.progressOnly=true`：仅更新独立进度区域；不得修改content、contentParts和isStreaming。
- `RESULT` + `data.answerStatus=committed`：个人沙箱的正式正文，可同时包含artifacts。
- `data.artifactsOnly=true`：只更新附件元数据；不得重置已完成的正文或流式状态。
- `data.artifacts`：已由服务端验证的文件描述（type、name、downloadUrl）。输入附件排除、
  临时文件过滤、历史产物时间过滤和用户隔离仍在服务端执行。

user-web将附件放在正文后的独立区域。元数据更新保持原Markdown组件的props和DOM子树，
不靠忽略校验修正来隐藏正文变化。已有历史消息中的Markdown下载区继续兼容。

## 收尾成本

原生工作簿更新的可信published回执可直接生成正文，包括原始回填值、警告和对账信息，无需再请求模型。
其他缺少有效回答的执行结果可调用有界最终摘要；上下文来自近期执行事实，不再重发整个工具会话。
该摘要不参与计算和文件验收，不能凭空补造业务数值或成功声明。

## 运行验证

Python模块为只读源码挂载，每轮新进程加载；后端编排服务使用构建产物，修改后通过仓库根目录
`./docker/start-smart.sh dev restart ai-orchestrator`重建启动，并核对健康状态。
前端采用Vite源码热更新，需配合事件处理、附件恢复和DOM稳定性回归验证。

执行过程中不展示正文草稿。前端对旧版本遗留的草稿进度也仅显示等待校验提示。最终RESULT到达后才展示正文，避免先读到草稿又被最终结果替换。
