## 业务代码修复

1. **意图解析**：支持名称置于「保存为」和「的 skill/技能」之间，兼容空格、英文大小写与个人技能称呼；保留否定表达和普通文件保存的边界。
2. **保存处理归属**：从 1152 行分发器提取独立 `personal-skill-chat.handler.ts`。生成失败、服务缺失、状态异常、五秒内仍在生成、聊天记录持久化失败，均不会落入普通沙箱。只有完整安装回执才回复保存成功；等待状态与查询地址放入事件数据。
3. **来源绑定**：选取业务任务答复，跳过保存管理轮次和已知失败/取消执行。显式消息 ID 严格绑定，用户消息对应其紧随的助手结果；目录记录保存实际来源消息 ID。
4. **规则与输出契约**：不再按逗号切分规则，避免丢弃 sy、sp 等短前缀；输入文件名、Markdown 转义名及 URL 编码来源链接不会误变成输出文件格式要求。不会因为历史引用了原始 xlsx 就要求保存时制作另一份 xlsx。
5. **存储根目录**：真实安装验收发现服务由 pnpm 在子目录启动，旧 Store 使用 cwd 会把技能写到服务包内。新增根目录解析：显式 PROJECT_ROOT → Docker `/workspace` → 本机向上定位仓库，避免“管理列表可见、沙箱不可见”。
6. **最终文件声明**：循环最终返回前检查明确的文件成功声明，不依赖普通纠偏次数和生成/只读意图分类。文件缺失、空文件或本轮前的旧文件不能支持新生成声明；依赖安装和脚本写出不能替代实际文件。补齐「生成了文件」措辞，最终拒绝记录为 `artifact_delivery/reject`。

存储修复前，首次真实验收生成的技能曾落入服务包的 data 子目录。本次将其活动包、版本快照和目录记录迁至正确用户目录，保持同一 skillId 和 v1；完整备份保存在 `misplaced-skill-backup/`，旧目录记录已移除该条。此迁移只处理本次新生成的这一项技能。
