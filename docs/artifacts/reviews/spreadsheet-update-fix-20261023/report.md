# 工数 Excel 更新修复与 35B 验证

日期：2026-10-23；工作区修复，尚未提交 Git。

## 修复范围

- 将 `plan_spreadsheet_update` 从 645 行的猜测式归一化器拆为公开 Schema、事实目录、语义规划器和工具门面。公开必填参数只有目标文件、期间、业务区块、列性质和目标单位；执行与状态查询只引用 `plan_id`。
- 移除公开原子操作、嵌套 plan、模型转抄哈希、run_id 和 auto_execute；规划只预览。日期元数据不再被强制写入一个模型没有确定坐标的单元格。
- 每个部门指标只注册一条真实单位事实。使用事实回执中的 K，避免查询 unit=source 被当作元而再次除以 1000。删除硬编码缺失部门补零；保留原预测并给出警告。
- 服务端精确匹配标题“有偿”、月份 202610、预测列与部门编码。显式 IR 只注册一套真实 metric/kind/unit；编译器不再按部门+月份降级匹配其他业务区块或单位。
- 锁定事实持久化并绑定哈希；执行检查源/目标输入指纹、计划哈希和事实哈希。按精确计划 ID 加载事务，不再拿第一份磁盘计划执行。重复规划获得独立 ID；发布状态持久化成品路径及哈希，已有输出不覆盖。
- 移除 agent 的 1019/1023/202610 硬编码自动执行“自愈”。标准更新执行只保留结构读取、统计、规划与执行工具，不再引导通用脚本绕过门禁。
- 交付检查排除本轮输入、历史文件；修复嵌套工作区绝对路径被重复拼接的误报。已验证发布后若汇报被通用脚本检查误判，使用发布回执生成摘要。
- 保留公式重算、零新增错误、缓存完整、预算保护和作用域门禁。允许两种经测试的 Calc 等价转换：工作簿日期系统内序号与日期类型；`SUM(C5:C5)` 与 `SUM(C5)`。字符串、不同日期和不同范围不等价。
- 抽离文件交付检测，将 `agent_loop.py` 控制在 1200 行以内。技能说明与实际挂载的运行时技能同步，移除旧接口示例。

## 实测过程中发现的问题

第一轮 35B：技能准入无效 JSON 后降级；模型先用脚本写表，再调用规划器，已有输出导致规划拒绝。这轮不计标准流程通过，据此清理脚本写表降级提示与工具暴露。

第二轮 35B：成功执行 aggregate → plan → execute 并生成通过门禁的文件，但交付路径被嵌套工作区的存在性断言误报；状态查询还混用了 run_id。随后修正路径解析与状态接口。

第三轮 35B：技能准入成功，标准更新与文件验证成功；模型汇报包含工具参数，通用“脚本泄漏”检查将其替换成错误的未完成提示。随后新增只基于本轮有效发布回执的摘要兜底，并加入回归。

这些失败与修正保留在验证摘要中，不能把中间失败轮次当成无错误成功。

## 最终结果

最终真实模型轮次约 **43.76 秒**（dsh metrics），5 次工具调用均成功：两份结构检查 → aggregate_spreadsheet → plan_spreadsheet_update → execute_spreadsheet_update。无 bash 写表，无需要模型转抄的 plan hash/run ID。技能准入通过，最终输出使用已验证发布回执生成摘要，未再把已交付文件说成未完成。

- 发布状态：`published`；门禁：`passed_with_warnings`（仅 4 个部门无匹配，保留原值）。
- 新工作簿包含原 `1019` 和复制后更新的 `1023`，259 条有偿明细汇总为 7 个部门，金额合计 **1747.12579 K**。
- 7 项写入坐标为 C5、C8、C10、C13、C14、C15、C16。其中 3 项与原预测相同，实际发生数值变化的是 C8、C10、C14、C16。
- 622 个公式均有缓存，公式错误 0，缺失缓存 0。比较每个单元格，历史工作表语义值/公式、预算、其他月份和无偿区均保持；合并范围一致。
- 4 个无匹配部门 FC32008、FC34001、FC34032、FC44008 保留原预测。
