### 保存阶段

- 来源提取保留有 ID 的用户原话和多轮纠偏；附件仅提供候选表头，不将助手口述的历史数字作为规则。
- 使用当前对话指定模型提出结构化分组、求和、筛选方案，并为每项操作引用精确的用户消息与原话。
- 校验来源引用、字段、筛选操作及取值，逐条覆盖输入消息。独立规则解析器能够识别的口径还必须保持一致，不能少排前缀或增加“仅有偿”等条件。
- 歧义或未支持操作返回 `needs_input` 和具体问题。模型不可用、输出截断或两次设计仍未通过校验时不安装技能。
- `SKILL.md` 明确实际字段与适用范围，最多五条关键方法，不依赖提炼时的内部变量。详细计算规则、设计及原话依据、独立重放验收分别放 `workflow.json`、`authoring.json`、`validation.json`。
- 保存时重放验收通过才安装。API 通过 `existingSkillId` 显式更新用户自己的技能，保留历史版本。

模型单次输出上限 2400 tokens、传输超时 30 秒，最多修正一次。自然语言保存入口等待最多 45 秒；未完成仍明确显示生成中，不报告保存成功。

### 呈现阶段

- 核算并验证成功后，首先通过既有 Broker SSE 协议发送表格。
- 程序生成口径、覆盖条数、最高/最低分组、负值情况和适用时的占比事实；处理并列、负数与分母条件。
- 当前模型从核验事实中选择最多三个解读重点，只能返回有效事实 ID。不能输出任意文本、数字、因果解释或调用工具。最终句子及数字绑定程序事实呈现。
- 模型草稿不直接流出；解读失败、未知引用、重复引用、截断或超时均保留核验表格。解读预算 256 tokens、20 秒，不重复模型请求。
- “只要表格”“只要结果”“无需解读”跳过模型；`DSH_PERSONAL_SKILL_INSIGHTS=0` 也可关闭解读。独立 `run.py` 仍是纯计算程序。
- 解读后再次核验来源与回执；若附件变化，撤回完成状态，不将旧结果标记为当前附件已验证结果。
