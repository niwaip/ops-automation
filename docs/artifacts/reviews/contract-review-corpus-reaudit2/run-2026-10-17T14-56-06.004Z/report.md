# 35B 工作模式合同审查：代码修改后第二次语料全量复审

## 结论

工程化方法和 harness 有明显进步，但当前版本尚不满足稳定验收。诊断、真实模型溯源、文件正文覆盖、失败证据保留均有效；剩余短板主要是上游参数与文档探测的质量边界，而非报告排版。

本轮未修改业务源码。使用真实认证上传 → 工作模式 chat/SSE → skill → 持久化执行 → 模型账本 → HTML 下载；不是浏览器上传控件 E2E，也不是全量法律准确率测评。

## 尚未解决的问题与优先级

### P1：推断的 PDF 类型覆盖真实业务类型

CT03-zh-pdf、CT03-zh-ja-pdf 首轮和复测均把保密协议识别为 procurement。输入 contractTitle 是 `[第 1 页]`；extractTitle 接受第一行页码为标题。标题识别失效后，正文“本协议不构成采购、投资或知识产权转让承诺”命中采购关键词，先于 NDA 规则。冻结绑定将此探测值记为 user_input，进一步赋予不应有的权威性。

代码：document-prober.service.ts:401–418（标题）、245–275（标题分类）、296–330（正文分类）。建议过滤页码等抽取标记，识别真实标题，保留 inferred/document_probe 来源与置信度；推断值不应等同用户显式指定。增加否定语境、随机文件名、同正文跨格式配对回归。

### P1：冻结前没有递归校验参数结构

CT03-ja-docx、CT05-zh-ja-docx 首轮的 recognizer 生成 customCheckpoints 字符串数组；schema 要求元素为对象。multi-node-parameter-binder.service.ts:545–547 只判断数组，没有递归验证 items。冻结后 scheduler 正确拒绝 INPUT_SCHEMA_VIOLATION，避免伪成功，但任务无法完成。新的 30/30 对照首轮再次命中，说明不是旧文件特例。

归因：模型输出格式错误是触发，工程缺乏冻结前校验/修复是放大因素。建议用能力完整 schema 验证识别结果；错误反馈修复一次，仍失败则明确澄清，不要静默删除用户要求或放宽调度器校验。

### P1：参数识别失败或空对象时用户立场丢失

首轮 CT01-ja-docx、CT06-ja-docx 为 socket hang up，CT06-zh-docx 为 524；CT02-ja-docx、CT05-ja-txt 识别返回 `{}`。输出 buyer/default，不能把默认值恰好相同当作用户确认。CT06-zh-docx 复测仍失败。

建议用户显式“甲方（角色）”由可审计的确定性绑定保留，缺字段与网络故障分开处理；必须有 source=user_confirmed 的真实来源。增加空对象/局部对象/网络失败时不丢显式参数的故障测试。

### P2：真实语义响应仍有解析失败，诊断已改善

首轮 CT04-ja-pdf、CT04-zh-ja-pdf 各 3 条降级，复测通过；CT03-ja-docx 复测又有 3 条降级。均提供 INVALID_JSON_RESPONSE、attempt、elapsedMs、modelId 和 rawSnippet，新增诊断得到真实调用验证。仅凭截取片段不能断言远端截断或精确 token 原因。

建议保留完整响应的受控引用、response hash、finish_reason、实际超时/重试分支；补充非法 JSON 的小范围修复/重试验证，并继续要求未完成语义审查显式降级。当前 succeeded 是执行完成，不能等同语义完整通过；harness 已将其分开。

## 已得到证据支持的改进

- DOCX OpenXML 正文保留通过已进入执行的全部配对样本，未再出现仅标题留下的系统性丢文。
- 先前系统上下文 general 污染和纯日文类型覆盖未再出现；新增的 PDF NDA 误判是不同路径。
- 已知 30/60 双语账期冲突在三种格式均被指出；45/75 未见示例冲突也被识别为 HIGH，60/60 一致账期为 PASS；30/30 首轮因输入错误中断，复测为 PASS，支持有限的泛化与误报控制结论。
- 隔离测试 31/31 与真实运行证据相互补充，真实调用确实暴露了隔离测试遗漏的边界。

## 对 harness 的评价

做得较好：每用例独立会话，原文件 SHA，完整 SSE、执行单、计划输入、模型账本、下载文件 hash；正文全语言逐条对照；运行源码指纹；首轮与复测分目录；增强门禁与旧门禁分列；独立脚本重新核账；双语新增正负变体。

还不充分：只有一套 18 份短文本语料，3 种格式并不等于 54 份独立语义样本。当前没有证明长合同、扫描 PDF/OCR、跨页表格、复杂 DOCX、混合附件、取消恢复、并发极限、浏览器 UI 和真实多轮澄清可靠。风险“非 PASS”只是候选信号，不能冒充法律精确率/召回率。双语门禁包含关键词启发式，本轮关键条款另查了生成解释和对应数值。

下一轮优先冻结版本，修复上述 P1 后跑同一 corpus 与独立 held-out，跨时段至少三轮记录首轮成功率、识别失败率、语义完整率、类型/立场一致率与 P95；单独设并发 1/2 对照，不把重跑成功并入首轮。然后扩展长文、扫描件、跨页和负例，并保存故障重放集。此次不建议继续只追加提示词和相似样例。
