## 测试质量问题

1. **P1：端到端边界缺失。** client.mjs:56–57 直接 POST /workspaces/my/notes。cases.mjs 中正文、folderPath、type、aiModel 预先填写；工作模式复用同一个历史 executionId。因此没有验证前端模式判断、真实模型生成、任务产物产生、保存按钮与页面预览。组件测试仅静态渲染按钮，没有点击或验证 DTO。
2. **P1：AI 失败或超时仍可全绿。** client.mjs:102–116 超时返回普通节点；run.mjs:238–243 仅 digest 存在才记录断言，缺失时直接跳过。本次 54 条记录中没有任何“AI 知识提炼摘要卡片生成完成”。目录数量也被当作可能完成条件，不能替代明确完成状态。
3. **P1：清理与后台任务竞态。** run.mjs:274–282 未等待所有异步任务终态就删除目录；结束后的日志不纳入 verdict。直接导致上述六个失败。
4. **P2：资产清单断言可误报。** run.mjs:248–250 使用“清单标题存在 OR 原文件名存在”；输入正文原本就包含文件名，未生成清单、相对链接无效都可能通过。
5. **P2：声明覆盖但没有断言。** checkHeadingsExtracted、checkRawDataInNote、docExtension 只存在于 cases.mjs，run.mjs 未使用。复杂 MD 仅检查某个表格片段，不足以证明所有标题、代码、公式保真；该样例本身未含公式。模型仅检查 FrontMatter，没有检查 Digest；幂等只检查同节点，没有检查目录/文件数量或配额；搜索只要求有一个结果，没有验证全部预期产物或内容索引。
6. **P2：初始化错误可能让 CI 误判成功。** run.mjs:81–85 在登录等异常后直接 return，未写最终报告或设置失败退出码。清理失败也不影响最终 passed。

## 覆盖矩阵与补测顺序

| 维度 | 已验证范围 | 必须补充 |
|---|---|---|
| 模式 | DTO 指定个人/工作归档路径 | 两种模式各自真实发起生成并点击保存；未传 folderPath 的默认路由；仅 executionId 与 mode 不一致情况 |
| 内容 | 预设短文本、MD 表格、两个 HTML 样例 | 两种模式 × 纯内容/MD/HTML；摘要与完整正文不同；多 HTML 块、完整代码/公式/链接/图片保真 |
| 模型 | 一个 aiModel 字符串持久化 | 实际切换可用个人模型，关联真实生成请求、消息与保存元数据 |
| 交付文件 | 内联 HTML 提取 | 沙箱实际生成 MD/HTML；PDF/DOCX/XLSX/PPTX/图片等支持格式的真实引用、下载哈希、MIME、预览；多资产、同名、缺失/过期路径 |
| 异步 | 启动日志、部分结果 | 明确成功/失败/降级状态；等待所有任务终态；清理后无后台异常；LLM 无效 JSON/超时降级 |
| 幂等/并发 | 连续重复请求、两会话 | 同会话同标题不同内容且等长、不同 messageId、超过五分钟、同秒三个同名会话、并发保存与额度一致性 |
| 权限/错误 | 单管理员正常请求 | 普通用户与跨用户/部门/公共空间权限；空内容、配额不足、写盘失败与部分归集失败 |
| UI/检索 | API 预览与文件名搜索 | 按钮状态、失败重试、刷新后定位、目录与链接可点击、HTML实际渲染、内容索引、删除与额度回收 |

建议先修测试门禁与清理时序，再执行“两种模式 × 三种核心格式”的六条真实 UI 主链路；之后补真实文件、并发和权限负向用例。原有 API 样例可继续作为快速回归层。原“全场景”“100% 保真”“AI 卡片已通过”等结论应降级为“保存 API 基础正向断言通过，异步与真实生成待验收”。
