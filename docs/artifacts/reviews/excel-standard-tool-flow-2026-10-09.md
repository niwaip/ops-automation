# Excel 标准工具流程复核（2026-10-09）

此前的方案没有写死金额或月份，但为一类财务问句设置了专用分发，并在模型调用前直接返回核算表格。这是专项流程，不能当作通用 Agent 分析方案。该路径以及 `variance_task.py`、`budget_variance.py` 已移除；当前结果由真实模型调用通用工具后生成。

## 当前流程

1. 当前会话的结构化附件进入 Skill 路由，不依赖用户在问句中重复文件名。
2. 专业方法进入 System 上下文，附件表头和文本作为数据保留。任务契约提供指标、操作、排序和显式基准提示；未指定的基准继续结合来源结构确认。
3. 只读发现实际/预算候选列对。匹配原件表头，并追溯简单直接引用，例如将泛称“利润实际”与被引用列“净利润”关联。候选包含表、列、范围和分组，不包含极值或预先算好的金额。多个候选保留给模型选择，不自动挑选其中一个。
4. 有可用候选时，初始附件上下文使用目录、表头和候选结构；实际数值留待工具读取。无法识别的结构使用原来的读取流程，模型可继续调用 `read_file` 定位。
5. 模型选择或修正参数，调用公开的 `compare_spreadsheet_columns`。工具按显式范围只读计算左值减基准，支持绝对差额、带方向差额、绝对相对差额、最大/最小、任意唯一分组及并列极值。
6. 执行层校验当轮工具列表及比较计划。支持分次计算不同指标；有效的部分成果保留，最终要求本轮证据覆盖所有请求指标。未提供的工具、错误列对、不可验证的公式或覆盖声明被拒绝。
7. 模型解释计算结果。完整逐行证据保留在运行时，模型接收去除逐行明细的摘要。最终验证来源哈希、指标、分组、差额、排序与金额单位；历史回复不能充当本轮证据，验收失败不会发布未验证极值。

金额单位读取来源声明，包括“单位：千元”和标签/值分列的字典布局；支持元、千元、万元、亿元的换算一致性验证。本例单位来自《使用说明》B6，并非程序给这份文件指定的单位。

## 迭代中发现的真实问题

没有把之前的失败调用算作成功：移除专项路径后，原始短问句曾继续被模型解释为收入减净利润；明确指定预算的测试先成功，加入真实表头候选后原始问句才成功。目录上下文优化后又暴露了金额单位误写，以及执行层误要求“每一次工具调用都必须覆盖全部指标”的问题。

本次同时修复了三个框架问题：结构化 files 没进入 Skill 路由；业务 Skill 被当成设计风格指令；执行层没有约束当轮工具列表。真实调用曾出现模型调用未提供的 bash，因此仅裁剪 tools 列表不足以形成执行边界，当前分发器已在执行前阻断。

金额单位错误现有独立测试，合法换算与错误叙述均覆盖。分步指标调用现有模型/工具循环测试：每次可产生部分有效证据，最终按全部指标累计验收。

## 适用范围与剩余限制

这是一套可复用的工具契约和证据流程，并非完整的通用业务语义解析器。指标提示仍使用公共同义词定义，候选发现目前支持简单表头、实际/预算标记与简单直接引用；自动发现有明确的行、列、分组和文本预算。复杂多级表头、复杂公式分组、重复类别及未知业务术语需要模型继续读取并明确计划，不能强行猜映射。

工具校验声明范围内的数据；完整总体需要正确的范围和 `expected_groups` 声明。公式计算依赖经过来源及副本哈希验证的重算结果；缺少可信重算结果时返回错误，不手工猜公式值。

当前证据验证覆盖请求的极值、金额和单位，不代表回答所有附加叙述均已完成形式化验证。最终真实回复仍有把两项指标的结果推广为“整个报表最大单项偏差”的扩展句；该扩展不属于本次已核验结论。因果解释或其他指标排名应另行获取数据和验证。
