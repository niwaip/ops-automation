# MCP AI 能力摘要落地与验证

## 交付结果

个人外部连接、管理员工作连接及能力详情新增「AI 生成能力摘要」。点击后基于当前本人可见的全部已发布工具生成草稿，支持编辑、查看工具覆盖依据、保存及恢复自动摘要。工作连接仍只有本组织管理员可修改。AI 仅在点击生成时调用，后续对话读取已保存摘要，不重复生成。

admin 的高德连接已完成真实生成、编辑、保存和刷新验证，当前描述为：

> 支持地址转经纬度、POI 地点搜索，以及驾车、骑行和公共交通路线规划。

## 实现边界

- 复用现有默认模型网关 `/ai/model/call`，不接入新的模型 SDK。生成输入包括工具名称、用途描述、审核后的读写类型、有限的参数用途摘录；不读取 MCP 凭证、不发送连接地址、参数默认值/示例或真实查询结果，不执行外部 MCP 工具。
- 支持 1–100 个已发布工具，生成内容覆盖全部工具，不再只使用前 8 个描述。单工具描述及参数摘录受预算限制，过大目录明确拒绝，不静默省略整项工具。
- 草稿最多 160 字符；工具覆盖映射要求每个工具恰好出现一次，拒绝未知、重复或缺失工具。能够在原文及摘要同时核对的业务词作为补充依据展示，忽略空白和括号举例；不把自然语言归纳强制等同于原文逐字复制。
- 共享 30 秒生成预算，格式、长度或覆盖校验失败时最多一次修复。模型/网络失败保留现有摘要，拒绝日志只记录固定分类、轮次和工具数量。完整工具覆盖不等同于对摘要每个语义断言的形式化证明，保存前仍可人工校对。
- 摘要独立存放在新增的 `mcp_connections.capability_summary` JSONB 字段，不修改传输配置修订，不使本人凭证或工具契约失效。
- 摘要绑定当前修订和可见工具集合的摘要指纹，权限、版本或工具变化后回退到默认描述。不同可见集合不复用管理员的摘要；连接列表也不直接暴露未经可见性过滤的原始摘要记录。
- 路由使用短摘要加原始工具能力短描述的独立 `routing_description` 数据（上限 1024 字符）。该字段不进入模型目录提示词；模型目录依旧只显示最多 160 字符的用途，完整 Schema 继续按需读取。这样中文改写或“公交/公共交通”等词语差异不会覆盖原有召回依据。
- 「恢复自动摘要」有独立删除接口，即使模型不可用也能使用；只有显式保存才发布草稿。
