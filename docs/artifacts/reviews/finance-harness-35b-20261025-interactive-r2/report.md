## 阻断：不同指标的源行被混合求和

T02 trace：`42be35cb-33e9-4a30-a4e6-6607c37feffe`。

| 指标（千元） | 用户实际收到 | 独立正确值 |
| --- | ---: | ---: |
| 全年营业收入 | 140058.3 | 124020 |
| 全年净利润 | 140058.3 | 16038.3 |

工具计划读取 `利润表!A4:D14`，用 `项目 in [营业收入, 净利润]` 选中两行；两个 metrics 都是对 `2026实际` 执行 sum，没有分别限定指标行，也没有按项目分组。因此每项都计算成 `124020 + 16038.3 = 140058.3`。两个回执均绑定 `利润表!B4` 与 `利润表!B14`，matched_records=2。

`T02-evidence.json`：verified=true，`spreadsheet_evidence=accept`。最终正文和折叠核算明细都将错误和数标记为各自指标。摘要还据此推导“净利润与收入完全一致”，建议用户检查源表。建议核对并不能撤回已交付的错误数值。

归因：模型选错了每项指标的计算口径；harness 验证了计划执行及指标标签存在，却没有验证指标与源行的语义绑定。算术正确、源单元格真实仍不足以证明业务指标正确。这是工程门禁缺口与模型计划错误的组合，不是单轮没完成或正常提示重试。

修复目标：在通过前验证每个指标的源行选择/聚合口径与需求一致。不能证明时明确失败或询问口径即可，不要求模型一次完成，也不应把错误推给源文件。
