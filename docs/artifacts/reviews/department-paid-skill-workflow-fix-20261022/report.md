## 已落地的保存机制

1. 从用户确认规则和纠偏编译分组、求和及筛选，不从技能名称或助手口述数字补充条件。
2. 保存 `references/workflow.json`，包括具体运算、执行步骤和不可关闭的验收约束。
3. 保存 `scripts/run.py`，为固定、只读的确定性解释器。新附件重新按必需字段定位唯一 Sheet、表头和列，不固化旧文件名、行号或列字母。
4. 保存 `execution.json`，绑定程序、流程入口和 SHA256。
5. 安装前用独立的 SheetJS/BigInt 实现全量重放来源附件，通过后写入 `references/validation.json`。
6. 无法完整编译的规则、缺少来源附件、多个来源、公式金额或尚未定义的交付步骤均不能报告核算技能 ready。
7. 技能变更必须重新编译和验收；禁止仅追加文字而继续运行旧计算流程。普通非核算技能继续保留说明和脚本资源方式。

## 已落地的复用机制

在模型调用前接管核算技能，校验程序与流程摘要，绑定本轮唯一附件。使用受信引擎和 Decimal 全量核算，校验源文件未变、筛选前后行数、分组条数、分组金额与总额。独立的表尾查询条件段明确排除；混入业务数据或缺失字段时拒绝跳过。

同一来源附件复用时，还与保存时的独立重放总额及行数比对。工具回执记录源文件摘要、列映射、范围、命中行、筛选条件、分组金额、技能版本/包摘要以及流程/程序摘要。`personal_skill_evidence=accept` 后才记录 `verified=true`，并直接从回执输出表格。

独立重放入口：

```bash
python /knowledge/skills/dept-summary/scripts/run.py --input /workspace/新附件.xlsx --receipt /workspace/核算回执.json
```
