# MCP 自动加载、硬编码与描述展示审计

## 结论

MCP 连接动态投影为 Skill，生产 MCP 加载、路由及调用代码未发现高德域名、连接 ID、`maps_*` 或 `microsoft_docs_*` 工具名分支。工具描述及参数来自远端 `tools/list`，经用户选择发布后持久化，而非每次聊天动态开放远端所有工具。

分层披露链路存在，但一级能力摘要只是确定性裁剪拼接，不是完整的语义归纳。设置页原先缺少描述入口，Skills 页虽显示执行说明及工具索引，也不能预览目录提示词或展开完整单工具契约。本次补齐展示及只读接口，并保留既有路由、摘要和执行策略。

## 自动加载链路

1. 本人或组织管理员发现工具：`mcp-connection.service.ts::discover` → MCP Runner → 官方 SDK `client.listTools`，使用分页并限制最多 10 页。
2. 选择发布：保存远端名称、描述、输入/输出 Schema、摘要、操作类型、允许角色及配置修订。发现不等于自动发布；远端新增工具不会直接获得调用权限。
3. `McpSkillCatalogService.list` 按当前用户、个人/工作模式、启用状态、当前修订及允许角色过滤工具；有可见工具的连接生成一条 `mcp-<connectionId>` 元数据。
4. 个人沙箱 `mcp_skill_catalog.available_mcp_skills` 经认证代理取目录，成功缓存 10 秒，失败缓存 2 秒并返回空目录。元数据使用字段白名单，不含工具 Schema。
5. `skills.get_available_skills` 将 MCP 元数据并入现有用户及系统 Skills，`SkillRouter` 使用名称、别名、描述等进行召回；`prompt_builder.build_skills_catalog` 为每个连接生成一条目录摘要。
6. `read_skill` / `read_mcp_skill` 才展开平台执行说明及该连接全部可见工具的索引；`list_external_tools(skill_id, tool_name)` 才读取一个工具契约并签发受控调用凭据，之后调用 `call_external_tool`。

工作连接发布时，还会逐工具生成 `platform.mcp.<bindingId>` 的现有 builtin 能力，复用工作执行适配器及权限校验。个人沙箱代理仅提供个人模式，不能把本次个人聊天/页面验证当作工作流程端到端验证。

## 硬编码的实际边界

| 内容 | 结论 |
| --- | --- |
| 高德连接 ID、域名、特定工具名驱动运行时分支 | 未发现；验证及配置脚本中的固定测试目标单独保留 |
| 一级摘要算法 | 固定规则：前 8 个工具，每个最多 72 字符，去重拼接后最多 512 字符 |
| 模型目录 | 每个 MCP 连接用途最多 160 字符；工具索引描述每项最多 240 字符 |
| 平台执行说明 | 统一代码模板，包含依赖查询、依据核验、不可猜测参数和写入确认等规则；并非各 MCP Server 的独立提示词 |
| 路由能力短语 | 中文 4–8 字精确短语启发式，并非通用语义理解模型 |
| 坐标依赖策略 | 显式编写的「从 A 到 B」及坐标/地址字段识别规则；依赖工具描述、Schema、已发布只读策略及本轮查询证据，不依赖高德工具名 |
| 远端初始化说明、MCP prompts/resources | 当前不自动载入，不能将它们理解为已经生效的系统提示词 |

代码检索覆盖 `apps/` 中供应商域名、名称、典型工具名和现有高德连接 ID；生产 MCP 路径无命中。原设置页的高德示例改为通用地址及参数说明，避免被误解为专用适配器。

## 本次落地

- 个人设置、管理员连接页和外部 MCP Skills 列表统一使用 `McpSkillDetailsModal`，提供「能力与执行说明」。
- 先展示能力摘要，再可展开一级模型目录原文预览、二级平台执行说明及工具索引；点击某工具才读取其完整描述、输入/输出契约。
- 新增只读 `GET /mcp-integrations/skills/:id/tools/:toolName`。沿用当前可见性校验，不调用 Runner、不执行工具、不签发调用凭据。
- 连接页首屏改用 `tools?view=index`，不再下载全部输入/输出 Schema；人工测试也先读取选定工具契约，提交动作保持原调用与确认入口。
- 页面预览与 Python 目录生成器做跨语言对照，覆盖截断、换行和 Unicode；查看预览不会向模型附加全部参数或提示词。
- 摘要和执行说明当前仅支持查看，没有新增自定义编辑字段，也没有更改用户现有连接、修订、授权或工具发布配置。

## 后续建议

优先补充连接级可维护的能力总述，个人连接由本人维护，工作连接由管理员维护，并保留自动摘要作为默认值。总述应表达可完成的任务和适用边界，例如高德可概括为“地点搜索与地址解析；骑行、驾车及公共交通路线规划”，避免某个长描述挤掉后续能力。公开 Schema、读写策略和权限仍以已发布契约为准，不能从总述推导。

其次将地图依赖、文档依据核验等策略按能力类型组织，并明确激活条件与回退行为，避免通用平台模板越来越长。连接数量增长时，一级目录仍随连接数增长，后续需要全局预算与候选连接召回；本次没有调整这些运行时策略。
