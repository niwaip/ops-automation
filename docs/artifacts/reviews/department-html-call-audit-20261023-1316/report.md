## 1. 结论

**计算成功，图表交付失败；“交互式页面已生成完毕”是假成功。主因是工程验收与 HTML 兜底链路不一致，另有模型生成数值错误。**

7 个部门的金额确实已计算，独立复算与本轮 `dept_data.json` 逐部门一致，总额 **1887.73102 K**。最终 `index.html` 却是 **2179 字节、23 行**的“指标核算未完成声明”页面，只有警告文字，没有柱状图或业务汇总数据。Redis 保存的回复与沙箱历史完全一致，问题在进入前端之前已经发生。

需要区分两个事实：工具曾检测到一个 250 行、磁盘占用 12 K 的同名文件，但这不证明本轮生成了新图。此前 **13:02:43** 的会话已经保存了一个 **250 行**的同名柱状图。现存证据更支持“检查/发送旧同名文件，最后兜底生成警告页面”，不能表述为已证明“本轮完成的新图被覆盖”。

隔离复现将前次 HTML 作为旧文件，传入本轮实际收尾文本、计算回执和请求，运行 finalizer → exporter，**得到与真实最终 HTML 完全相同的 SHA256，最终整段聊天回复也逐字相同**；将同一文件改为本轮新文件，则原图保留。这定位了旧文件识别与警告内容兜底生成的关键条件。

## 4. 根因与责任边界

### 工程原因 A：文件存在、当前轮生成、任务完成三种状态没有统一

`file_tools.py:794` 的 `send_workspace_file` 检查路径、普通文件、可读性和大小；HTML 没有本轮 mtime、内容摘要、分组数、金额或柱状图验收。返回标记只带路径、名称、comment，没有文件 hash 或不可变快照。

`final_answer.py:59` 判断物理产物时只检查目录中是否有期望后缀，未检查本轮时间，旧 HTML 也被视为产物。相比之下，`artifact_exporter.py:253` 与 `html_report_fallback.py:213` 又要求文件足够新。同一个旧文件可以先被 send_file 接受，最后被 exporter 排除。

前次会话 `chat-session-1792730309468-pezbjusi` 在 13:02:43 已保存标题“各部门金额统计柱状图”的 250 行 HTML（正文 8660 字节，不含结尾换行）。其行数与本轮 wc 一致；du 的 12 K 是磁盘占用，不能当作精确文件长度。**没有本轮发送前的原件 hash/mtime，因此旧文件身份是有多项证据支持的推断，而非可作字节级比对的历史事实。**

### 工程原因 B：发送成功后强制简短收尾，随后又要求正文包含金额

`agent_loop.py:1033` 在 send_file 成功后向模型注入“请直接回复用户，告知文件已发送，请其查收即可。无需再调用任何其他工具”，取最终响应后直接退出循环。实际 10 字响应的 rawSha256 与“文件已推送，请查收。”完全匹配，清洗前后 hash 相同。

`final_answer.py:223` 随后调用指标验收。`analysis_validation.py:227` 对普通金额指标主要在 **最终回复文字** 中找数值，虽然传入了本轮成功计算回执，也不会据此确认普通金额统计已完成。因简短收尾没有金额，系统追加“已达成指标：无、未完成指标：金额”。

这是输出要求互相冲突：系统先要求只回“查收”，再以“查收没有金额”判未完成。现有回执和独立复算都证明金额已经计算，不能将这条警告解释成模型不会计算。

### 工程原因 C：警告被编译成 HTML，再被包装成成功

`html_report_fallback.py:250` 对可兜底正文的实质性检查仅要求达到 120 字，没有排除“指标核算未完成声明”，也未检查用户要的柱状图。带警告的收尾恰好足够长，因此写成新的 `index.html`。

`artifact_exporter.py:311` 只识别警告开头等少数错误文本。本轮文本以“文件已推送”开头，警告在后面，未命中；随后第 326 行加上固定的“交互式页面已生成完毕”。文件存在性恢复被升级成任务成功，未保留失败语义。最终 verification=false 与成功横幅也不一致。

### 模型次因与未知项

send_file 的 comment 中“人均金额 333.53 千元/人”是错误数值。原表去重员工为 51 人，1887.73102 ÷ 51 ≈ **37.01 K/人**。各部门人数相加也为 51，不能由该数据推导 333.53。该 comment 是模型工具参数，未经过数值核对，属于模型生成错误与工程缺少派生指标验收的组合问题。

本轮大段模型正文伴随工具调用，而执行循环 `agent_loop.py:1031` 会在工具后清空临时 reply_text；它只在最后将最终文本交给 HTML exporter。若该正文中包含新图代码，就存在未物化而丢失的路径。**因为仅有长度/hash，没有该段原文，不把“模型一定输出了完整新图”写成已确认事实。**

## 6. 隔离复现与修复验收建议

`replay.py` 使用 bundled Python、openpyxl 与 Decimal 只读复算；用真实计算回执、已由响应 hash 确认的最后一句话、前次 HTML 做隔离复现，模型函数被 mock 为一调用即失败。

| 对照条件 | 结果 |
| --- | --- |
| 旧 HTML，mtime 早于本轮 | 生成 2179 字节警告 HTML，无 SVG/canvas；HTML hash 与真实文件一致；最终回复逐字一致；模型调用 0 次 |
| 同样 HTML，mtime 属于本轮 | 原柱状图保留；仍出现错误的金额未完成警告；模型调用 0 次 |

真实最终 HTML SHA256：`5efc9ea64773904e4461cbd79e6d9b200729500c43cbcb6dff2fe4703dc2a18c`。附件、当前 HTML、当前 JSON 的复算前后 hash 保持一致。五个关键运行时模块在沙箱与本地 SHA256 相同；本地 mtime 均早于调用。没有调用时源码快照，因此一致性检查本身仍不能替代历史版本证明。

修复应按以下条件验收：

1. 发送、finalizer、exporter 共享同一份本轮产物清单，包含 turn/session、来源、mtime、内容 hash；发送后读取同一快照，避免同名路径后来变成不同文件。
2. 仅有旧 `index.html` 时不得作为本轮新图发送；仅有 wc/du 成功时不得认为图已生成。模型正文含 HTML 并伴随工具调用时，应明确保留/物化或要求真正写文件。
3. 对图表任务同时验收计算事实和产物内容；HTML 应能对应 7 个部门及金额，并有实际柱状图。不能只看最终回复是否包含数字，也不能只看文件存在。
4. 失败、警告、未完成声明不得作为“恢复成功”的报告内容，更不能加成功横幅；旧文件不得被警告正文静默覆盖。
5. send_file 成功后保留核心统计摘要，统一 chat 与产物验收要求；派生人均数值由确定性计算产生。
6. 回归覆盖旧同名文件、本轮有效图、只有警告正文、HTML 正文伴随工具调用、发送后文件变化，以及本次原话的端到端交付。
