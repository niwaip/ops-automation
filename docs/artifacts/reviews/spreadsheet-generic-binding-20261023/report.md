# Excel 更新能力去硬编码与 35B 实测报告

完成日期：2026-10-24，Asia/Shanghai。代码保留在当前工作区，尚未提交 Git；本次保留了原有未提交修改。

后续修正：本报告只验证了“缺单位时提问”，未覆盖“用户补充单位后继续”的两轮链路。该遗漏导致用户确认后仍重复提问。随后已删除领域专用技能，补上用户单位确认及连续任务工具路由；后续结果见 [单位追问修复报告](../spreadsheet-update-unit-followup-20261024/report.md)。本报告中的技能同步及原单位门禁描述是当时状态。

## 结论

本次清除了 Excel 更新链路及工数更新技能中依赖示例工作簿的业务默认值。最终版本使用真实 `qwen36-35b-a3b` 完成两项独立测试：原附件缺少目标金额单位时正确提出问题；变换文件名、字段、期间、业务键、单位和布局后成功生成新 Excel，并通过独立读回验证。

这里的“去硬编码”指去除示例驱动的业务假设。Excel 格式约束、标准单位换算、协议枚举、数值精度容差与资源预算仍是必要的技术常量。测试夹具和历史审计证据保留，生产实现不引用它们。

## 实现变化

- 文件、基准 Sheet、新 Sheet、月份、期间字段、业务区块、预测标签均绑定当前请求和实际读取结果；移除固定日期、月份、文件名、字段别名及编码格式规则。
- 目标位置按实际业务键、合并表头、期间与指标定位；移除默认列、固定行距、顶部表头窗口及固定小计标签假设。结构证据包含带坐标的完整标签扫描结果，并显式说明扫描是否完整。
- 来源聚合保留原始业务键与真实单位；目标单位必须由工作簿声明证明，不能沿用来源单位或模型猜测。无法唯一确定时返回 `needs_input`。
- 来源适配不再默认选择第一张表、猜测键列/值列、补零或执行隐藏业务技能。缺失匹配保留原值并说明；已有公式禁止被业务数值覆盖。
- `plan_spreadsheet_update` 使用 `base_sheet` 明确表示目标工作簿的复制基准，避免与来源明细 Sheet 混淆。模型只提供业务参数；事实哈希、写入坐标与执行协议由服务端生成。执行与状态查询只接收 `plan_id`。
- 更新流程的聚合工具使用平铺过滤条件，由服务端编译为现有 Query IR；模型无需构造多层私有谓词树。移除了该流程中早于正式工具定义的独立自由文本规划步骤。
- 发布继续要求来源指纹、计划与事实一致性、限定写入集合、重算和交付凭据。缺少必要信息时直接说明问题，不再用泛化的“文件生成失败”掩盖原因。

主要实现位于 `apps/backend/runtimes/personal-sandbox-runner/src/dsh_modules/spreadsheet_update/`，相关结构证据与工具分发在同级模块。源技能 `.agents/skills/work-hours-update/SKILL.md` 已与实际运行时副本同步。

| 原附件、原请求 | 来源聚合成功；目标无可验证金额单位，返回 `needs_input`；没有发布文件，输入哈希不变 | 100.29 秒 |

原附件测试中，模型仍曾提交猜测的 `target_unit=K`，服务端正确拒绝据此写入。最终回复为：“目标工作簿未声明可唯一验证的金额单位。请确认应以什么单位更新；本次尚未生成更新文件。”这项测试通过的是缺失业务依据的门禁，并不表示原附件已经生成成品。

变换用例不是只修改提示词：实际文件和表内字段、Sheet、业务键、期间、区块及预测标签均替换；目标键列移到 F，写入列移到 G，区块标题位于第 19 行、月份位于第 33 行、指标位于第 34 行，目标单位明确声明为万元。来源包含数字、中文、Unicode 与分隔符形式的业务键。

## 回归和运行状态

94 项检查通过：更新能力 69 项、交付门禁 4 项、无硬编码契约 7 项、查询能力 9 项、规划流程 5 项。更新测试另在一个用例内覆盖 8 种可复现布局变体。`git diff --check` 通过。

对 121 个生产 Python 文件及源/运行时工数技能进行原示例特定日期、月份、文件名和编码模式扫描，匹配为零。该扫描是补充证据；布局变体与真实 35B 实测用于验证未残留同类结构假设，不能把字面量扫描等同于对整个仓库所有业务逻辑的形式化证明。

所有 Docker 操作通过仓库根目录的 `./docker/start-smart.sh` 进入；在实际 broker 内向用户沙箱运行最新 runner。最终模型开始前冻结的源码及技能哈希，与结果收集时一致；原用户输入文件哈希保持不变。

中间实测曾因嵌套查询协议、复制基准字段歧义、深层表头证据不足及附件路径别名失败，相关记录保留在 [迭代证据](iteration-evidence.json)。这些失败促成上述工程修正，不计入最终通过结果。

当前验证边界为按业务键聚合、单目标期间及单指标回填。多指标、多币种或无法唯一定位的布局仍需明确绑定，不能据此宣称支持任意 Excel 自动更新。
