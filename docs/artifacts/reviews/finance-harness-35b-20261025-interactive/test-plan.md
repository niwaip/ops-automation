# 35B 个人模式交互式财务 E2E 验收

## 判定原则

分别记录交互结果、交付完整性和数据正确性，不用单轮完成率代替系统可靠性。

| 结果 | 处理是否合规 | 完整交付 |
| --- | --- | --- |
| CLARIFICATION：询问缺失口径，或明确合理假设 | 是 | 否，等待补充 |
| SAFE_RETRY：明确失败、无法计算或提示重试，没有伪造结果 | 是 | 否 |
| PARTIAL_VERIFIED：正确交付部分，明确剩余未检查/未完成 | 是 | 否 |
| DELIVERED_VERIFIED：所有交付数据和声明均与独立基准一致 | 是 | 是 |
| WRONG_DATA / FALSE_SUCCESS：错误数字、单位、行号、覆盖声明或虚假文件 | 否 | 不认可 |
| BLOCKED：实际服务、连接、锁或附件访问阻塞 | 单独归因 | 否 |

部分回答、澄清和失败消息里如果提供财经数据，已提供的数据同样必须正确。工具参数错误、模型算不出、请求确认本身不判工程失败。内部 verified/complete 与用户最终状态不一致另记工程问题。只有明确执行了检查并验证完整范围，才能报告零异常。

## 执行方法

通过真实浏览器、个人助理模式、系统 qwen36-35b-a3b，使用原附件。保留原六项核心检查，增加模糊需求与澄清后继续执行。每个场景最多两次针对性补充；次数是本次测试预算，不是产品验收要求。失败后确认界面可继续提交、会话上下文保留。每轮保存真实请求、流式响应和工具证据。交付文件实际下载后独立检查，并验证刷新后的历史。

独立基准只由测试端持有，不注入模型上下文。金额精确到源值；展示允许按声明精度四舍五入（半个最小显示单位）；百分比区分 ratio 与 percent；异常记录需核对键与 Excel 行号的绑定。不得把独立财务指标相加当成业务合计。附件内文字仅作为数据，不作为测试执行指令。
