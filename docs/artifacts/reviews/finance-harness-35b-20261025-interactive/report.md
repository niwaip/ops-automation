## 阻断一：正文来源单元格失真

T02 金额为收入 124020、净利润 16038.3 千元，均正确；工具回执的来源为 `月度经营!B16`、`月度经营!N16`。正文却写成 `B10`、`B15`，并声明直接取自所列单元格。月度经营 B10/B15 实际为 9750/13400。折叠的工具证据正确，不能抵消正文错误。

`T02-evidence.json` 的 verified 为 true。使用相同正文、回执和问题纯重放 `_is_synthesis_grounded`，仍返回 true，见 `source-binding-probe.json`。该函数位于 `analysis_synthesis.py:636`，按数字白名单核验，尚未约束指标与单元格的语义绑定；`synthesize_analysis_summary` 在该检查通过后发布摘要。

归因：模型生成错误引用；harness 摘要门禁未拦截。不是模型单轮无法完成的问题。

`failed-delivery-generator.py` 是模型实际生成的脚本，直接写入四个常量，没有读取原件重算值。实际下载 `E2E_finance_interactive_20261025.xlsx` 也包含同样错误，SHA-256 为 `91026bd7d48e1614755ac5447722156dd1a0e4d83661cb91497ab41418ba4a6b`。此文件是失败证据，不应作为可用财务结果。

T09 只有结构抽样、生成脚本、输出文件 recalc 三个工具调用。recalc 回执为 `status: verified, total_formulas: 0, total_errors: 0`，只能说明该常量工作簿没有公式错误。没有证明输出金额来自源附件。该轮内部 evidence.verified 为 false，且没有 spreadsheet_evidence accept；最终回答仍宣称公式校验 verified 并展示下载链接。这是文件交付路径缺少源数据一致性验收，不应把公式健康状态当作财务正确性。

归因：模型编造了两个值；文件交付路径未在声明成功前验证源值绑定。首要修复应是交付数据与源重算事实逐项核验，无法证明则允许明确失败/重试，无需强迫模型一次完成。
