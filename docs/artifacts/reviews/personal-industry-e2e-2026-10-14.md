## 发现与归因

### CSV 汇总：工具调用和故障分类存在工程缺口（P1）

MFG-01 和 RET-01 使用不同的 CSV、不同的汇总口径，均失败在 `aggregate_spreadsheet`：异常为 `openpyxl does not support .csv file format`。两次都先由 Skill Router 选择 xlsx；结构工具对 CSV 的结果没有阻止后续把该路径送入 XLSX 聚合工具。

责任不宜归结成“小模型算错”：模型发起了不适用的表格工具调用，这是模型/协议选择的一环；运行时也未在工具入口处以格式校验拒绝 CSV 并提供受支持的读取路径，最终还把本地文件解析异常包装为“上游大模型服务暂时不可用或响应超时”。后一项属于确定的工程归因错误。用户看到失败原因会被引导去重试模型服务，而不是识别 CSV 与 XLSX 工具不匹配。

代码核对：`spreadsheet_structure` 通过 `inspect_workbook` 建立工作簿目录，并使用 `openpyxl.load_workbook` 读取；这条结构读取路径本身面向 Excel 工作簿。真实 SSE 中，第二个场景的 `report_informational_spreadsheet` 成功，随后 `aggregate_spreadsheet` 才触发 CSV 格式异常。建议对每个表格工具增加格式契约：CSV 用 CSV reader/文本解析，XLSX 才调用 `openpyxl`；工具不匹配时返回可操作的 `unsupported_source_format`，并将任务状态记录为工具/输入格式错误，而不是模型服务不可用。

### 明确排除 PPT/HTML 仍触发生成：路由与执行策略问题（P1）

MFG-02 明确请求 Markdown，并写明“无需HTML/PPT”。运行遥测却显示 Skill Router 命中 `pptx`（得分 20.2）；后续模型写出 `presentation.html` 和两份 PPTX，系统导出了 HTML，回答也把这些文件作为交付物呈现。请求的 Markdown 本身可下载，内容包含设备状态、温度、异常、物料、安全和交接人员；刷新后记录及下载链接仍存在。

这是工程路由问题与模型执行行为共同造成的范围扩张。关键证据是进入模型前路由已经选中 `pptx`；不应把额外交付只算成模型自行发挥。当前 `SkillRouter.route` 有技能否定检查，但这条真实请求仍命中 PPTX，说明否定词与 `PPT`/`HTML` 写法组合没有在实际路由中生效。建议把“明确输出格式”和“明确禁止格式”提取为请求契约，路由和导出阶段都按契约拦截；仅靠在生成提示中补一句“不要PPT”不足以约束自动导出。

### DOCX 交付正常，模型调用仍有无关工作（P2）

RET-02 生成的 `零售门店闭店交接清单.docx` 为 40,466 字节，python-docx 可读取，包含 4 个表格（行数分别为 2、22、1、1）。现金与收银、冷藏食品温度、货架补货、退换货暂存、设备断电检查、钥匙交接、异常记录、责任人、备注字段均存在。真实 SSE 约 55,085 tokens，过程还调用了实时网页搜索；该场景仅要求制作通用模板，没有外部资料需求。属于不必要的模型/路由工作量，交付链本身正常。

MFG-02 的主 Markdown 为 1,847 字节，检查到 M-03、178℃、14:10、3 袋、每小时巡检、维修值班员、李师傅、王师傅和“未提供”等源材料事实。个别用词断言不做质量评分。完整调用显示 127,322 tokens；本轮没有必要为了质量评价模型内容，也不据此推断模型参数规模。

## 建议优先级

1. 先修正 CSV/XLSX 工具输入契约及错误分类，并复跑这两份固定 CSV。
