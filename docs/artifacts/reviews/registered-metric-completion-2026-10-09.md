# 大模型财务调用失败的工程修复

本轮将执行状态、任务缺项及证据交付从模型输出格式中分离。模型负责选择真实来源和计划；程序维护证据集合，按注册语义执行有界补算。大模型仍可能混淆金额与比率、遗漏字段或给出不完整的协议，这些失误不应单独决定已经完成的核算是否能够交付。

## 实现

- `analysis_task_state.py` 独立核验原件哈希、执行回执、声明范围和所需指标类型，返回结构化 issues 与 missing_metrics。缺项列出稳定 metric_id 和 expected_type，不再被模型 JSON 格式错误遮住。
- `analysis_turn.py` 管理当前任务、补算与交付。ID 由程序根据当前成功回执生成，JSON 可解析但 ID 错误的情形同样由程序处理。可选 hypotheses 只接受简短无数字文字，其他字段被忽略，不阻断已有事实。协议诊断保存字段形状、匹配/缺失数量和文本摘要哈希，不保存未知 ID 或模型原文。
- `registered_metric_completion.py` 读取可信领域注册表的分子/分母关系。只有已绑定字段唯一、原件和领域版本匹配、表头及选中行范围相同、且本轮有聚合工具权限时才补算。复用的是源表达式，通过原核算引擎重新读取和计算；不采用旧事实数字口算，不猜 Sheet 或范围。
- 补算回执记录 execution_origin、parent_evidence_ids 与领域版本。每轮最多四次内部执行，相同失败计划不会再次尝试；零分母、来源歧义、跨期间、过期原件或未注册关系保持未完成。
- 已注册且任务契约完整的请求，可在工具执行后由程序生成报告，省去模型复述证据协议的轮次。未知任务仍保留探索机会。
- 注册指标的 number/percentage 类型在核算与任务验收两层检查，防止将百分比当作金额指标完成。
- 私有核算阶段同时抑制 content 与 thought/reasoning 输出，最终数值来自已验证回执。

这套机制复用既有 finance 注册关系，也通过临时实验领域注册“合格数量/投入数量”的合格率验证。通用引擎没有加入固定问题、工作簿名、Sheet 坐标或毛利率结果。

## 真实失败复验

使用 21:43 归档的两份成功金额回执，只读重放：

- 修复前任务缺失 finance.gross_margin，两份回执重复包含收入、毛利额、营业利润、净利润。
- 程序生成一次来源表达式补算，得到毛利率 43.09244476697306885986131269%，报告显示 43.0924%。
- 模型 JSON 的 ID 错误且 hypotheses 含数字，程序仍能维护三份正确证据并生成完整报告。
- 隔离的完整运行循环使用这次真实计划作为模拟模型输出，仅一次模拟模型调用、两次核算执行即可通过；没有调用外部模型服务。
- 原工作簿哈希保持不变，原会话归档和聊天历史没有被覆写。

## 验证与生效

308 项测试通过，包括重复回执、协议错误、非财务注册关系、多期间补算、字段歧义、零分母、权限不足、旧领域版本、原件变动、类型错误以及私有思考流抑制。编译检查和 git diff --check 通过。

通过仓库统一 Docker 入口在运行中的用户沙箱复验，41 个相关模块及两份技能文件哈希与仓库一致。当前为源码只读挂载、每次 CLI 请求启动新进程；后续请求加载更新代码。不带此挂载的镜像部署仍需重新构建并滚动更新。

数值可验证和任务契约完整不等于自动理解所有未知业务。注册关系之外的来源选择与业务假设仍需要明确绑定；无法证明的部分继续保持未完成。
